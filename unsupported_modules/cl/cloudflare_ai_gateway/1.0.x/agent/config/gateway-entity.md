# Gateway config entity, form, schema & admin UI

## The `cloudflare_gateway` config entity

`src/Entity/Gateway.php` — a `ConfigEntityType` (`#[ConfigEntityType]` attribute), config prefix
`gateway` (so config objects are `cloudflare_ai_gateway.gateway.<id>`), `admin_permission:
'administer cloudflare'`. Implements `GatewayInterface`, which extends the SDK's
`CloudflareAssetInterface` — a gateway is therefore also a referenceable Cloudflare *asset*.

Stored / exported fields (`config_export`, schema
`config/schema/cloudflare_ai_gateway.schema.yml`):

| field | type | default | meaning |
|-------|------|---------|---------|
| `id` | machine_name | — | entity id |
| `label` | required_label | — | human label |
| `host` | string | `https://gateway.ai.cloudflare.com` | gateway host base |
| `gateway_slug` | string | `''` | gateway name as configured in the Cloudflare dashboard |
| `credentials` | string | `''` | **id** of a `cloudflare_credentials` entity (supplies token + account) |
| `default_provider` | string | `openai` | upstream provider used for passthrough requests |
| `origin` | string | `external` | `managed` (suite-provisioned) or `external` (referenced only) |

No API token and no account id are stored here. The credential set (a `cloudflare_credentials`
entity from `cloudflare_sdk`) supplies both at runtime; the account id is resolved from it.

Accessors: `getHost()`, `getGatewaySlug()`, `getCredentialsId()`, `getDefaultProvider()`,
`getOrigin()`, `isManaged()`/`isExternal()`. Asset-interface methods: `getType()` returns
`GatewayProvider::TYPE` (`ai_gateway`), `getResourceName()` returns the slug, `getSetting($key)`
exposes `host` / `default_provider`. Origin values come from the `GatewayOrigin` enum
(`src/GatewayOrigin.php`: `Managed`/`External`).

## Add / edit form

`src/Form/GatewayForm.php` (extends `EntityForm`; add + edit both use it, delete uses core
`EntityDeleteForm`). Fields: `label` (textfield, required), `id` (machine_name, locked after
create), `host` (`#type url`, required, default = current host), `gateway_slug` (textfield,
required), `credentials` (`select`, required, options from `credentialOptions()` — every
`cloudflare_credentials` entity keyed id→label), `default_provider` (textfield, optional). The
credential field lists credential-set **labels only**; no secret value is placed in any
`#default_value`. On save: status message + redirect to the collection.

## Admin UI & routes

- Collection: `/admin/config/services/cloudflare/gateways` (this is the module's `configure:`
  link, `entity.cloudflare_gateway.collection`). List columns: label, gateway_slug, credential
  set (`src/GatewayListBuilder.php`).
- Add: `/admin/config/services/cloudflare/gateways/add` — also surfaced as the "Add AI gateway"
  action link on both the gateway collection and the shared `entity.cloudflare_asset.collection`
  (`cloudflare_ai_gateway.links.action.yml`).
- Edit / delete: `.../{cloudflare_gateway}/edit`, `.../delete`.
- Canonical detail: `.../{cloudflare_gateway}` → `GatewayDetailController::view`
  (`cloudflare_ai_gateway.routing.yml`, `_permission: 'administer cloudflare'`). Shows a core
  properties table (type, name, origin, credential, resolved URL) plus the asset kind's
  analytics panel (see [primitives/asset-integration.md](../primitives/asset-integration.md)).

All add/edit/delete/collection routes are generated by `AdminHtmlRouteProvider` gated on the
entity's `admin_permission` (`administer cloudflare`, defined by `cloudflare_sdk`). This module
ships **no `.permissions.yml`**.

## Install / update

`cloudflare_ai_gateway.install`: `hook_update_10001` installs the now-required `cloudflare_api`
module (it became a hard dependency). No `hook_install`/`hook_schema`.
