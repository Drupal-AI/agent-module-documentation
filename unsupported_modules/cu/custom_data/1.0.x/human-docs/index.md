# Custom Data — manual setup guide

**Custom Data** (`custom_data`) defines a general‑purpose, fieldable **content entity
type** with your own bundles ("custom data types"), so you can store structured
records as their own entity rather than bending nodes to the job. Each custom data
type is a config entity you define; the items are content entities with fields, an
owner, published status, and revisions. Types can optionally expose a canonical URL
at `/custom-data/{id}`, and access is handled per bundle through the contrib Entity
API's query‑access and permission‑provider handlers, so you can grant view or edit
rights type by type.

Reach for it when your data isn't really "content pages" but structured records —
and you want proper entity behaviour (fields, revisions, granular access) without
writing a custom entity module yourself.

> **Important — this module is discontinued.** Its maintainers mark it *Unsupported
> / Obsolete* and recommend using **[Storage
> Entities](https://www.drupal.org/project/storage)** instead. It also targets
> Drupal 9 and 10 only (`^9 || ^10`), not Drupal 11. Treat it as reference for
> existing sites; for new work, prefer the recommended alternative.

This guide is written for a **human** clicking through the admin UI. If you want
terse, token‑cheap references for an AI coding agent, read the sibling
[`agent/`](../agent/start.md) docs instead.

## Where it lives in the admin menu

Once enabled, you manage your custom data types at **Administration → Structure →
Custom data types** (`/admin/structure/custom-data-type`, route
`entity.custom_data_type.collection`).

## How to use it

1. Go to **Structure → Custom data types** and add a type. Give it a label and,
   if you want its items to be viewable at their own URL, enable the **canonical
   URL** option (items then appear at `/custom-data/{id}`; a type without canonical
   URLs returns 404 for anonymous viewers).
2. Add fields to the type through the normal **Manage fields** UI, exactly as you
   would for a content type.
3. Set access. The module provides `administer custom_data`, the restricted
   `administer custom_data_type`, and `access custom_data overview`, plus
   **per‑bundle** permissions generated by the Entity API permission provider — so
   you can grant view/edit rights for each type independently. Assign these at
   **People → Permissions**.
4. Create and manage items of each type; they support revisions, and a user with
   *Administer custom data* can override the default new‑revision behaviour.

Uninstalling the module removes the entity type and all of its data, so export
anything you need first.
