Config schema quality

How well Drupal contrib modules describe their configuration for an agent: does the module's own config have a schema, do the schema labels say more than the key name, do settings carry validation constraints, and how often is validation switched off with type: ignore. One row per project, newest documented branch.

Descriptions, read by a model

Each unique label/description was read and judged against one question: could an agent use this as a tool parameter description, knowing only the key path and type? Good = usable as-is; weak = leaves the agent guessing (units, allowed values, format, effect); bad = no usable information; missing = no text at all.
