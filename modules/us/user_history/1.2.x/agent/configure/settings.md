# Configure — settings form & config object

**Route:** `user_history.settings` → `/admin/structure/user_history/settings`
(permission `administer user_history entities`, `_admin_route: TRUE`).
The route is generated by `UserHistoryHtmlRouteProvider::getSettingsFormRoute()`, form
`\Drupal\user_history\Form\UserHistorySettingsForm`. It is the module's `configure` link.

**Config object:** `user_history.settings` (schema `config/schema/user_history.schema.yml`).

## Keys

| Key | Type | Default | Meaning |
|---|---|---|---|
| `no_change.ignore` | bool | `true` | On a user update that produced no tracked-field change, skip writing a history record. |
| `no_change.delete` | string | `''` | PHP relative-date period (e.g. `3 months`, `5 days`). `hook_cron` deletes "no change" update records older than this. Blank = never delete. |
| `no_change.batch` | int | (form default 100) | Max "no change" records deleted per cron run. `0` = no limit. |
| `base_fields.<name>` | bool | all `true` | Which of the 16 user base properties are snapshotted. **UI checkboxes are `#disabled` — all base fields are always tracked.** |
| `attached_fields.<field_name>` | int/bool | `{}` | Which fields added to the `user` entity (via Field UI / code) are tracked. Toggled in the settings form. |
| `archive.directory` | string | `user-history/archive/` | Sub-path for CSV/TXT/XML/JSON archive files (under `private://`, or `public://` if no private scheme). |
| `archive.filename` | string | `user-history-archive` | Base archive filename; date/time + format extension are appended. |
| `archive.max_cardinality` | int | `3` | Field cardinality above which a multi-value field is serialized into one archive column instead of separate columns. Validated 1–20. |

`base_fields` names: `uid, name, pass, mail, timezone, status, roles, created, changed, access, login, init, langcode, preferred_langcode, preferred_admin_langcode`.

## What happens when tracked fields change

Changing `base_fields` or `attached_fields` and saving does not rewrite existing records. Instead:
- `UserHistorySettingsForm::submitForm()` and `ConfigEventsSubscriber::configSave()` compare the new
  config to the running `state` values (`user_history.base_fields` / `user_history.attached_fields`) and
  set `user_history.base_fields_update_required` / `user_history.attached_fields_update_required`.
- While a flag is set, `hook_help()` / `hook_requirements()` show a warning linking to the **Update**
  batch form (`/user_history/update`), which adds/removes attached-field columns and back-fills values.

## Set via drush / PHP

```php
$config = \Drupal::configFactory()->getEditable('user_history.settings');
$config->set('no_change.ignore', TRUE)
  ->set('no_change.delete', '6 months')
  ->set('no_change.batch', 100)
  ->set('attached_fields.field_full_name', TRUE)
  ->save();
```

```bash
drush config:set user_history.settings no_change.delete '6 months' -y
```
