# API — entity, storage, routes, Commerce integration

## Entity classes and interface

- Content entity: `Drupal\commerce_purchasable_entity\Entity\PurchasableEntity`
  (`src/Entity/PurchasableEntity.php`), extends `Drupal\commerce\Entity\CommerceContentEntityBase`,
  implements `Entity\PurchasableEntityInterface`.
- The module interface extends **Commerce's** `Drupal\commerce\PurchasableEntityInterface`
  (`getOrderItemTypeId`, `getOrderItemTitle`, `getPrice`, `getStores`, `getStoreIds`), plus
  `EntityStoresInterface`, `EntityPublishedInterface`, `EntityOwnerInterface`,
  `EntityChangedInterface`. Because it implements the Commerce contract, an instance is a valid
  target for an order item and goes through cart/checkout/pricing/tax/promotions like a product
  variation.

Interface methods (`Entity/PurchasableEntity.php`):

| Method | Notes |
|---|---|
| `getTitle()` / `setTitle($title)` | The `title` base field (`PurchasableEntity.php:77`). |
| `getSku()` / `setSku($sku)` | The `sku` base field (`PurchasableEntity.php:92`). |
| `getPrice()` | Returns a `\Drupal\commerce_price\Price` from the `price` field, or `NULL` if empty (`PurchasableEntity.php:126`). |
| `setPrice(Price $price)` | Sets the `price` field. |
| `getStores()` / `getStoreIds()` / `setStores(array)` / `setStoreIds(array)` | The `stores` reference to `commerce_store` (`PurchasableEntity.php:159`). |
| `getOrderItemTypeId()` | Reads the bundle's (`commerce_purchasable_entity_type`) `orderItemType` — the order item type to create when this entity is purchased (`PurchasableEntity.php:108`). |
| `getOrderItemTitle()` | Returns `getTitle()`. |
| `getCreatedTime()` / `setCreatedTime($ts)` | The `created` base field. |

`getCacheContexts()` adds the `store` cache context (`PurchasableEntity.php:196`).

## Storage handler and `loadBySku()`

Storage class `Drupal\commerce_purchasable_entity\PurchasableEntityStorage`
(`src/PurchasableEntityStorage.php`), extends `Drupal\commerce\CommerceContentEntityStorage`,
implements `PurchasableEntityStorageInterface`. It is the entity type's `storage` handler (declared
in the annotation), reached via the entity type manager — there is no standalone service id.

```php
/** @var \Drupal\commerce_purchasable_entity\PurchasableEntityStorageInterface $storage */
$storage = \Drupal::entityTypeManager()->getStorage('commerce_purchasable_entity');

// SKU lookup — the one custom storage method.
$entity = $storage->loadBySku('TICKET-001');   // PurchasableEntityInterface|NULL
```

`loadBySku($sku)` is `loadByProperties(['sku' => $sku])` then `reset()` (a parameterized entity
query — no raw SQL). The `sku` base field carries a `UniqueField` constraint, so at most one match
is expected. (The class injects `request_stack` in `createInstance()` but does not use it.)

## Creating a purchasable entity from code

```php
use Drupal\commerce_purchasable_entity\Entity\PurchasableEntity;
use Drupal\commerce_price\Price;

$entity = PurchasableEntity::create([
  'type'   => 'default',                 // a commerce_purchasable_entity_type bundle id
  'sku'    => 'TICKET-001',
  'title'  => 'Conference ticket',
  'price'  => new Price('49.00', 'USD'),
  'stores' => [$store->id()],            // required, entity_reference to commerce_store
  'status' => 1,
]);
$entity->save();
```

## Routes

Generated by `Routing\PurchasableEntityHtmlRouteProvider` (extends core `AdminHtmlRouteProvider`;
overrides `getCanonicalRoute()` to return the edit-form route) plus the entity `links`.

| Route name | Path | Access |
|---|---|---|
| `entity.commerce_purchasable_entity.collection` | `/admin/commerce/purchasable-entities` | entity list access |
| `entity.commerce_purchasable_entity.add_page` / `.add_form` | `/admin/commerce/purchasable-entities/entities/add[/{type}]` | create perm |
| `entity.commerce_purchasable_entity.canonical` / `.edit_form` | `/admin/commerce/purchasable-entities/entities/{commerce_purchasable_entity}` | update perm (canonical == edit) |
| `entity.commerce_purchasable_entity.delete_form` | `…/{commerce_purchasable_entity}/delete` | delete perm |
| `entity.commerce_purchasable_entity_type.{collection,add_form,edit_form,delete_form}` | `/admin/commerce/config/purchasable-entities/types/…` | `administer commerce_purchasable_entity_type` |
| `commerce_purchasable_entity.configuration` | `/admin/commerce/config/purchasable-entities` | `access commerce administration pages` |

Access on the entity routes is enforced by `PurchasableEntityAccessControlHandler` — see
[../permissions/permissions.md](../permissions/permissions.md).

## Commerce integration (no plugin types of its own)

This module defines **no** plugin types and **no** `.services.yml`; it plugs into Commerce purely by
implementing the `PurchasableEntityInterface` contract and by config:

- The bundle config entity's `orderItemType` binds each purchasable-entity type to a
  `commerce_order_item_type` whose `purchasableEntityType` is `commerce_purchasable_entity`. The
  module ships one such order item type, `purchasable_entity` (referencing `orderType: default`).
- Adding to an order/cart is **not** provided here. The module targets sites that use an alternative
  add-to-cart form (e.g. Commerce Webform Order) or custom code. When an order item is created for
  one of these entities, Commerce resolves the order item's `unit_price` server-side from the
  entity's `price` field via its own price resolvers — the price is entity data, not request input.
  (The shipped order-item form display uses the `commerce_unit_price` widget with
  `require_confirmation: true`, an admin-only override on the order-item edit form.)
- Availability, pricing, tax, and promotions operate through Commerce's own plugin managers on any
  `PurchasableEntityInterface`; this module contributes no plugins to them.
