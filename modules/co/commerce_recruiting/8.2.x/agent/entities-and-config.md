# Entities, routes, permissions, blocks, settings

## Entities

### `commerce_recruitment_campaign` (config entity)
Groups campaign options. Fields include `recruiter` (allow-list of eligible recruiters — empty =
open to all), `start_date` / `end_date` (time-limited), `status`, and (via `hook_update_N` installs)
`auto_re_recruit`, `bonus_any_option`, `allow_self_recruit`, and `recruitment_bonus_resolver`
(a `commerce_plugin_item:commerce_recruiting_bonus_resolver`). `admin_permission =
administer recruitment campaign entities`. `Campaign::getBonusResolverOptions()` supplies resolver
choices. Admin list at `/admin/commerce/recruitment/campaigns`.

### `commerce_recruitment_camp_option` (content entity)
A single "product → bonus" rule inside a campaign. Fields: `code` (unique, CSPRNG default via
`getDefaultCode()`, `CodeUnique` constraint), `campaign_id` (backref set by `Campaign::postSave()`),
`product` (dynamic entity reference: `commerce_product` / `commerce_product_variation` /
`commerce_product_bundle`), `bonus` (commerce_price), `bonus_percent`, `bonus_method`
(`fix` | `percent`), `redirect` (link — where the code sends the visitor), `user_id`. Bonus method
constants: `CampaignOptionInterface::RECRUIT_BONUS_METHOD_FIX` / `_PERCENT`. `admin_permission =
administer recruitment option entities`. Usually edited inline inside the campaign form (IEF);
`commerce_recruiting.module` adds `#states` + a validation handler for the bonus fields.

### `commerce_recruitment` (content entity, "Recruitment")
A recorded referral. Fields: `recruiter` (owner), `recruited` (buyer), `campaign_option`, `order_item`,
`product` (DER), `bonus` (commerce_price), `state` (workflow `recruitment_default`), `name`, `status`.
`admin_permission = administer recruitment entities`; access via `entity` module
`EntityAccessControlHandler` + `EntityPermissionProvider`. Routes under
`/admin/commerce/recruitment/recruitings/...`. Owner key = `recruiter`.

### `commerce_recruitment_reward` (content entity, "Reward")
A redeemable payout owned by the recruiter (`user_id`, defaulted to current user in `preCreate`).
Fields: `recruitments` (entity_reference, unlimited, required), `price` (summed in `preSave`),
`state` (workflow `reward_default`), `name`. Uses `UncacheableEntityAccessControlHandler` +
`UncacheableEntityPermissionProvider`; `admin_permission = administer reward entities`. Canonical
route is user-facing: `/user/rewards/{commerce_recruitment_reward}` (subject to entity view access);
edit/delete live under `/admin/commerce/recruitment/rewards/...`.

### Field type + base fields
- `recruitment_info` (`RecruitmentInfo`, `src/Plugin/Field/FieldType/`) — a computed multi-property
  field added to `commerce_order_item` holding campaign_option + recruiter + number + currency_code.
- User entity gains a `code` string base field (personal recommendation code, max 50).

## Routes (`commerce_recruiting.routing.yml`)

| Route | Path | Access |
|---|---|---|
| `commerce_recruiting.recruitment_url` | `/code/{campaign_code}` | `access content` (public referral link) |
| `commerce_recruiting.create_reward` | `/user/rewards/collect/{campaign}` | `access content` (acts only on current user's own recruitments) |
| `commerce_recruiting.campaign.recruiters_list` | `/admin/commerce/recruitment/campaigns/{campaign}/recruiters` | `access commerce administration pages` |
| `commerce_recruiting.collections` | `/admin/commerce/recruitment` | `administer recruitment entities` |
| `commerce_recruiting.configuration` | `/admin/commerce/config/recruiting` | `access commerce administration pages` |
| `commerce_recruiting.settings` | `/admin/commerce/config/recruiting/settings` | `access commerce administration pages` |

Entity CRUD routes are generated by `RecruitmentHtmlRouteProvider` (extends `AdminHtmlRouteProvider`)
and add a per-entity-type settings form at `/admin/commerce/config/{entity_type_id}`.

## Permissions

No `*.permissions.yml`. Permissions come from the `entity` module's providers per entity type:
`administer recruitment entities`, `administer reward entities`,
`administer recruitment campaign entities`, `administer recruitment option entities`, plus generated
view/update/delete own/any permissions. Admin routes above additionally use core
`access commerce administration pages`.

## Blocks (`src/Plugin/Block/`, logged-in users only)

- **FriendBlock** — renders a share link on a product page for open ("free for all") campaigns; set
  the block's entity context to *Product from URL*.
- **RecruiterBlock** — lists all campaign codes the context user participates in, grouped by campaign.
- **RecruitmentSummaryBlock** — the user's created + accepted recruitments grouped by campaign/state.
- **RewardsBlock** — the current user's rewards (`RewardManager::findRewards($user)`).
- **RecruitmentSessionBlock** — shows the active recruiting session (debug aid).

## Settings form (`SettingsForm`, config `commerce_recruiting.settings`)

- `use_recruitment_code_url_parameter` (bool) — accept codes as a URL query parameter, e.g.
  `/?code=abc--123`.
- `recruitment_code_url_parameter_name` (string, default `code`) — validated lowercase a–z only.
- `write_recruitment_transition_log` (bool, default on) — log skipped cron transitions.
