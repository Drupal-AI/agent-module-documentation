# Content Moderation Bypass (content_moderation_bypass) — agent index

Extends core **Content Moderation**. For each `content_moderation` workflow it generates a dynamic
permission `bypass {workflow_id} transition restrictions`; a user who holds it may set a moderated
entity to **any** state in that workflow, ignoring the transition graph the workflow defines (Draft →
Review → Published, etc.). There is **no UI, route, form, block, or settings page** — the module works
entirely by swapping/extending three core content_moderation pieces so the permission is honoured on
save. The gate is a plain `$user->hasPermission('bypass {workflow_id} transition restrictions')` check;
nothing in the request (no field, query param, or API input) can flip it — a user without the
permission is fully bound by the normal workflow.

Mechanism (three integration points, all permission-gated): (1) a **service provider** swaps the core
`content_moderation.state_transition_validation` service class so `isTransitionValid()` /
`getValidTransitions()` short-circuit to "allowed" for bypass holders; (2) a **validation constraint**
`BypassModerationState` is added to the `moderation_state` base field via
`hook_entity_base_field_info_alter`, and its validator strips core's `moderation_state` transition
violations for bypass holders (this is the authoritative save-path gate); (3) a **WorkflowType plugin**
overrides core's `content_moderation` plugin so the state selector offers every transition to bypass
holders.

- Depends on: `drupal:content_moderation` (core, which pulls in `workflows`).
- Core: `^10.1 || ^11`. Package: `Content moderation`.
- **No** settings page / `configure` route, **no** routes, services of its own, drush, blocks, or
  config schema. **Provides permissions** (dynamic, one per content_moderation workflow).
- Defines **no** new plugin type. It ships plugin *implementations* that override core: a
  `WorkflowType` (`content_moderation`) and two `Validation/Constraint` plugins.
- Alpha (`8.x-1.0-alpha10`), `security_advisory_coverage: not-covered`.

## Key facts (real machine names)

- Permission (dynamic, per workflow): `bypass {workflow_id} transition restrictions` — generated by
  `Drupal\content_moderation_bypass\ContentModerationBypassPermission::transitionPermissions()`
  (wired via `permission_callbacks` in `content_moderation_bypass.permissions.yml`). Example live
  values on this site: `bypass editorial transition restrictions`,
  `bypass dkan_publishing transition restrictions`.
- Service override: `content_moderation_bypass.services` is *not* used — instead
  `ContentModerationBypassServiceProvider::alter()` re-classes the existing core service
  `content_moderation.state_transition_validation` to
  `Drupal\content_moderation_bypass\ContentModerationBypass\ContentModerationBypassStateTransitionValidation`.
- Constraint plugin id: `BypassModerationState` (`BypassModerationStateConstraint` extends core
  `ModerationStateConstraint`; validator `BypassModerationStateConstraintValidator` extends core
  `ModerationStateConstraintValidator`). Added to the `moderation_state` field by
  `content_moderation_bypass_entity_base_field_info_alter()` in the `.module`.
- WorkflowType plugin id: `content_moderation` (`Plugin\WorkflowType\ContentModerationBypass` extends
  core `ContentModeration`; overrides `getTransitionsForState()`).
- Shared helper: trait `ContentModerationBypassTrait::permissionForWorkflow(WorkflowInterface)` builds
  the permission string used by every check.
- Hooks implemented: `hook_entity_base_field_info_alter`, `hook_help`
  (`help.page.content_moderation_bypass`).
