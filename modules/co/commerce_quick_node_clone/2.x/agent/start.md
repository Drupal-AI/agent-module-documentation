# Commerce Quick Node Clone (commerce_quick_node_clone) — agent index

Adds a **"Clone product"** action for Commerce **`commerce_product`** entities: it builds an
unsaved duplicate, reassigns it to the current user, deep-clones paragraph fields, applies a
title prefix + status rule, and opens the **standard product edit form** — nothing is saved
until the editor clicks Save. Modeled on `quick_node_clone` but scoped to Commerce products.
Version **2.0.2**. Package *Commerce Extension*. License GPL-2.0-or-later.

- **Dependencies:** `node`, `commerce`, `commerce_product` (required). Optional soft deps
  (checked via `moduleExists`): `group`/`gnode` (per-group create access) and `paragraphs`
  (paragraph deep-clone). No composer.json ships with the module.
- **Core:** `^10 || ^11 || ^12`.

## What it provides (from source)

- **Route `commerce_quick_node_clone.node.quick_clone`** — `GET /clone/{node}/edit`, `{node}`
  upcast as `entity:commerce_product`. Controller
  `QuickNodeCloneNodeController::cloneNode()` (extends core `NodeController`). Custom access
  `QuickNodeCloneNodeAccess::cloneNode`. `_admin_route: TRUE`. See
  [api/clone.md](api/clone.md).
- **Route `commerce_quick_node_clone.settings`** — `/admin/config/content/commerce-quick-node-clone`,
  form `CommerceQuickNodeCloneSettingsForm`, permission `Administer Quick Node Clone Settings`.
  See [config/settings.md](config/settings.md).
- **Entity operation** `quick_clone` ("Clone product") and a **`Clone` local task** on
  `entity.commerce_product.canonical` (links.task.yml). Added by
  `hook_entity_operation()` in the `.module`, gated by
  `_commerce_quick_node_clone_has_clone_permission()`.
- **Views field plugin** `commerce_quick_node_clone_link` (`CloneLink`) — a per-row clone
  link. See [views/clone-link.md](views/clone-link.md).
- **Permissions:** `Administer Quick Node Clone Settings` (static) plus one dynamic
  `clone <product_type> content` per product type, generated by
  `CommerceQuickNodeClonePermissions::cloneTypePermissions()`.
- **Config:** `commerce_quick_node_clone.settings` (`text_to_prepend_to_title`, `clone_status`,
  and an `exclude` paragraph-field map); schema in `config/schema/`. A legacy
  `quick_node_clone.settings` key is still read as a fallback and migrated by post-update hooks.
- **Hooks/alters invoked:** `hook_cloned_node_alter($clone, $original)` and
  `hook_cloned_node_paragraph_field_alter($paragraph, $field_name, $settings)` (fired during
  clone). Trait `GroupEntityCompatibilityTrait` and `_commerce_quick_node_clone_get_group_entity_class()`
  bridge `GroupContent` → `GroupRelationship` across Drupal versions.

## Behavior notes (from source)

- The clone route is a **read-only GET that persists nothing** — it returns a pre-filled edit
  form (`entity.form_builder->getForm($duplicate, 'default')`); the real save is the form's own
  POST. A `destination` query is honored after that save.
- `createDuplicate()` copies field values; the controller then overrides `uid` → current user
  and `created`/`changed` → now. Product **variations are entity references and are NOT
  deep-cloned** — only paragraph reference fields are (`cloneParagraphs()`).
- `clone_status` = TRUE keeps the source publication status; FALSE forces the destination
  bundle's default status. `text_to_prepend_to_title` is prefixed to the (each translation's)
  title.
