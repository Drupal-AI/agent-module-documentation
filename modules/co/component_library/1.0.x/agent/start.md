# Component Library — agent index

info.yml name: **Component Library** (`component_library`), description "Build a library of
components", package *User interface*. Version **1.0.0-alpha6** (alpha; not covered by Drupal
security advisory policy). Core `^9 || ^10 || ^11`. Depends on `entity`, `codemirror_editor`,
core `layout_builder`. Configure route: `entity.component_library_pattern.collection`
(`/admin/structure/component-library-pattern` → actually mounted under
`/admin/structure/component-library/...`).

**What it is:** a site-building tool for treating theming as content. Component markup lives in
**config entities holding Twig templates**, authored in-browser with the CodeMirror editor,
previewed live, then rendered on the site. It exposes patterns to component systems
(`ui_patterns` integration is optional) and adds an **Override Mode** that lets a privileged
user re-write any theme template's Twig (and attach CSS/JS libraries) from the browser.

## Core model (4 config entity types)
- **Pattern** (`component_library_pattern`, prefix `pattern`) — a named component: holds preview
  `data` (YAML → context fields), `description`, `tags`. `admin_permission: administer component
  library patterns`. Collection `/admin/structure/component-library/patterns`.
- **Variant** (`component_library_variant`, prefix `variant`) — a Twig `template` bound to a
  pattern; the actual markup. `admin_permission: administer component library variants`.
  Collection `/admin/structure/component-library/variants`. A pattern can have many variants.
- **Asset** (`component_library_asset`, prefix `component_library_asset`) — config holding raw
  `files[]` (`{code, name, type: js|css, path}`). On use they are written to
  `public://component_library_assets/{id}/{type}/...` and registered as Drupal libraries
  (`hook_library_info_build`); CSS is forced to load after the theme (`hook_css_alter`,
  weight 999999999999). `admin_permission: administer component library assets`.
- **Component Override** (`component_override`, prefix `override`) — an in-browser Twig override
  of a theme template (`override`=theme suggestion, `theme`, `template`, `plugin`, `variables`,
  `libraries`). `admin_permission: administer component overrides`. Add form:
  `/admin/appearance/settings/{theme}/component-library/override/add`.

## Rendering internals
- `template_preprocess_component_library_variant` / `_component` render a variant's `template`
  via `#type => inline_template` with the pattern's YAML `data` as context.
- Twig function `component_library_variant(name, args)` (from `ComponentLibraryTwigExtension`)
  renders a variant by id as an inline_template.
- Twig loaders: `VariationTemplateLoader` serves `@component_variation/{variant_id}` from config
  (priority -150); `component_library\Twig\Loader` serves Override Mode templates from
  `component_override` entities (priority 110).
- **Custom theme engine**: `hook_system_info_alter` swaps EVERY twig theme's `engine` to
  `component_library_engine` (submodule). `component_library_engine_render_template` wraps
  twig_render_template output with Override-Mode HTML comment markers, attaches override
  libraries, and injects the per-template override URL into `drupalSettings` — only when Override
  Mode is on and the user has `access override mode`.

## Routes (all admin-gated; none anonymous)
- `component_library.variant_preview` `/component-library/variant-preview` — perm `administer
  component library variants`. `VariantPreviewController` outputs the current user's own preview
  from a **private** tempstore (`component_library:variant_preview`) as `#markup`; the variant
  form's AJAX `previewCallback` writes it and shows it in an iframe. Self-scope only.
- `component_library.tags_autocomplete` — perm `administer component library patterns`; `q`
  matched against pattern tags, labels `Html::escape()`d.
- `component_library.override_mode` `/override-mode` — perm `access override mode`; renders the
  Override-Mode tray (populated by JS).
- `component_library.override_mode.settings` `/admin/structure/component-library/override-mode` —
  perm `administer override mode`.
- `component_library.overview`, `entity.component_library_asset.{collection,add,edit,delete}` —
  asset/overview admin perms.
- Entity CRUD for pattern/variant/override generated by entity-API route providers.

## Permissions
From `EntityPermissionProvider`: `administer component library patterns`, `administer component
library variants`, `administer component library assets`, `administer component overrides`.
From `component_library.permissions.yml` (both `restrict access: true`): `administer override
mode`, `access override mode`. Submodule gcomponent_library: `administer gcomponent library
configuration`.

## Config
`component_library.override_mode.settings`: `override_mode` (bool, default **true**),
`variables_max_size` (6000), `memory_limit` (256 MB) — the last two throttle Override-Mode
variable capture in `OverrideMode::prepareOverrideDetails`.

## Submodules
- **component_library_engine** — the theme engine that wraps rendered output for Override Mode
  (required for the in-page override buttons/markers).
- **component_library_workspaces** — Workspaces integration (core `workspaces`): makes overrides
  workspace-aware so template/CSS/JS changes publish with a workspace.
- **gcomponent_library** (project id "Group Component Library", core `^10.1 || ^11`) — Group
  (`group`) integration: `gcomponent_library_collection` config entity + per-group style/variant
  selection field; `PreprocessComponentLibraryComponent` picks a group's chosen variant.

## Integration / consumption
- **ui_patterns**: `Plugin/UiPatterns/Pattern/ComponentPattern` + `ComponentPatternDeriver`
  expose patterns as UI Patterns; the module is an API and needs no specific component system,
  but pairs with `ui_patterns` and CSS utility frameworks (Tailwind/Bootstrap). Pattern
  save/delete clears the ui_patterns plugin cache.
- **CKEditor**: a separate "CKEditor Component Library" integration (per project page) can embed
  pattern variants into CKEditor 5 content.

## Security posture (plain mechanism)
Component/override **templates are Twig and are evaluated as such**, and assets are raw JS/CSS
served site-wide — so the permissions above are high-trust authoring capabilities and should be
granted only to trusted developers/site builders. All preview, autocomplete, override and
settings routes require those restricted admin permissions; the variant preview route serves
only the requesting user's own preview from a private tempstore. No anonymous or `_access: TRUE`
route.
