# Content Singleton (content_singleton) — agent index

Defines a fieldable, revisionable, translatable content entity type `content_singleton` whose
**bundles are singletons** — a `Singleton` validation constraint enforces at most one entity per
bundle. Bundles are the config entity `content_singleton_type`. Each type gets a clean frontend
path (e.g. `/about-us`) via an inbound/outbound path processor. No module dependencies; requires
PHP **8.3**, core `^11`, license GPL-2.0-or-later. Version **1.0.0-alpha1** (`1.0.x`). No `.module`
file — hooks are OOP (`src/Hook/`).

- **Entity types, fields, singleton constraint, access, permissions, hooks, Views** →
  [entity/singleton.md](entity/singleton.md)
- **Types (bundles), config object + schema, frontend paths / path processor, routes & admin UI** →
  [config/types.md](config/types.md)

## What it provides (from source)

- Content entity **`content_singleton`** (`src/Entity/ContentSingleton.php`), extends
  `EditorialContentEntityBase`; `bundle_entity_type = content_singleton_type`, revisionable,
  translatable, `show_revision_ui: TRUE`, `admin_permission: 'administer content singletons'`.
  Base fields: `label` (required, 255), `changed`, plus editorial `status` and revision metadata.
  Entity constraint `Singleton`.
- Config bundle entity **`content_singleton_type`** (`src/Entity/ContentSingletonType.php`,
  `ConfigEntityBundleBase`); `config_export`: `id, label, description, path, revision`. `postSave`
  / `postDelete` rebuild the router (paths drive URLs).
- Validation: `Singleton` constraint + `SingletonConstraintValidator`
  (`src/Plugin/Validation/Constraint/`) — queries for another entity of the same bundle and adds a
  violation. Excludes self on update.
- Access: `ContentSingletonAccessControlHandler` — `administer content singletons` short-circuits;
  otherwise per-bundle perms; **published entities are `view`-allowed to everyone** (unpublished
  needs `view <bundle> content singleton`). Create needs `edit <bundle> content singleton` OR admin.
- Permissions: 2 static (`content_singleton.permissions.yml`) + 6 **per bundle** generated by
  `ContentSingletonPermissions::contentSingletonTypePermissions()` (view/edit/delete + view/revert/
  delete revisions).
- Services (`content_singleton.services.yml`): `content_singleton.helper`
  (`ContentSingletonHelper` — existing/available bundle queries), `access_check.content_singleton.add`
  (`_content_singleton_add_access`), `content_singleton.path_processor`
  (`ContentSingletonPathProcessor`, inbound+outbound priority 200).
- Controllers: `ContentSingletonAddController::addPage` (`/content-singleton/add` — lists empty
  bundles, redirects if one), `ContentSingletonRevisionController` (revision overview/show/title).
  `ContentSingletonViewController` exists but is **not wired to any route** (legacy; canonical route
  from `DefaultHtmlRouteProvider` renders the entity).
- Route provider `ContentSingletonRouteProvider` (marks edit/delete `_admin_route`);
  `ContentSingletonRouteSubscriber::alterRoutes()` is now a **no-op** (paths handled by the path
  processor). Type routes use `AdminHtmlRouteProvider` + core `EntityPermissionsRouteProvider`.
- Hooks (`src/Hook/`): `entity_type_build` registers a `mercury_editor` form class when Mercury
  Editor is present; `entity_type_alter` swaps in `NodeModerationHandler` when Content Moderation is
  present; theme hooks define `content_singleton` theme + suggestions (`templates/content-singleton.html.twig`).
- Optional Views: `config/optional/views.view.content_singleton_admin.yml`; `ContentSingletonViewsData`.
- Config schema: `content_singleton.type.*` (`config/schema/content_singleton.schema.yml`,
  `FullyValidatable`). No settings/config form (`configure` = null).
