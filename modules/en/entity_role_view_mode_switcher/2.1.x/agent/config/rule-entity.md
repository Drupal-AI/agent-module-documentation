# The `rule` config entity (View Mode Switcher Rule)

Defined by `Rule` (`src/Entity/Rule.php`) implementing `RuleInterface` (`src/Entity/RuleInterface.php`),
extending `ConfigEntityBase`.

## Annotation (source of truth)

- `id = "rule"`, `label = "View Mode Switcher Rule"`, `config_prefix = "rule"`.
- `admin_permission = "administer site configuration"`.
- `entity_keys`: `id`, `label`, `uuid`.
- `config_export`: `id`, `label`, `conditions`.
- Handlers: `view_builder` = core `EntityViewBuilder`; `list_builder` = `RuleListBuilder`;
  forms `add`/`edit` = `RuleForm`, `delete` = `RuleDeleteForm`; `route_provider.html` =
  `RuleHtmlRouteProvider`; `access` = core `EntityAccessControlHandler`;
  `permission_provider` = `Drupal\entity\EntityPermissionProvider`.

Caveat: `permission_provider` references the **contrib `entity`** module's class, but `entity` is **not**
declared as a dependency in info.yml/composer.json. With `admin_permission` set, core uses that permission
for access, so the module functions without `entity` enabled in practice; the reference is an undeclared soft
coupling.

## Routes and links

Routes are generated by `RuleHtmlRouteProvider` (extends core `AdminHtmlRouteProvider`; it adds nothing, just
returns `parent::getRoutes()`), from the entity `links`:

- `entity.rule.collection` — `/admin/structure/entity_role_view_mode_switcher_rule`
- `entity.rule.add_form` — `/admin/structure/entity_role_view_mode_switcher_rule/add`
- `entity.rule.canonical` — `/admin/structure/entity_role_view_mode_switcher_rule/{rule}`
- `entity.rule.edit_form` — `/.../{rule}/edit`
- `entity.rule.delete_form` — `/.../{rule}/delete`

All gated by `administer site configuration` (admin_permission). Menu link `entity.rule.collection` sits under
*Structure* (`system.admin_structure`, weight 99); action link `entity.rule.add_form` appears on the
collection (`*.links.menu.yml`, `*.links.action.yml`). `RuleListBuilder` shows columns *label* + *machine name*.

## Stored data: `conditions`

`conditions` is a **sequence of mappings** (schema `config/schema/rule.schema.yml`, type
`entity_role_view_mode_switcher.rule.*`). Each condition mapping:

- `negate` (boolean) — invert the role test.
- `role_id` (string) — a user role machine name.
- `original_view_mode_id` (string) — qualified id `"<entity_type>.<view_mode>"` (e.g. `node.teaser`).
- `new_view_mode_id` (string) — qualified id `"<entity_type>.<view_mode>"` to switch to.

Accessors on `Rule`: `getConditions()` returns the array (or `[]`); `setConditionsFromArray()` clears and
rebuilds `conditions` from a form-values array, keeping only the four keys above.

## Editing (RuleForm)

`RuleForm` (`src/Form/RuleForm.php`) renders a `#tree` table of conditions with per-row **Negate** (checkbox),
**Role** (select from `Role::loadMultiple()`), **Original/New View Mode** (selects from
`EntityViewMode::loadMultiple()`, labelled `"<target_type> - <label>"`), and a per-row AJAX **Remove** plus an
AJAX **Add Condition** button (callbacks `ajaxAddCondition*`/`ajaxRemoveCondition*`, wrapper
`js-ajax-elements-wrapper`). The form sets `#cache => ['max-age' => 0]` on itself. `copyFormValuesToEntity()`
feeds the table into `setConditionsFromArray()`. Help text states conditions are evaluated in order and the
first to pass takes effect; if none pass, no switch occurs. `RuleDeleteForm` is a standard confirm form
redirecting back to the collection.

## Example exported rule

```yaml
# config: rule.premium_paywall.yml
id: premium_paywall
label: 'Premium paywall'
conditions:
  - negate: true
    role_id: premium
    original_view_mode_id: node.full
    new_view_mode_id: node.teaser
```

Reads as: for `node.full`, if the user is **not** `premium`, render `node.teaser` instead.
