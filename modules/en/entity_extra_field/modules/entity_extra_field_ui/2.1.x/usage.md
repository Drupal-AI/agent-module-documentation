Entity Extra Field UI is the admin-facing companion to Entity Extra Field: it wires the extra-field management screens (list, add, edit, delete) into Field UI for every fieldable bundle, plus config-translation support.

---

The submodule depends on `field_ui` and the parent `entity_extra_field` module. It contributes no config or plugins of its own; instead it makes the parent's `entity_extra_field` config entity manageable through the UI. A `RouteSubscriber` (`alterRoutes`) walks every entity type that has a `field_ui_base_route` and mounts the extra-fields collection/add/edit/delete routes under that bundle's Field UI path (routes `entity.<entity_type>.extra_fields[.add|.edit|.delete]`). `hook_entity_operation()` adds a "Manage extra fields" operation to bundle entities for users with `administer entity extra field`. Local task and local action menu links are generated by derivers (`MenuLinksTask`, `MenuLinksAction`, `TranslateLocalTask`), and `entity_extra_field_ui.config_translation.yml` registers the config-translation mapper so extra-field labels/descriptions can be translated. Per the parent README, this submodule can be safely disabled in production after extra fields are configured — the fields keep rendering because they live on the parent module's config entities.

---

- Expose "Manage extra fields" screens under each content type / bundle's Field UI.
- Add the "Manage extra fields" operation link to bundle listings (e.g. content types).
- Provide the add-extra-field local action button on the collection page.
- Provide edit and delete forms for existing extra fields.
- Mount extra-field routes automatically for any entity type with a Field UI base route.
- Generate local task tabs and menu links for the extra-field screens.
- Enable config-translation of extra-field labels/descriptions.
- Give site builders a no-code UI to create block/views/token/twig/entity_link/component extra fields.
- Keep the UI enabled only in dev/config environments and disable it in production while fields stay active.
- Restrict all extra-field management to users holding `administer entity extra field`.
- Support extra fields on custom entity types that implement Field UI.
- Integrate extra-field management into the existing *Manage fields / display* workflow site builders already know.
- Reach the extra-fields list at `/admin/structure/<...>/manage/<bundle>/extra-fields` via the auto-mounted route.
- Add config-translation tabs so translators can localize extra-field labels per language.
- Manage extra fields on nodes, taxonomy terms, media, users, and any bundle exposing Field UI.
- Add a new extra field via the local action button without writing config YAML by hand.
- Edit an existing extra field's plugin configuration and visibility conditions through a form.
- Delete an extra field (and its config entity) from the delete confirmation form.
- Rely on the RouteSubscriber to keep extra-field routes in sync as new entity types are added.
