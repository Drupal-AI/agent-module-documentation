# Configuration, routes & permissions

## Install & enable

```bash
composer require drupal/entity_attributes
drush en entity_attributes -y
```

No composer.json ships with the module, so there are no external composer requirements. Core
dependencies are **`field`** and **`system`** only. Optional submodules: `entity_attributes_eck`
(needs `eck`), `entity_attributes_paragraphs` (needs `paragraphs`). Optional integration:
`codemirror_editor` (for YAML syntax highlighting; not a hard dependency).

## Settings form

`EntityAttributesConfigForm` (`src/Form/EntityAttributesConfigForm.php`, form id
`entity_attributes_config_form`) at route **`entity_attributes.config_form`**,
path **`/admin/config/search/entity-attributes`** (menu link under *Configuration → Search and
metadata*, `entity_attributes.links.menu.yml`), permission **`administer entity attributes`**.

- `buildForm()` groups every plugin's entity types/bundles into vertical tabs (grouping keyed by
  each plugin definition's `config_tab` / `config_tab_label` / `config_section`) and renders a
  `checkboxes` element per section; option keys have the form `bundles_{entity_type}[{bundle}]`.
- A `use_codemirror` checkbox (disabled unless `codemirror_editor` is installed).
- `submitForm()` diffs the selection against current state. **Enabling** a bundle calls the plugin's
  `addAttributesField()`; **disabling** a bundle that currently has the field routes through a
  **confirmation step** (`buildConfirmForm()` → `confirmSubmit()`) warning that stored data will be
  lost, then calls `removeAttributesField()`. `processFieldChanges()` writes `enabled_bundles` and
  `use_codemirror` to config, clears entity/field caches, and updates field-storage lock status.

## Config objects & schema (`config/schema/entity_attributes.schema.yml`)

- **`entity_attributes.settings`** (`config_object`): `enabled_bundles` (type `ignore` — a nested
  map `entity_type → [bundle, …]`) and `use_codemirror` (boolean).
- **`entity_attributes.static_menu_link_overrides`** (`config_object`, `FullyValidatable`):
  `definitions.{encoded_plugin_id}.third_party_settings.entity_attributes.attributes_data` — the
  store for static menu link attributes (see `StaticMenuLinkAttributes`).
- **`block.block.*.third_party.entity_attributes`** / **`system.menu.*.third_party.entity_attributes`**:
  third_party_settings schema for block and menu config entities (`attributes_data`, type `ignore`).
- Widget/formatter settings schema: `field.widget.settings.entity_attributes_yaml` (`collapsed`
  boolean) and `field.formatter.settings.entity_attributes_hidden` (empty mapping).

`attributes_data` uses the `ignore` schema type deliberately (attribute names/values are arbitrary).

## Permissions (`entity_attributes.permissions.yml` + `EntityAttributesPermissions`)

- **`administer entity attributes`** — static, `restrict access: true`. Gates the settings form.
- Dynamic **`edit entity attributes {entity_type} {bundle}`** — generated by
  `EntityAttributesPermissions::permissions()` for every plugin's entity-type/bundle pair. These are
  the per-bundle permissions that let a user see and edit the attributes field on an entity form.

At runtime, `EntityAttributesPermissions::hasPermission($entity_type, $bundle)` checks the matching
`edit entity attributes …` permission; when it is missing the field element is hidden
(`#access = FALSE`) for content entities and is not added at all for config-entity forms.

## Enabling entity types (operational)

1. Go to `/admin/config/search/entity-attributes`.
2. Tick the entity-type bundles that should have an attributes field; save.
3. Grant the relevant `edit entity attributes …` permissions to the intended roles at
   `/admin/people/permissions`.
4. Print the attribute variables in your templates (see `architecture/rendering.md`).

## Uninstall

`EntityAttributesUninstallValidator` (tagged `module_install.uninstall_validator`) blocks uninstall
while any bundle is still enabled, linking back to the settings form to disable everything first.
