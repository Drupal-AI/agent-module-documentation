# The `entity_tab` config entity + admin UI

## Entity type

`src/Entity/EntityTab.php` — `@ConfigEntityType(id = "entity_tab")`, config prefix
`entity_tab`, `admin_permission = "administer all entity tabs"`. Interface
`src/Entity/EntityTabInterface.php`. Handlers: list builder
`EntityHandler/EntityTabListBuilder`, forms `EntityTabForm` (add/edit) +
`EntityTabDeleteForm` (delete), route provider `Routing/EntityTabAdminRouteProvider`.

`config_export` / stored keys (schema `config/schema/entity_tab.schema.yml`,
type `entity_ui.entity_tab.*.*`):

- `id`, `label`, `uuid`, `weight` (int, default `10`) — entity keys.
- `path` (type `path`) — the path component appended to the target entity's canonical path.
- `tab_title` (label) — the local-task tab label.
- `page_title` (label) — the page `<title>`; passed through `\Drupal::token()->replace()` in
  `EntityTab::getPageTitle()` with tokens `entity_ui_tab` (the tab) and `entity_ui_target_entity`
  (the viewed entity) — see `entity_ui.tokens.inc`.
- `target_entity_type` (string) — machine name of the content entity type the tab is added to.
- `target_bundles` (sequence, nullable) — empty array = all bundles; otherwise only these bundles
  (enforced by `EntityTab::hasBundleAccess()`).
- `content_plugin` (string, default `entity_view`) — the `entity_ui_tab_content` plugin ID.
- `content_config` (mapping, schema `entity_ui.content_config.plugin.[content_plugin]`) — the
  plugin's stored settings, e.g. `view_mode` for `entity_view`, `form_mode` for `entity_form`.

The tab's content plugin is held in a `EntityTabLazyPluginCollection`
(`getPluginCollections()` → key `content_config`); `preSave()` strips the injected `entity_tab`
key before persisting. `calculateDependencies()` adds a module dependency on the target entity
type's provider. `postSave()` triggers a router rebuild when `path` changes and a local-task cache
clear when `tab_title` changes (both on create).

## Admin UI routes

CRUD routes come from `EntityTabAdminRouteProvider` (extends core `AdminHtmlRouteProvider`), all
gated by the entity's `admin_permission` `administer all entity tabs`:

- `/admin/structure/entity_ui/entity_tab/{entity_tab}` (canonical)
- `/admin/structure/entity_ui/entity_tab/add/{target_entity_type_id}` (add-page →
  `Controller/EntityTabAddPage`, requirement `_entity_create_access: entity_tab`)
- `/admin/structure/entity_ui/entity_tab/add/{target_entity_type_id}/{plugin_id}` (add-form)
- `/admin/structure/entity_ui/entity_tab/{entity_tab}/edit`
- `/admin/structure/entity_ui/entity_tab/{entity_tab}/delete`

The provider deliberately **omits the collection route**; instead one collection (list) route per
target entity type is generated by `Routing/AdminRouteProviderSubscriber` at route-rebuild, using
the target type's `entity_ui_admin` handler (`EntityHandler/EntityUIAdminBase::getCollectionRoute()`).
That collection route is gated with an OR permission
`administer all entity tabs+administer <type> entity tabs`, and lives beside the target type's own
admin UI (e.g. `admin/structure/types/entity_ui` for nodes). A "Add entity tab" local action is
added there (`getLocalActions()` → route `entity.entity_tab.add_page`).

## Permissions (`entity_ui.permissions.yml` + `src/EntityUiPermissions.php`)

- Static: `administer all entity tabs`.
- `EntityUiPermissions::entityUiAdminPermissions()` — one `administer <type> entity tabs`
  (`restrict access: TRUE`) per entity type that has an `entity_ui_admin` handler.
- `EntityUiPermissions::entityUiTabPermissions()` — loads every `entity_tab` and merges each tab's
  `getPermissions()` (delegated to its content plugin; see plugins doc). These are the access
  permissions for the generated tab pages.
