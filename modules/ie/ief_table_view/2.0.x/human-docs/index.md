# IEF Table View — manual setup guide

**IEF Table View** (`ief_table_view`) connects the core **Views** module to
**Inline Entity Form** so that the table IEF shows for its referenced entities is
generated by a **View** you control. Instead of IEF's fixed set of columns, you
decide exactly which fields appear, in what order, and how they're formatted.

This is a boon for more involved inline‑entity workflows — think order line items
or nested content — where the default table simply doesn't show the columns
editors need to tell referenced items apart or manage them at a glance. You build
a normal View of the referenced entity type with the columns you want, and IEF
renders that instead of its built‑in table.

Because the display comes from a View, it still honors the underlying entity
access — the View applies access as usual — so the module adds no access of its
own. It depends on core **Views** and the **Inline Entity Form** module.

This guide is written for a **human** clicking through the admin UI. If you want
terse, token‑cheap references for an AI coding agent, read the sibling
[`agent/`](../agent/start.md) docs instead.

This module has **no central settings form** — you configure it per field on
*Manage form display*, in combination with a View, as described below.

## Where it lives in the admin menu

IEF Table View adds no dedicated admin page. You configure it in two familiar
places: the **Views UI** (Structure → Views), where you build the View that
supplies the columns, and **Manage form display** on the content type whose IEF
widget should use that View.

## How to use it

1. In **Structure → Views**, build a View of the *referenced* entity type with
   the fields/columns you want IEF to show.
2. On the host content type's **Manage form display**, use an Inline Entity Form
   widget for the reference field and point its table at the View you created.
3. Save, then edit content and confirm the inline table shows your tailored
   columns.
