Droost Examples is a read-the-source catalog of modern, green-by-default reference implementations of common Drupal patterns, generated by the Droost scaffolder.

---

Droost Examples ships one worked, current-idiom example of nearly every common Drupal extension pattern, so an AI agent (or a developer) can copy a correct, present-day implementation instead of guessing. Every file was produced by running a Droost scaffolder blueprint (`drush droost:scaffold <blueprint>`) once, and every file passes phpcs (Drupal + DrupalPractice) and PHPStan at max using modern idioms — PHP 8 attributes, constructor DI, `final`, typed signatures. The catalog includes: an MCP `#[Tool]` plugin (`ExampleTool`), an autowired service (`ExampleService`), an event subscriber, a `#[Block]` plugin, a `FormBase` form, an OOP `#[Hook]` class, a Drush command, and queue-worker / action / field-formatter / field-widget / field-type plugins; a real content entity type (`ExampleWidget`) and a config entity type (`ExampleProfile`), each with its interface, list builder, forms and access control handler; a standalone entity access control handler; a route subscriber that alters an existing route; a kernel-test skeleton that runs in CI; a Single Directory Component (`components/example_card`); and Views field/filter/sort handlers with their `views_data`. Admin routes for the two entity types are gated by `administer example_widget` / `administer example_profile` (both `restrict access: true`) plus per-operation view/edit/delete/create permissions, and the module ships `droost_examples.settings` config with a schema. It depends on `droost` and core `text` (the ExampleWidget entity declares a `text_long` base field). This is a developer reference — read the source; do not run it in production. Re-run any blueprint to regenerate a file or to see its options.
