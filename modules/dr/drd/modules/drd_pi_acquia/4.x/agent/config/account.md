# drd_pi_acquia — Acquia account & sync

## Install / enable

`drush en drd_pi_acquia` (pulls in `drd_pi` and `drd`). Then configure an encryption profile
under DRD settings so the Acquia private key is stored encrypted.

## Create an account

Configuration → DRD → Acquia → Accounts (`/drd/settings/acquia/accounts`) → Add Acquia Account.
Form (`Entity\AccountForm`) fields:

- **Enabled** / **Label** / **Machine name** (from `DrdPiAccountForm`).
- **E-mail** (`email`, required) — your Acquia account e-mail.
- **Private key** (`private_key`, required) — from
  `https://accounts.acquia.com/account/security`.

On submit, `AccountForm::submitForm()` calls `setPrivateKey()` → `setEncrypted('private_key', …)`
so the key is encrypted through DRD's `drd.encrypt` service before the config entity is saved.
`getPrivateKey()` decrypts on read. The `email` value is stored as plain config.

## Config objects

- Account entities: `drd_pi_acquia.acquia_account.<id>` — keys `id`, `label`, `uuid`, `email`,
  `private_key` (schema `config/schema/acquia_account.schema.yml`; `config_export` list on the
  entity annotation). `admin_permission = administer site configuration`.
- `drd_pi_acquia.settings` — `Account::getConfigName()`; the `Form\Settings` config form
  declares it editable but currently stores nothing ("No settings required at this point.").

## Acquia Cloud API

`Account::curl($command)` — `Account::ENDPOINT = https://cloudapi.acquia.com/v1/`. Builds a
Guzzle client with `http_client_factory->fromOptions(['base_uri' => …, 'auth' => [email,
privateKey]])` (HTTP basic auth; Guzzle default TLS verification is on), GETs
`<ENDPOINT><command>.json`, and `json_decode`s a `< 300` response (returns `[]` on any error).

Inventory mapping:

- `getPlatformHosts()` → `GET sites` → one `DrdPiHost` per site id.
- `getPlatformCores(host)` → `GET sites/{host}/envs` → per environment a `DrdPiCore` plus a
  `DrdPiDomain` built from `default_domain`.
- `getPlatformDomains(core)` → the domain attached during `getPlatformCores()`.
- `getAuthorizationSecrets(domain)` → `GET sites/{host}/envs/{env}/dbs` → `['username' => …,
  'password' => …]` from the first DB, used by DRD to authorize itself on the remote site.
- `getAuthorizationMethod()` → `drd_agent` `Base::SEC_AUTH_ACQUIA`.

## Routes & permissions

- `drd_pi_acquia.drd_pi_acquia_settings` — `/drd/settings/acquia`, `Form\Settings`,
  `_permission: access administration pages`.
- `entity.acquia_account.collection` — `/drd/settings/acquia/accounts`,
  `_permission: administer site configuration`.
- Add/edit/delete/canonical entity routes are generated by the entity's
  `AdminHtmlRouteProvider`. Local task/action/menu links are declared in
  `drd_pi_acquia.links.{task,action,menu}.yml`.

## Running the sync

Use the shared DRD mechanisms (this submodule adds no command): the `drd_action_pi_sync` action,
`drush drd:pi:sync`, or the DRD dashboard. `WidgetAcquia` (block `drd_pi_acquia`) renders the
account/host/core/domain counts and a link to the settings form.
