# Drush De-Identify — manual setup guide

**Drush De-Identify** (`drush_deidentify`) adds Drush commands that make it easy
to produce a shareable copy of your database without the sensitive data in it. It
does two related jobs: it exports a database dump with cache (and any tables you
choose) reduced to structure only, and it overwrites sensitive table columns
in place with realistic-but-fake values generated by the Faker library. Together
these let you hand a developer, tester, or CI pipeline a working copy of a
production database that no longer contains real personal information.

It is a command-line tool with no web pages, permissions, or settings — because
it is invoked only through Drush, it has no HTTP attack surface. The typical use
is to sync a production database into a scratch environment, clean the columns
that hold personal data, and then export a sanitized dump to pass along.

The export command is deliberately close to Drush's own `db-export`, but it calls
a hook so that the list of structure-only tables can be extended by other modules
without you having to remember every `--omit_tables` flag. It supports Drupal 8,
9, and 10 (and is documented as working on D7).

**Handle the output carefully.** A dump you export *before* de-identification is
complete still contains real data, so treat any dump as sensitive until you have
confirmed the personal-data columns have actually been cleaned. De-identify
first, verify, then share.

This guide is written for a **human** clicking through the admin UI. If you want
terse, token‑cheap references for an AI coding agent, read the sibling
[`agent/`](../agent/start.md) docs instead.

## How to use it

The module adds two commands, run from the Drupal root.

**Clean sensitive columns in place** with fake data —
`drush_deidentify:db-clean` (alias `ice-clean`). Its argument is a
comma-separated list of `table~column` pairs:

```bash
drush ice-clean users_field_data~mail,users_field_data~name
```

Each named column is overwritten with Faker-generated values, so the copied
database no longer holds the real values.

**Export a sanitized dump** — `drush_deidentify:db-export` (alias `ice-export`):

```bash
drush ice-export --result-file=deid.sql --gzip
```

Options:

- `--result-file=<path>` — the output file, relative to the Drupal root
  (required if you want a saved dump).
- `--gzip` — compress the dump with gzip (gzip must be on your `PATH`).
- `--omit_tables=<t1,t2>` — extra tables to export as structure only, in addition
  to the cache tables that are always structure-only.

A typical flow: sync/import a production database into a scratch environment, run
`ice-clean` on the columns that hold personal data, then run `ice-export` to hand
off a sanitized dump. Other modules can extend the always-structure-only list by
implementing `hook_drush_deidentify_export()`, so site-specific tables can be
excluded automatically.
