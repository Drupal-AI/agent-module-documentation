# DX Toolkit Demo (dx_toolkit_demo) — agent index

**Example/reference submodule** of DX Toolkit demonstrating the ServiceInjector factory-service
pattern. Package `Development`. Depends on `dx_toolkit`, `node`, `taxonomy`. Core requirement
`^10 || ^11`. License GPL-2.0-or-later. Version 1.0.1. It has **no routes, controllers,
permissions, blocks, or config** — only two ServiceInjector plugins, one service, and two Drush
commands. Everything runs on the CLI.

## What it provides

- **ServiceInjector plugins** (`src/Plugin/ServiceInjector/`), both `extend
  Drupal\dx_toolkit\Plugin\ServiceInjectorBase`:
  - `ViewStorage` — simple, no deriver (`@ServiceInjector` id `view_storage`, would yield
    `service_injector.view.storage`).
  - `ConfigFactory` — id `config_factory`, deriver `Derivative/ConfigFactoryDeriver` producing
    editable-config services for `system.site`, `system.performance`, `node.settings`,
    `user.settings`.
- **ContentAuditor service** (`dx_toolkit_demo.content_auditor`,
  `src/ContentAuditor.php` implements `ContentAuditorInterface`): constructor injects
  `@service_injector.node.storage`, `@service_injector.taxonomy_term.storage`,
  `@service_injector.user.storage`, `@service_injector.system.site.config`. Methods `auditSite()`
  and `auditByType($id)`.
- **Drush commands** (`src/Commands/DemoCommands.php`, tagged `drush.command` in
  `drush.services.yml`): `dx:demo:audit` and `dx:demo:audit-type <entity_type>`.

## Operate

`drush en dx_toolkit_demo -y`, then `drush dx:demo:audit` or `drush dx:demo:audit-type node`.

## Caveat (accuracy)

The ServiceInjector plugins extend `ServiceInjectorBase` and the service wiring references
`service_injector.*` ids, **but dx_toolkit 1.0.1 ships no `ServiceInjectorBase` class or
ServiceInjector manager/compiler pass**, so these services are not actually generated by that
release. Read this submodule as a pattern template. See [plugins/service_injector.md](plugins/service_injector.md).
