BAT Event Series lets you create recurring BAT events from a single record: a `bat_event_series` entity holds a start/end pattern plus an iCal RRULE (via the `rlanvin/php-rrule` library) and expands it into individual `bat_event` availability records. It ships daily and hourly series types out of the box.

---

The module defines the `bat_event_series` content entity (base table `event_series`, bundle entity
`bat_event_series_type`, config schema `bat_event_series.event_series_type.*`). A series stores a
recurrence rule in its `rrule` field; `RRule\RRule` (from `rlanvin/php-rrule`) turns the
frequency/until inputs into an RFC RRULE string and enumerates occurrence dates, which the module
materializes as concrete `bat_event` records targeting a unit. Two series types install by default —
`availability_daily` (granularity `bat_daily`, target event type `availability_daily`) and
`availability_hourly` (`bat_hourly`) — described in `config/install`, along with a
`views.view.event_series` listing. Modal forms (`EditRepeatingRuleModalForm`,
`EditRepeatingRuleConfirmationModalForm`) let an admin edit the repeating rule and preview/confirm how
the change re-generates the underlying events (using a private tempstore), and a dedicated
"delete events" form removes a series' generated events. Series-type config mirrors event types
(`event_granularity`, `target_event_type`) and the module attaches the state-reference, event-dates,
and target-entity fields to each bundle. Access uses the base `bat_entity_access()` model.

---

- Generate recurring availability from one record instead of creating each `bat_event` by hand.
- Store a reservation/availability recurrence as an iCal RRULE on a `bat_event_series` entity.
- Use the built-in `availability_daily` series type for day-granularity recurring availability.
- Use the built-in `availability_hourly` series type for hour-granularity recurring availability.
- Define custom series types with their own granularity and target event type.
- Expand a weekly/monthly/daily frequency until a given end date into concrete events.
- Edit a series' repeating rule through a modal form and re-generate its events.
- Preview and confirm how a rule change affects the generated events before committing (tempstore).
- Delete all events generated by a series via the dedicated delete-events form.
- List and manage event series at `/admin/bat/events/event_series`.
- Manage series types at `/admin/bat/events/event_series/event-series-types`.
- Block out recurring maintenance windows across units.
- Publish recurring open/available periods (e.g. a class that runs every Tuesday).
- Load series by id or conditions (`bat_event_series_load`, `_load_multiple`).
- Create/delete series programmatically (`bat_event_series_create`, `_delete`, `_delete_multiple`).
- Format an RRULE date for display with `bat_event_series_rrule_date_formatter()`.
- Attach state/date/target fields to a series type in code (`bat_event_series_type_add_*`).
- Reuse the `views.view.event_series` listing as a starting point.
- Scope series visibility/edit to owners with the BAT per-bundle permissions.
- Drive the same calendar tables that `bat_event` uses, keeping availability consistent.
