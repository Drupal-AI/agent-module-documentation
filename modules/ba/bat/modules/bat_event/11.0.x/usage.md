BAT Event is the availability engine of the BAT suite: a `bat_event` content entity records that a given unit is in some state (available, booked, blocked, priced, ...) over a date range, and the module maintains fast per-event-type calendar tables (via the Roomify `roomify/bat` library) so availability can be queried across many units and dates. It also defines the `state` entity and `bat_event_type` bundles that control granularity and semantics.

---

Each `bat_event` (base table `event`, bundle = `bat_event_type` config entity) references a target unit (`unit_id`), a date range (`event_dates`, a `datetime_range` field), and a state or value. `bat_event_type` config carries `event_granularity` (`bat_daily` or `bat_hourly`), `fixed_event_states` (fixed vs open states), `target_entity_type` (default `bat_unit`), and `default_event_value_field_ids` / `default_event_label_field_name` describing which fields hold the event's value and label. When an event type is created the module **dynamically creates two SQL tables** for it (a state store and an event store) via `bat_event_create_event_type_schema()`, populated day/hour/minute columns generated by `bat_event_generate_*_schema_fields()`; `Event::batStoreSave()` writes to them through the library's `Calendar`/`DrupalDBStore`. The `state` content entity (base table `states`) defines the possible states, referenced through the `bat_event:state` entity-reference selection plugin. A rich procedural API answers availability questions — `bat_event_get_matching_units()`, `bat_event_get_calendar()`, `bat_event_get_calendar_response()`, `bat_event_get_states()`, `bat_event_constraints_get_info()`. Cron can prune old events (`bat_event_cron`, configurable at `/admin/bat/config/bat_event`). Access uses the base `bat_entity_access()` model; the module ships Views field/filter handlers (duration, value, event-type, blocking filter) and exposes hooks for target entity types and booking constraints.

---

- Record availability of a unit over a date range as a `bat_event` (available / booked / blocked / maintenance).
- Store a price or numeric value against a unit for a period using a value-type event.
- Define event types with daily (`bat_daily`) or hourly (`bat_hourly`) granularity.
- Choose between fixed states (a fixed set) and open states for an event type.
- Define the set of possible availability states as `state` entities (e.g. Available, Booked).
- Query which units match a set of states across a date range (`bat_event_get_matching_units`).
- Build an in-memory availability `Calendar` for a set of unit types (`bat_event_get_calendar`).
- Get a calendar response (included/excluded units) for a period (`bat_event_get_calendar_response`).
- Point events at a non-unit target entity type via `hook_bat_event_target_entity_types()`.
- Register booking constraints (min stay, etc.) with `hook_bat_event_constraints_info()`.
- Maintain fast per-event-type state/event calendar tables automatically as event types change.
- Persist availability writes through the Roomify BAT library's `Calendar` + `DrupalDBStore`.
- Reference an event's state via the `bat_event:state` entity-reference selection handler.
- Configure which field carries an event's value/label per event type.
- Prune old past events on cron for performance (`/admin/bat/config/bat_event`, opt-in, data-integrity warning).
- List and administer events at `/admin/bat/events/event` and event types at `/event-types`.
- Manage availability states at `/admin/bat/events/state`.
- Filter Views by blocking/non-blocking events (`BatEventHandlerBlockingFilter`).
- Show event duration, value, or event-type as Views fields.
- Load/create/save/delete events and event types via the `bat_event_*` API.
- Enumerate event ids matching conditions (`bat_event_ids`) or all event type ids (`bat_event_types_ids`).
- Underpin `bat_booking`, `bat_event_series`, `bat_fullcalendar`, and `bat_facets`, which all build on events.
- Clean up an event type's calendar tables automatically when the type/bundle is deleted.
