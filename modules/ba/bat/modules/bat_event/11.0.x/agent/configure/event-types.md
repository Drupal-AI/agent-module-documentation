# BAT Event — entities, event types, calendar tables

## Entities

| Entity | Type | Base table | Bundle | Notes |
|---|---|---|---|---|
| `bat_event` | content | `event` | `bat_event_type` (config) | An availability/value record for a unit over a period. |
| `state` | content | `states` | — | A possible availability state (Available, Booked, ...). |
| `bat_event_type` | config | — | (bundle_of `bat_event`) | Controls granularity, states, target entity, value fields. |

`bat_event` base fields: `id`, `uuid`, `uid` (owner), `created`, `changed`, `type` (→ `bat_event_type`).
Field storages installed in `config/install`: `event_dates` (**daterange**, datetime), plus
`event_state_reference` / `field_event_state_reference` (**entity_reference** → `state`). The unit
link is `unit_id` (→ the type's `target_entity_type`, default `bat_unit`).

## Event type (`bat_event_type`) config

`config_export` keys (schema `bat_event.event_type.*`):

| Key | Meaning |
|---|---|
| `name`, `type` | Label + machine name. |
| `event_granularity` | `bat_daily` or `bat_hourly` — the calendar resolution. |
| `fixed_event_states` | Whether the type uses a fixed set of states (vs open/value states). |
| `target_entity_type` | The entity type events target (default `bat_unit`). |
| `default_event_value_field_ids` | Field(s) holding the event's value/price. |
| `default_event_label_field_name` | Field holding the event's display label. |

Managed at `/admin/bat/events/event/event-types` (perm `administer bat_event_type entities`). When a
type is added/edited, `hook_ENTITY_TYPE_insert`/form submit call
`bat_event_type_add_event_state_reference()`, `bat_event_type_add_event_dates_field()`, and
`bat_event_type_add_target_entity_field()` to attach the required fields.

## Dynamic calendar tables (the availability store)

For each event type, BAT maintains **two SQL tables** — a *state store* and an *event store* —
created by `bat_event_create_event_type_schema($machine_name)` and named per the Roomify
`DrupalDBStore` convention. Column sets are generated by `bat_event_generate_day_schema_fields()`,
`_generate_hour_schema_fields()`, `_generate_minute_schema_fields()` (day → hour → minute columns).
`bat_event_get_event_type_tables()` returns the names; `bat_event_delete_event_type_schema()` drops
them on type deletion (`bat_event_entity_bundle_delete`). `Event::batStoreSave()` writes availability
into them via `Roomify\Bat\Calendar\Calendar` + `Roomify\Bat\Store\DrupalDBStore` (state calendar +
event calendar). The machine name driving table creation comes from the event-type config entity
(created by the restricted `administer bat_event_type entities` permission).

## State entity

`state` records the availability states. Referenced from events through the
`bat_event:state` EntityReferenceSelection plugin (`StateSelection`). Load helpers:
`bat_event_load_state($id)`, `bat_event_load_state_by_machine_name($name)`, `bat_event_get_states()`,
`bat_event_create_state()`, `bat_event_save_state()`. Managed at `/admin/bat/events/state`
(perm `administer state entities`).

## Routes & settings

- Events: `/admin/bat/events/event` (collection requires the **restricted** `bypass bat_event
  entities access`), add `/event/add[/{event_type}]` (`_event_add_access`), canonical/edit/delete
  (`_entity_access`).
- States: `/admin/bat/events/state[...]` (`administer state entities`).
- Event types: `/admin/bat/events/event/event-types[...]` (`administer bat_event_type entities`).
- **Settings** `/admin/bat/config/bat_event` (`BatEventSettingsForm`, perm `configure bat settings`):
  edits `bat_event.settings` → `bat_event.delete_old` (`status`, `days_back`, `how_many_per_cron`) so
  `bat_event_cron()` prunes old past events. The form itself warns this can break data integrity;
  it is opt-in and off by default.
