Backstop Generator provides a Drupal admin UI for building BackstopJS visual-regression test configuration (a `backstop.json` / `bsg_<profile>.json` file per test Profile) from your site's URLs, menus, content types, and theme breakpoints.

---

The module models a BackstopJS test as three config entity types — Profiles, Scenarios, and Viewports. A Viewport is a screen size (width/height); the install hook auto-creates viewports from the default theme's breakpoint definitions, and the Viewport Generator can import breakpoints from any enabled theme. A Scenario is a single page/URL state to screenshot, with dozens of BackstopJS knobs (delay, hide/remove/click/hover selectors, ready events, cookiePath, misMatchThreshold, etc.). A Profile groups viewports + scenarios + engine/parallelism settings, and its `generateBackstopFile()` method serialises everything through `BackstopJsonTemplate` and writes the resulting JSON to a directory (default `/tests/backstop`, one level above the Drupal docroot). Scenarios are not created by hand — the add form is disabled by a route subscriber — but are bulk-generated by `ScenarioGenerator` from the homepage, menu trees (with depth), random nodes per content type, or explicit paths / node lookups, in all enabled languages. A Commands admin page prints copy-paste `backstop reference` / `backstop test` terminal commands per profile; the module itself never runs BackstopJS (Node.js) — that is done by the developer from a terminal. All routes require `administer site configuration`; entity operations use the `administer backstop_generator` permission.

---

- Generate a `backstop.json` for BackstopJS visual-regression testing without hand-editing JSON.
- Create separate test Profiles for different concerns (languages, menus, content types, or specific paths).
- Auto-create Viewports (screen sizes) from a theme's breakpoint definitions on install.
- Import viewport sizes from any enabled theme via the Viewport Generator.
- Define custom viewports (mobile/tablet/desktop) manually with explicit width and height.
- Bulk-generate homepage Scenarios for every enabled language.
- Bulk-generate Scenarios by walking one or more menu trees to a configurable depth.
- Bulk-generate Scenarios for N random nodes of chosen content types.
- Bulk-generate Scenarios from explicit paths or `Label | node/1`-style entries.
- Set global default test/reference domains applied to all new scenarios (e.g. CI URL vs. production).
- Configure per-profile scenarioDefaults (delay, misMatchThreshold, requireSameDimensions, selectors) inherited by scenarios.
- Override profile defaults on individual scenarios for modals, dynamic content, or edge cases.
- Hide selectors (visibility) or remove selectors (display:none) to mask volatile elements and avoid false diffs.
- Automate UI interactions before capture: click/hover selectors, keypress selectors, scroll-to selector.
- Wait for readiness before capture via readyEvent, readySelector, readyTimeout, or a fixed delay.
- Import cookies via a cookiePath to bypass cookie-consent or auth walls during capture.
- Choose the BackstopJS engine (Puppeteer or Playwright) and pass engine/Chromium args (e.g. `--no-sandbox`).
- Tune CI performance with asyncCaptureLimit and asyncCompareLimit.
- Toggle debug / debugWindow output for troubleshooting test runs.
- Regenerate affected profile JSON automatically when a referenced viewport or scenario is edited or deleted.
- Regenerate all global-default profiles when module-wide settings change.
- Copy ready-made `cd`, `backstop reference`, and `backstop test` commands from the Commands page.
- Test multilingual sites by generating language-prefixed scenario URLs for non-default languages.
- Keep visual-regression config in Drupal config so it exports/imports with the rest of the site.
