# `email_message_log` content entity

Records one sent message. Class `Drupal\email_messages\Entity\EmailMessageLog`
(`@ContentEntityType`), interface `EmailMessageLogInterface` (extends `EntityOwnerInterface`).
Created automatically by `EmailMessageManager::mailMessage()` when the source message has
`log_message` enabled (see ../api/manager.md).

## Definition (annotation)

- `id = "email_message_log"`, `base_table = "email_message_log"`,
  `admin_permission = "administer message log"`.
- `entity_keys`: id=`id`, label=`id`, uuid=`uuid`.
- Handlers: `view_builder` = `EmailMessageLogViewBuilder`, `list_builder` =
  `EmailMessageLogListBuilder`, `views_data` = core `EntityViewsData`, forms add/edit =
  `EmailMessageLogForm`, delete = core `ContentEntityDeleteForm`, route_provider =
  core `AdminHtmlRouteProvider` (so canonical/add/edit/delete/collection routes are generated and
  gated by `administer message log`).
- `field_ui_base_route = entity.email_message_log.settings` (Field UI attaches here).
- Links under `/admin/structure/email-message-logs[...]`.
- `preCreate()` defaults `uid` to the current user.

## Base fields (`baseFieldDefinitions()`)

`description` (text_long), `rendered_message` (text_long — the resolved body, view-only),
`message` (entity_reference → `email_message`), `email` (email — recipient), `language` (language),
`uid` (entity_reference → user, "Author"), `created` (created — "Sent time"). Getters/setters for
created time and owner come from the interface.

## Routes / links

Generated by `AdminHtmlRouteProvider` (all require `administer message log`):
canonical `/admin/structure/email-message-logs/{email_message_log}`, add, edit, delete, collection.
Local task `entity.email_message_log.view/edit_form/delete_form/collection` and menu links live in
`*.links.task.yml` / `*.links.menu.yml`. A separate settings form route
`entity.email_message_log.settings` (`admin/structure/email-message-log`,
`EmailMessageLogSettingsForm`, perm `administer message log`) is a placeholder page (just a Save
button) serving as the Field UI base route.

## List builder (`EmailMessageLogListBuilder`, extends `EntityListBuilder`)

Constructed with `date.formatter` + `redirect.destination`. Columns: id (link), author (themed
username), email, message (referenced entity label), created (formatted). `render()` appends a
"Total message logs: N" summary. `getDefaultOperations()` adds the current destination to each op
and removes the `edit` operation.

## View builder

`EmailMessageLogViewBuilder` unsets `#theme` in `getBuildDefaults()` — the log has no entity
template; it renders as plain field output.

## Bundled view (`config/install/views.view.email_message_logs.yml`)

View `email_message_logs`, base table `email_message_log`, page display at
`admin/structure/email-message-logs`. Access: `perm` = **`access message log overview`**. Shows id,
email, message, language, uid, created; exposed filters on email, uid, message. `hook_views_data_alter()`
sets the `uid` filter handler to `user_name` and the `message` filter to the `email_message` plugin.
Installed on new sites via `config/install`; on existing sites `email_messages_update_9002()` imports it,
and `_9001()` installs the log entity type.

## Views filter plugin (`src/Plugin/views/filter/Message.php`)

`@ViewsFilter("email_message")`, class `Message` extends core `InOperator`. Provides an
`entity_autocomplete` (target_type `email_message`, tags) value form so the log view can be filtered
by one or more referenced messages; `valueValidate()`/`validateExposed()` reduce autocomplete input
to message ids; `adminSummary()` loads the selected messages for the summary label.

Note: browsing logs (which include recipient addresses and rendered message content) requires the
explicit `access message log overview` permission; entity CRUD requires `administer message log`.
