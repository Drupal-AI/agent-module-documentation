# Entity Migrate Export (eme) — agent index

Developer/admin tool that exports existing content entities into a **generated
Drupal module** made of Migrate API migration YAMLs plus their source data (one
JSON file per entity, with copied file assets). Enable and run that generated
module with core Migrate + Migrate Plus (`drush migrate:import`) on another
environment to recreate the content. Entities referenced by the selected ones
(and some reverse references) are pulled in automatically so the migrations run
without broken dependencies.

- No contrib dependencies; core `^8.9 || ^9 || ^10 || ^11`. The **generated**
  module depends on `drupal:migrate` and `migrate_plus:migrate_plus`
  (`migrate_plus` is in eme's `require-dev`, so confirm it is installed on the
  target site before importing).
- Settings route (`configure`): `eme.settings` →
  `/admin/config/development/entity-export/settings`.
- Defines permissions, three Drush commands, config schema, and two plugin types.

## What you'd do

- **Run an export and read the generated module layout** → [drush/commands.md](drush/commands.md)
- **Change export defaults (base id, entity types to ignore)** → [configure/settings.md](configure/settings.md)
- **Grant who may export / manage settings** → [permissions/permissions.md](permissions/permissions.md)
- **Add an export format or a reference-discovery rule** → [plugins/export.md](plugins/export.md)

## Routes (all admin, under `/admin/config/development/entity-export`)

| Route | Path suffix | Form / controller | Permission |
|---|---|---|---|
| `eme.eme_export_form` | (root) | `Form\ExportForm` | `export content` |
| `eme.collection` | `/collection` | `Form\Collection` (re-export previous exports) | `export content` |
| `eme.settings` | `/settings` | `Form\EmeSettingsForm` | `manage content export settings` |
| `eme.eme_export_download` | `/download` | `Form\DownloadForm` | `export content` |
| `eme.eme_export_download_file` | `/download-file` | `Controller\DownloadController::download` | `export content` + `_export_exists` |

UI flow: pick entity types + names on `ExportForm` → batch runs → on success it
redirects to `eme.eme_export_download`, which serves the tarball `eme.tar.gz`
from `temporary://`. `Collection` lists modules previously generated by eme
(discovered via their `eme_settings` info key) and re-exports them.

## Key facts

- Config object: `eme.settings`. Keys: `eme_id` (string, nullable),
  `ignored_entity_types` (sequence of entity-type IDs).
- Service ids: `eme.batch_runner`, `eme.export_plugin_manager`,
  `eme.discovery_plugin_manager`, `logger.channel.eme`; access checks
  `access_check.export_exists` (`_export_exists`) and
  `access_check.temporary_scheme_configured` (`_temporary_stream_accessible`).
- Permissions: `export content`, `manage content export settings` (both
  `restrict access: TRUE`).
- Drush: `eme:export` (`emex`), `eme:cleanup` (`emecl`), `eme:release-lock` (`emerl`).
- Plugin types: **Eme export** (`@Export`, manager `eme.export_plugin_manager`,
  dir `Plugin/Eme/Export`) and **Eme reference discovery** (`@ReferenceDiscovery`,
  manager `eme.discovery_plugin_manager`, dir `Plugin/Eme/ReferenceDiscovery`).
- Only shipped export plugin: `json_files`. Shipped reference-discovery plugins:
  `EntityReference`, `MenuLinkContent`, `PathAlias`, `Crop`, `Flagging`,
  `LayoutOverride`.
- Generated module default name `<eme_id>_content` (default `eme_content`);
  default migration group and ID-prefix `<eme_id>` (default `eme`). Batch/lock
  name and `semaphore` key: `eme`. Archive: `eme.tar.gz`.
- No submodules. (`tests/modules/eme_test_module_extension_list` is a test-only
  helper, not shipped.)
