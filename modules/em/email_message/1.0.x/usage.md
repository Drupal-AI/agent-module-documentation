Email Message field adds a single Drupal field type that stores an email subject together with a formatted body, so an editor can capture a whole email message in one field instead of two loose fields.

---

The module registers one field type (`email_message`), one widget (`email_message_default`) and one formatter (`email_message_default_formatter`). The field type extends core's `text_long` item, so the body is a long, format-filtered text value; a required `subject` string column is added alongside it. The default widget is core's textarea widget wrapped in a fieldset with an extra "Email subject" textfield above the body, and the default formatter renders the subject (with line breaks preserved) followed by the format-processed body inside an `email-message` container. The module only stores and displays the data: despite the name it sends no mail, defines no routes, permissions, services or hooks, and has no configuration form. It requires the core `field` and `text` modules. Add the field to any fieldable entity via Manage fields, then read the parts back in code through `getEmailSubject()` and `getEmailBody()` on the field item.

---

- Store a reusable welcome / onboarding email (subject + body) as a field on a content type.
- Add a "notification email" field to a Webform-adjacent or custom entity so each record carries its own message.
- Let editors author transactional email copy (order confirmation, password reset wording) in the CMS instead of in code.
- Keep a subject and body together as one logical value so they cannot drift apart across two separate fields.
- Attach several distinct email-message fields to one entity (e.g. "approval mail" and "rejection mail"), each keeping its own configured label as the group title.
- Provide a formatted body using a chosen text format (filtered HTML, full HTML, plain text) rather than raw text.
- Configure a default value (subject, body and text format) on the field so new entities start with boilerplate email copy.
- Expose the message on the entity's display using the default formatter, showing subject then rendered body.
- Read the subject in custom code with `EmailMessageItem::getEmailSubject()` to feed a mail plugin's subject line.
- Read the processed body in custom code with `EmailMessageItem::getEmailBody()` to feed a mail plugin's body.
- Model per-node or per-term email templates that a custom `hook_mail()` implementation later assembles and sends.
- Give site builders a single field to place on config-entity-like content that represents an email template.
- Capture campaign / newsletter draft copy (subject line + body) as structured entity data.
- Store canned support-reply templates that staff select and send from a custom workflow.
- Hold the subject and body for automated reminders (event reminders, renewal notices) generated by cron.
- Validate that a message counts as filled only when both subject and body are present (the item is empty otherwise).
- Generate sample email-message content in tests or with Devel Generate via the field type's `generateSampleValue()`.
- Migrate legacy subject/body pairs into a single structured field during a content migration.
- Reference a complete email message from other entities via an entity reference to the host entity.
- Localize / translate email subject and body together as one field on translatable entities.
- Present editors a consistent fieldset UI (subject above a rich-text body) wherever an email message is edited.
- Use the field's text format handling so the rendered body is sanitized by the format's filters on display.
- Build a library of email messages (one entity per message) for staff to browse and pick from.
