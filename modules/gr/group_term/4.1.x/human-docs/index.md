# Group Term — manual setup guide

**Group Term** (`group_term`) lets you treat taxonomy terms as *group content*.
On its own, Drupal's [Group](https://www.drupal.org/project/group) module lets
you build "groups" — teams, tenants, departments, clubs — that own their own
content and have their own membership and permissions. Group Term extends that
idea to your vocabularies: it lets a group *own* a set of taxonomy terms, so each
group can curate its own categories or tags instead of everyone sharing one flat
site-wide list.

Under the hood it registers a Group *relation type* with one variant per
vocabulary (`group_term:<vocabulary_id>`, for example `group_term:tags`). Once you
enable that relation on a group type, each group of that type gains a **Terms**
tab that lists the terms it owns, plus buttons to create brand-new terms or relate
existing ones — all governed by Group's normal per-group roles and permissions.
Each term belongs to a single group (the relationship is fixed to one group per
term).

It also adds handy tokens so you can print a term's owning group anywhere tokens
are supported: `[term:group]` gives the group's label, and `[term:groups]` returns
the full list of a term's parent groups (the array token needs the contrib
[Token](https://www.drupal.org/project/token) module).

There is **no settings form** for this module — everything is configured through
Group's own relationship UI and permission matrix, which is why this guide has no
separate configuration page. If you want a terse, token-cheap reference for an AI
coding agent instead, read the sibling [`agent/`](../agent/start.md) docs.

## Where it lives in the admin menu

Group Term has no page of its own. You configure it from within the Group module:

- **Enable the relation** at **Structure → Group types → *(your group type)* →
  Set available content** (`admin/group/types/manage/<type>/content`) — pick the
  "Group term (*vocabulary*)" plugin.
- **Grant permissions** in that group type's permission matrix (Group's own
  per-role permissions screen).

## How to use it

1. **Decide which vocabulary a group should own.** Every vocabulary on your site
   becomes an available relation named `group_term:<vocabulary_id>`. (Create a new
   vocabulary and it appears automatically.)
2. **Install the relation on a group type.** Go to **Set available content** for
   the group type and enable the "Group term (*vocabulary*)" plugin. From now on,
   groups of that type can own terms from that vocabulary.
3. **Set who can do what.** In the group type's permissions, grant roles the
   rights they need:
   - `access group_term overview` — lets a member see the group's **Terms** tab
     and the list of owned terms.
   - `create group_term:<vocab> entity` (and the matching update/delete/view
     permissions, generated by Group) — lets a member add or manage terms for
     their group.
   - The global `create any group_term entity` permission is a blanket
     administrator override that ignores per-group restrictions — treat it as
     trusted-admin only.
4. **Manage a group's terms.** Visit a group and open its **Terms** tab
   (`group/{group}/terms`). From there you can **Create taxonomy term** (a new term
   scoped to this group, at `group/{group}/term/create`) or **Relate taxonomy
   term** to attach an existing term (`group/{group}/term/add`).
5. **Reuse the owning-group in tokens.** Wherever tokens are available, use
   `[term:group]` for the owning group's label, chained tokens like
   `[term:group:id]` or `[term:group:url]`, and `[term:groups]` for the full list.

This makes Group Term a natural fit for multi-tenant sites where each tenant curates
its own tags, or for any setup where categories should be owned and moderated by a
specific group rather than shared across the whole site.
