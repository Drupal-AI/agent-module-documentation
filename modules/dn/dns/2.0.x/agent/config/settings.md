# DNS — install, settings, routes, Views, migration

## Install / enable

`drush en dns` pulls in core `options`, core `views`, and contrib `field_ipaddress` (require `drupal/dns` via Composer; it declares `drupal/field_ipaddress:^2.0` and PHP `ext-intl`). Enabling installs the three entity tables (`dns_zone`, `dns_record`, `dns_zone_grant`), the `dns.settings` config object, and the `dns_records` view. Sites upgrading from alpha2 get the grant table created by post-update `dns_post_update_install_zone_grant_entity()` (`dns.post_update.php`) — without it the access policy fatals on missing `dns_zone_grant` storage.

## Settings form and config

`\Drupal\dns\Form\SettingsForm` (form id `dns_settings`) at route `dns.settings` → `/admin/config/content/dns`, permission `administer dns`. It edits config object **`dns.settings`** (`getEditableConfigNames()`), two keys:

- `allow_tld_zones` (boolean, default `false`) — allow single-label zones like `com`.
- `default_ttl` (integer seconds, default `3600`) — pre-filled TTL for new records (applied in `DnsRecordForm::getEntityFromRouteMatch()`).

Install defaults: `config/install/dns.settings.yml`. Schema: `config/schema/dns.schema.yml` defines `dns.settings` (config_object) and `views.field.dns_record_rdata_value` (`views_field` with a `rdata_key` string option).

## Routes (`dns.routing.yml`)

Only four routes are declared explicitly; entity CRUD routes are generated by route providers (see [api/entities.md](../api/entities.md)).

- `dns.settings` — `/admin/config/content/dns`, `_form: SettingsForm`, `_permission: administer dns`, `_admin_route`.
- `dns.admin_content` — `/admin/content/dns`, `_controller: SystemController::overview`, `_permission: administer dns` (menu landing page listing Zones/Records).
- `dns.record_add` — `/dns/records/add`, `_entity_form: dns_record.add`, `_permission: administer dns`. Zone-less entry: the form shows a zone autocomplete and re-checks per-zone create access at validate time (`DnsRecordForm::validateForm()`), so the admin-only route requirement does not weaken per-zone gating.

## Permissions (`dns.permissions.yml`)

`administer dns` (`restrict access: true`, super-admin escape and the entity `admin_permission` for all three entities), `create dns zones`, and the legacy site-wide zone perms `view any dns zone`, `view own dns zones`, `edit own dns zones`, `delete own dns zones`. Fine-grained per-zone capabilities are **not** site-wide permissions — they live in the `dns_zone` access-policy scope (see [api/entities.md](../api/entities.md)).

## Menu / action / task links

- Menu (`dns.links.menu.yml`): `DNS` under `system.admin_content`; children `Zones` (zone collection), `Records` (records view page); `DNS settings` under `system.admin_config_content`.
- Actions (`dns.links.action.yml`): `Add zone` on the zone collection; `Add record` on the records page (zone-less `dns.record_add`); `Add record` on the zone canonical via `Plugin/Menu/LocalAction/AddRecordToZoneAction` (injects the `{dns_zone}` route param).
- Tasks (`dns.links.task.yml`): zone tabs `View` / `Edit` / `Delete` / `Collaborators`. Records have no canonical view, so no record tabs.

## Views integration

`config/install/views.view.dns_records.yml` ships view `dns_records` (base table `dns_record`) with three displays:

- `page_records` → path `admin/content/dns/records`, access `perm: administer dns`.
- `embed_zone` → embed display, access `none`; embedded on the zone canonical page by `dns_dns_zone_view()` (`dns.module`) with the zone id as the contextual argument, so it is gated by the zone's own view access. Rows carry a `dns-record-type-{{ record_type }}` class powering the `dns/type_filter` client-side pills.
- Row style folds `ip_address` + `target` (and several `rdata_value` instances: priority/weight/port/content) into one "Value" column.

`dns.views.inc::dns_views_data_alter()` adds a virtual `rdata_value` field to `dns_record`, handled by `\Drupal\dns\Plugin\views\field\RdataValue` (`#[ViewsField('dns_record_rdata_value')]`). It adds no SQL (`query()` is a no-op, not click-sortable); `render()` reads a single key from the loaded entity's decoded `rdata` and returns it as a string, empty when the key is absent.

## Drupal 7 migration

`migrations/d7_dns_zone.yml` and `d7_dns_record.yml` (tags `Drupal 7`, `Content`). Source plugins `D7DnsZone` / `D7DnsRecord` (`src/Plugin/migrate/source/`) read the D7 `dns_zones` / `dns_records` tables via the query builder (parameterized `->fields()` / `->leftJoin()`; `addExpression('z.name', …)` uses a literal column). Process plugins (`src/Plugin/migrate/process/`): `DnsCanonicalZoneName`, `DnsZoneUnicodeLabel`, `DnsD7Rdata`, `DnsD7TargetCanonical`. Zones default `uid` to 1 (D7 user mapping is post-alpha); records are folded into the 2.x base-field + `rdata` shape. Fixture: `tests/fixtures/migrate/dns7.php`.
