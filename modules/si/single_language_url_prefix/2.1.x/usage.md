Single Language URL Prefix keeps a language path prefix (e.g. `/en`) in every URL even when the site has only **one** enabled language — something core drops for monolingual sites.

---

Drupal core only applies the URL language prefix when more than one language is enabled; on a single-language site core strips it, so `/en/about` becomes `/about`. This module registers an inbound/outbound **path processor** (`SingleLanguageNegotiationUrl`, service `single_language_url_prefix.path_processor`, tagged inbound priority 500 / outbound -1) that re-adds the behaviour for the one-language case. It only acts when exactly one language is enabled and the core URL language-negotiation **source is "path prefix"** with a prefix configured for that language: on **outbound** URLs it injects the prefix into `$options['prefix']`; on **inbound** requests it strips the matching prefix back off so routing still works. A single settings form (`single_language_url_prefix.settings` at `/admin/config/regional/language/single-language-url-prefix`, permission *administer languages*) holds one value, `excluded_paths` — a newline-separated list of paths/patterns (matched with core's `path.matcher`) that should keep working **without** the prefix. If more than one language is enabled, the module does nothing and core's normal behaviour takes over.

---

- Keep a `/en` prefix on a monolingual English site's URLs for consistency with a future multilingual rollout.
- Prepare URLs for adding a second language later without changing existing link structures.
- Serve a single-language site under a language-prefixed path (e.g. `/fr/...`) to match a CDN or proxy layout.
- Preserve language-prefixed URLs when temporarily disabling all but one language.
- Match analytics or redirect rules that expect a language segment in every path.
- Exclude `/admin` and `/user` paths from the prefix so back-office URLs stay clean.
- Exclude an API base path (e.g. `/api/*`) from getting a language prefix.
- Exclude webhook or callback endpoints that third parties call without a prefix.
- Keep a health-check or status path prefix-free while everything else is prefixed.
- Enforce a canonical prefixed URL shape across a single-language marketing site.
- Provide language-prefixed URLs for a decoupled front end that always expects `/en/...`.
- Migrate a formerly multilingual site down to one language without breaking prefixed links.
- Configure exclusions as wildcard patterns (e.g. `/blog/*`) using core's path matcher.
- Ensure outbound links generated by Drupal include the language prefix even when monolingual.
- Ensure inbound prefixed requests still resolve to the right route on a single-language site.
- Standardise URL structure so switching to multilingual is a config-only change.
- Keep search-engine-indexed prefixed URLs valid after reducing to one language.
- Avoid custom code or a custom path processor to achieve prefixing on a monolingual site.
- Exclude a set of legacy paths from prefixing during a phased migration.
- Combine with core language negotiation "URL" (path prefix) to drive the prefix value.
- Present a consistent `/lang/...` URL scheme to editors and authors on a one-language site.
- Support a design where the language code is always the first URL segment.
