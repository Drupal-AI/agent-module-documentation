# Simple XML sitemap exclude pattern — manual setup guide

**Simple XML sitemap exclude pattern** (`simple_sitemap_exclude`) extends the
Simple XML Sitemap module with **path-pattern exclusions**. Where the base module
decides sitemap inclusion one entity bundle or one entity at a time, this add-on
lets you write a pattern that keeps out a whole *family* of URLs at once — every
faceted-search permutation, every paginated variant of an archive, a staging
section, a set of thank-you pages, or paths generated by a module rather than by an
entity. Those are exactly the cases that per-entity settings can't express, because
the URLs are generated rather than stored.

The reason to bother is a search-engine argument, not a tidiness one. A sitemap is
a statement to a crawler about which URLs are worth its attention, and crawl budget
is finite: a site that submits fifty thousand faceted permutations dilutes the
signal for the two thousand pages it actually cares about, and near-duplicate URLs
in a sitemap are an active negative. Excluding the noise makes the sitemap say what
you mean.

The flip side is the thing to be careful about: **an exclusion pattern is broader
than it looks.** A pattern that quietly removes a whole content section becomes a
set of pages that stop being found — often discovered months later in a traffic
report. Write patterns narrowly, and check the generated sitemap after changing one
rather than trusting the pattern to mean what it looked like it meant.

The module depends on **Simple XML Sitemap** (`simple_sitemap`), adds an
**Administer sitemap settings** permission, and works on Drupal 10.2 and 11.

This guide is written for a **human** clicking through the admin UI. If you want
terse, token-cheap references for an AI coding agent, read the sibling
[`agent/`](../agent/start.md) docs instead.

## Where it lives in the admin menu

Manage your exclude patterns at **Configuration → Search and metadata → Simple XML
Sitemap → Exclude** (`/admin/config/search/simplesitemap/exclude`).
