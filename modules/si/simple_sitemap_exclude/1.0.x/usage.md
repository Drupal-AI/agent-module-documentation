Simple XML sitemap exclude pattern adds a list of regular-expression path patterns to Simple XML Sitemap; during sitemap generation any link whose path matches a pattern is dropped from the sitemap. Configure the patterns at `/admin/config/search/simplesitemap/exclude` (permission `administer sitemap settings`).

---

Simple XML Sitemap decides inclusion per entity bundle and per entity, which covers ordinary content but not the awkward URLs a site also serves: faceted-search permutations, paginated archive variants, a staging section, thank-you pages that only make sense after a form submission, or paths emitted by a module rather than by an entity. This module fills that gap with a single textarea of patterns, one per line. Each line is a **PHP `preg_match()` regular-expression body** — the module wraps it as `'/' . $pattern . '/'` and tests it against the link **path** (the generated URL with the scheme and host stripped, e.g. `/node/12`). The matching is enforced through `hook_simple_sitemap_links_alter()`: for every configured pattern it walks the pending links and `unset()`s any whose path matches, so exclusion happens as links are collected, before the XML is written, and applies across sitemap variants. Patterns are unanchored substring matches unless you anchor them yourself — `^\/node\/.*` catches every node path, `^\/home$` catches only `/home`. Config lives in `simple_sitemap_exclude.settings:patterns` (a sequence of strings); the form also exposes Simple Sitemap's "regenerate now" control so you can rebuild immediately. Version **1.0.0**, core `^10.2 || ^11.0`, requires `simple_sitemap ^4.2`. The point of care is that **a pattern is broader than it looks**: an unanchored or greedy pattern can silently strip a whole content section, a page that then stops being discovered and surfaces months later in a traffic report. Write patterns narrowly and re-check the generated sitemap after changing one. Because the patterns are compiled and run by `preg_match()` at generation time, only trusted administrators (the `administer sitemap settings` permission) should hold this access.

---

- Exclude faceted-search URLs (query-style listing paths) from the sitemap.
- Keep paginated archive variants (`?page=`/`/page/N`) out of a sitemap.
- Exclude thank-you / confirmation pages that only exist post-submission.
- Remove a staging or work-in-progress section by path prefix.
- Exclude module-generated paths that have no entity to toggle in Simple Sitemap.
- Drop print or export URLs (e.g. `/print/*`) from search.
- Exclude a legacy path prefix during a migration.
- Keep utility pages (e.g. `/user/*`, `/search`) unindexed via the sitemap.
- Reduce sitemap size by removing near-duplicate URLs.
- Exclude a campaign landing path from organic discovery.
- Focus crawl budget on canonical, high-value pages.
- Exclude all node paths with `^\/node\/.*` while keeping alias URLs.
- Exclude a single exact path with an anchored pattern like `^\/home$`.
- Keep test or demo content out of the sitemap by path.
- Remove filtered listing URLs generated by Views.
- Improve SEO signal quality by trimming low-value URLs.
- Regenerate the sitemap immediately after editing patterns from the same form.
- Combine several exclusion rules by listing one regex per line.
- Audit which URLs a pattern removes by diffing the generated sitemap before/after.
- Exclude a private or gated section that should not be advertised to crawlers.
