# Permissions

Permissions are **dynamic**, generated by
`\Drupal\form_mode_control\FormModePermission::getPermissions()` (declared via
`permission_callbacks` in `form_mode_control.permissions.yml`).

## Per-form-mode permissions

For **every enabled** `entity_form_display` (each activated form mode on each bundle), one
permission is generated. Its machine name is built by
`form_mode_control_get_permission_by_mode_and_role()`:

```
use  The form mode <form_mode_id> linked to  <entity_type_id> entity( <bundle> )
```

(note the literal double spaces — the string is used verbatim as the permission id). Its
human label reads *"Use the form mode <mode> linked to <Entity type> ( <Bundle> )"*. Holding this
permission lets the role open that bundle's form via `?display=<form_mode_id>`. Each such
permission declares a config dependency on the bundle (or the form display) so it is removed if the
bundle/form display goes away.

## Master permission

- **`access_all_form_modes`** — label *"Use all form modes"*. A role with this permission may
  switch to **any** form mode by URL, regardless of the individual per-form-mode permissions.

## Where to grant

`/admin/people/permissions` — the permissions appear under a *Form Mode Control* section (only the
form modes that are currently activated on a bundle show up). The admin config form links here via
its "Manage form mode permissions" button.

Note: the stored **default** form mode (configured on the admin form) is applied regardless of
these permissions; the permissions only gate the interactive `?display=` switch.
