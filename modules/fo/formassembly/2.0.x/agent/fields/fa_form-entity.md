# The `fa_form` entity and how a form is embedded

`fa_form` is a `ContentEntityType` (`Drupal\formassembly\Entity\FormAssemblyEntity`) — one entity per
FormAssembly form. Base table `fa_form`. It is populated/updated by sync, not hand-authored (see
[../api/services.md](../api/services.md)).

Handlers: view builder `FormAssemblyEntityViewBuilder`, storage `FormAssemblyStorage`, access
`FormAssemblyEntityAccessControlHandler`, list builder `FormAssemblyEntityListBuilder`, forms
default/add/edit `FormAssemblyEntityForm` + delete `FormAssemblyEntityDeleteForm`, route provider
`FormAssemblyEntityHtmlRouteProvider`, views data `FormAssemblyEntityViewsData`.

## Base fields

| Field | Type | Notes |
|---|---|---|
| `id` | internal id | Entity id. |
| `uuid` | uuid | |
| `user_id` | (uid key) | Set to current user on create. |
| `name` | string(255) | Form name as keyed by FormAssembly; overwritten on sync. Entity label. |
| `status` | boolean | Enabled/Archived. Sync disables forms missing upstream. |
| `faid` | integer | FormAssembly form id (read-only). Sync matches on this. |
| `modified` | timestamp | Last modified in FormAssembly (read-only); drives update-on-sync. |
| `created` | created | Created in Drupal. |
| `changed` | changed | Last edited in Drupal. |
| `query_params` | map | Pre-fill parameters, `map_assoc_widget` (from `map_widget` dep). Key = the `tfa` input `name`; value = literal or Drupal token. Sent on the markup request. |

## Routes (entity)

Generated by `FormAssemblyEntityHtmlRouteProvider` (extends core `AdminHtmlRouteProvider`) — the routing
YAML only declares the OAuth endpoints.

| Route | Path | Access |
|---|---|---|
| `entity.fa_form.canonical` | `/formassembly/fa_form/{fa_form}` | `view formassembly form entities` |
| `entity.fa_form.collection` | `/formassembly/fa_form` | `access formassembly form overview` |
| `entity.fa_form.add_form` | `/formassembly/fa_form/add` | create (see permissions note) |
| `entity.fa_form.edit_form` | `/formassembly/fa_form/{fa_form}/edit` | `edit formassembly form entities` |
| `entity.fa_form.delete_form` | `/formassembly/fa_form/{fa_form}/delete` | delete (see permissions note) |
| `fa_form.settings` | `/admin/structure/fa_form/settings` | `administer formassembly form entities` |

`field_ui_base_route` is `fa_form.settings`, so Field UI display/fields tabs attach there.

## Rendering / embedding

`FormAssemblyEntityViewBuilder::view()` calls `ApiMarkup` to fetch the form HTML, splits it into head
(scripts/links, moved to `#attached`) and the `.wFormContainer` body using `symfony/dom-crawler`, and
outputs the body as `#markup` wrapped in `FormBodyUnescapedMarkup` (rendered verbatim — the module
deliberately trusts FormAssembly's HTML/JS/CSS). It sets `max-age = 0` and triggers the page-cache
kill switch, so form pages are not cached. View mode `fa_form.markup` is installed for this.

Two ways to place a form:
- **Own path** — visit the entity canonical route `/formassembly/fa_form/{id}`.
- **Entity reference** — add an entity-reference field targeting `fa_form` to any entity; editors need
  `reference formassembly` to select a form. The referenced form renders inline where the field displays.

When the Token module is present, `query_params` values may use tokens (resolved per request, with the
current user and any content entity in the route as token data). Optional `scrivo/highlight.php` adds a
read-only HTML inspector to the entity edit form.
