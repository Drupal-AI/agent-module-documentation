Form Mode Manager Theme Switcher lets you assign a specific theme (front, admin, or a named "custom" theme) to each Form Mode Manager form-mode route, so, for example, a "contributor" add form can render in a different theme from the rest of the site.

---

The submodule registers a theme negotiator (`theme.negotiator.form_mode_theme_switcher`, priority -30) that applies only on routes generated by Form Mode Manager (routes carrying the `_form_mode_manager_entity_type_id` option). For each such route it looks up its configuration keyed by the form-mode id (the route's `_entity_form` operation with dots replaced by underscores, e.g. `node.contributor` → `node_contributor`) and, if a theme type is set, selects the theme: `admin` uses the site's admin theme (gated by the `view the administration theme` permission), a plain theme key (e.g. `default`) uses that system theme, and the special value `_custom` uses a specifically named theme stored under `form_mode.<form_mode_id>`. A route may also override via a `form_mode_theme` route option (which takes priority). All settings live in the config object `form_mode_manager_theme_switcher.settings` (`type.<form_mode_id>` and `form_mode.<form_mode_id>`), edited at `/admin/config/content/form_mode_manager/theme-switcher` (route `form_mode_manager.theme_switcher_settings`, permission `administer site configuration`). It requires the parent Form Mode Manager module and core `field`.

---

- Render a specific form mode's add/edit form in the admin theme while the site uses a front theme.
- Give a "contributor" form mode a simplified custom theme distinct from the default.
- Apply the front-end default theme to a user-facing form mode form.
- Configure a different theme per form mode without writing a theme negotiator.
- Use the admin theme for a back-office form mode, respecting the "view the administration theme" permission.
- Assign a named custom theme to a form mode via the `_custom` type option.
- Keep normal pages on the default theme while only form-mode forms switch themes.
- Provide a branded editing experience for a particular content-entry form mode.
- Override the theme for a single form-mode route with the `form_mode_theme` route option.
- Standardize which theme power-user form modes use across entity types.
- Present a taxonomy or user form mode in a dedicated theme.
- Deploy per-form-mode theme choices as exported configuration.
- Ensure editors see a consistent admin-styled form for complex form modes.
- Differentiate a public "quick submit" form mode visually from the site chrome.
- Test theme variations for a form mode by toggling its `type` setting.
- Limit theme switching strictly to Form Mode Manager routes (it never affects other routes).
- Combine with role-restricted form modes so a role's form renders in a tailored theme.
- Roll out a new admin theme to selected form modes before applying site-wide.
- Give onboarding form modes a friendlier, distraction-free theme.
- Configure fallback to the site theme when no per-mode theme type is set.
