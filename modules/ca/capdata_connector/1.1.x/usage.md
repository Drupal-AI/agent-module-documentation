Maps a site's Drupal content types and taxonomies onto the CapDataCulture ontology and exports the published data as an RDF/XML file for the CapData Opéra open-data platform.

---

CapData connector (capdata_connector) is an open-data publishing module built for the CapData Opéra / France 2030 programme. Through a single admin form (`/admin/config/services/capdata-mapping`) a non-technical editor picks, for each of ~28 CapDataCulture ontology classes (Oeuvre, Personne, Lieu, Production, Evenement, Collectivite, Participation, and their referentials), whether to include it in the export and which Drupal entity — a taxonomy vocabulary or a content type — represents it, then maps each ontology property to a field on that entity (with optional per-field processing such as URL cleaning, HTML stripping or image-style derivation). The mapping is stored in the `capdata_connector.settings` config object. On demand, `CapDataConnectorManager::dataExport()` walks the mapped, published, French-language entities and builds an RDF graph with the `capdataopera/php-sdk` library, serialising it to RDF/XML. The file is generated by the Drush command `capdata-rdf-export` (writing `.well-known/capdata-export.rdf` plus a gzip copy) and served at `/rof/capdata-rdf-export`. Three alter hooks let other modules inject extra graph data. The module provides no entities, no permissions of its own, and no config schema; it reuses core's `administer site configuration` permission to gate the settings form.

---

- Publish an opera house's programming as linked open data in RDF/XML for the CapData Opéra platform.
- Map a "Spectacle/Production" content type to the CapData `Production` class and export it.
- Map an "Événement" content type to the `Evenement` class, exporting event dates and venues.
- Map a "Personne/Artiste" content type to the `Personne` class with names, ARK BnF and ISNI identifiers.
- Map a taxonomy vocabulary (e.g. genres, work types) to referential classes like `GenreOeuvre` or `TypeOeuvre`.
- Map an "Œuvre" content type to the `Oeuvre` class with categories, genres and characters (roles).
- Expose institutional/organisation data via the `Collectivite` class, including the site's own organisation IRI.
- Model participations (authorship, interpretation, partnership, collaboration) between people and productions.
- Attach BnF ARK URIs and ISNI codes to referential terms for authority-record alignment.
- Apply an image style to an exported image/media field so the RDF references a derivative URL.
- Strip HTML tags from a rich-text field before it is exported as a plain literal.
- Clean and validate a URL field value before including it as an RDF resource.
- Export French-language translations of multilingual taxonomy terms and nodes only.
- Generate the export file on a schedule via `drush capdata-rdf-export --uri=https://opera-example.com` from cron.
- Serve the pre-generated RDF file to CapData harvesters at a stable anonymous URL.
- Provide a downloadable RDF/XML attachment (`capdata-export.rdf`) to data consumers.
- Let a custom module enrich the export via `hook_capdata_graph_beginning_alter`, `hook_capdata_graph_item_alter` and `hook_capdata_graph_alter`.
- Add per-property free-text comments in the mapping UI to document local alignment decisions.
- Map production and event date-range fields, choosing the start or end date for a CapData date property.
- Share cultural catalogue data with tourism offices and territorial collectivities without re-keying.
- Give artists a machine-readable record of the works and media they participated in.
- Reuse an existing editorial Drupal site as the source of truth for a semantic-web data feed.
