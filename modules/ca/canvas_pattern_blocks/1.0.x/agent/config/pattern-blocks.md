# Config entity, admin UI, routes & permission

## Install / enable
`ddev drush en canvas_pattern_blocks -y`. Requires the `canvas` module (Composer:
`drupal/canvas ^1.2`). No install hooks, no default config shipped.

## The `canvas_pattern_block` config entity
`src/Entity/CanvasPatternBlock.php` — `final class CanvasPatternBlock extends ConfigEntityBase
implements CanvasPatternBlockInterface`, declared with `#[ConfigEntityType]`:
- `id: 'canvas_pattern_block'`, `config_prefix: 'canvas_pattern_block'`,
  `admin_permission: 'manage canvas pattern blocks'`.
- `entity_keys: {id, label}`. `config_export: [id, label, pattern]`.
- Handlers: `list_builder` = `CanvasPatternBlockListBuilder`; `form` add/edit =
  `CanvasPatternBlockForm`, delete = core `EntityDeleteForm`; `route_provider` html =
  `AdminHtmlRouteProvider`.
- Links: collection `/admin/structure/canvas-pattern-block`, add `/add`,
  edit `/{canvas_pattern_block}`, delete `/{canvas_pattern_block}/delete`.

### Stored properties & methods
- `id` (machine name), `label` (nullable string), `pattern` (nullable string — the Canvas pattern ID).
- `getPatternId(): ?string` returns `pattern` (the interface's only method).
- `calculateDependencies()`: if `pattern` is set and loads, adds a **config dependency** on the
  pattern (`addDependency('config', $pattern->getConfigDependencyName())`) — so deleting the pattern
  cascade-deletes this handle; a placement can never point at a missing pattern.
- `postSave()` / `postDelete()`: call `refreshComponents()` (see plugins doc) to refresh block
  definitions and regenerate Canvas block Components.

## Config schema
`config/schema/canvas_pattern_blocks.schema.yml` — type `config_entity`, `constraints:
FullyValidatable`. Mapping:
- `id`: `machine_name`,
- `label`: `required_label`,
- `pattern`: `string`, constraint `NotBlank` (a handle must reference a pattern).

Example config object (`canvas_pattern_blocks.canvas_pattern_block.<id>.yml`):
```yaml
id: homepage_hero
label: 'Homepage hero'
pattern: hero_default   # a canvas pattern ID
```

## Admin UI & routes
Routes are auto-generated by `AdminHtmlRouteProvider` from the entity `links`, all gated by the
entity's `admin_permission` (`manage canvas pattern blocks`):
- `entity.canvas_pattern_block.collection` → `/admin/structure/canvas-pattern-block`
- `entity.canvas_pattern_block.add_form` → `/admin/structure/canvas-pattern-block/add`
- `entity.canvas_pattern_block.edit_form` → `/admin/structure/canvas-pattern-block/{…}`
- `entity.canvas_pattern_block.delete_form` → `/admin/structure/canvas-pattern-block/{…}/delete`

Menu link (`.links.menu.yml`): "Pattern blocks" under `system.admin_structure`. Action link
(`.links.action.yml`): "Add pattern block" on the collection page.

### The add/edit form
`src/Form/CanvasPatternBlockForm.php` (`extends EntityForm`):
- `label` (textfield, required), `id` (machine_name, `exists` callback, disabled after create),
- `pattern` (select) — options built from **all** `Pattern` entities (`patternStorage()->
  loadMultiple()`, `asort`ed by label), required, with a `- Select a pattern -` empty option; the
  select is hidden (`#access`) when no patterns exist, replaced by an informational item telling the
  user to create a pattern first.
- `save()` adds a status message and redirects to the collection.

### List builder
`src/CanvasPatternBlockListBuilder.php` (`extends ConfigEntityListBuilder`): prepends a help item and
lists columns **Label / Pattern / Machine name** plus the default operations.

## Permission
`canvas_pattern_blocks.permissions.yml` — `manage canvas pattern blocks` ("Manage pattern blocks",
`restrict access: true`). This single permission controls the whole admin UI (create/edit/delete of
the handles). Placing the resulting block on a page is governed separately by Canvas / block-layout
access. There are no custom routes or controllers beyond the entity's admin routes.
