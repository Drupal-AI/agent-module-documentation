Dynamic Local Tasks lets an administrator add local task tabs (primary and secondary) to any existing route through configuration, without writing a custom module.

---

Local tasks (the row of tabs shown at the top of a page, such as *View / Edit / Delete* on a node) are normally declared by a module in a `*.links.task.yml` file. Dynamic Local Tasks moves that capability into the admin UI: it defines a `local_task` config entity whose instances are turned into local task plugin derivatives at runtime by the `DynamicLocalTasks` deriver. Each entity names a target `route_name` (the page the tab links to), an optional set of `route_parameters`, a `weight`, and either a `base_route` (making it a *primary* tab that starts a new tab set on that route) or a `parent_id` (making it a *secondary* tab nested under an existing primary tab). Admins manage the entities at `/admin/structure/menu/dynamic-tasks`; route and base-route fields use an autocomplete backed by the `router` table so you can search by route machine name or path. Everything is gated behind the restricted `administer dynamic local tasks` permission, and the module ships config schema for the entity but no other dependencies, services, or Drush commands. Because a rendered tab still respects the linked route's own access checks, the tool changes navigation only — it does not grant access to pages a user could not already reach. The maintainers note that local tasks should normally live in a module and that this tool is for special cases.

---

- Add a custom tab to a content entity's page (for example a "Statistics" tab on node view) that links to an existing route, without a custom module.
- Surface an admin report route as a tab under an existing admin section by attaching it to that section's base route.
- Add a secondary (sub) tab under a core primary tab such as the user "Edit" tab by setting a `parent_id`.
- Create a primary tab set on a route that currently has no tabs by pointing a `base_route` at it.
- Expose a Views page as a local task tab on a related entity or admin page.
- Give editors quick access to a frequently used route by adding it as a tab on a page they already visit.
- Link a moderation or revision route as a tab on the canonical entity page.
- Prototype navigation/IA changes for tabs quickly in the UI before committing them to a module.
- Add a "Manage" or "Settings" tab to a custom route provided by another contrib module you cannot easily patch.
- Attach a tab to a taxonomy term page by supplying the term route plus a `route_parameters` value.
- Provide a shortcut tab to a config form from an entity collection page.
- Reorder where a dynamic tab sits relative to other tabs using the weight field (delta 50).
- Add a tab that carries fixed route parameters (e.g. `taxonomy_vocabulary=tags`) to a parameterized route.
- Build multi-tab admin dashboards by grouping several dynamic primary/secondary tabs on one base route.
- Add a tab pointing at a module's autogenerated entity route (e.g. an entity collection) onto another page.
- Give site builders a no-code way to add tabs on distribution/profile sites where custom code is discouraged.
- Export the created tabs as configuration (`dynamic_tasks.dynamic_local_task.*`) and deploy them across environments with the config system.
- Temporarily add a diagnostic/utility tab (linking to a status or report route) during a migration or launch, then delete it afterwards.
- Add a tab linking to a search or listing page on a section landing page.
- Restrict who sees the tab implicitly by pointing it at a route whose own access requirements limit the audience.
