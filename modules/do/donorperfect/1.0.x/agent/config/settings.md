# Settings, routes, permissions and the metadata cache

## Install & enable

```bash
composer require drupal/donorperfect
drush en donorperfect donorperfect_donor donorperfect_gift donorperfect_contact donorperfect_other -y
```

Requires contrib `address` (^2.0) and `entity` (^1.0) plus core `datetime` and `options`. You need
a DonorPerfect account with XML API access.

## Permissions (`donorperfect.permissions.yml`)

- **`donorperfect user`** — "Use DonorPerfect integration functionality" (`restrict access: TRUE`).
  Gates the admin landing page, cache refresh and the donor name-search endpoint.
- **`donorperfect admin`** — "Administer DonorPerfect integration" (`restrict access: TRUE`).
  Gates the settings form and is the `admin_permission` of every DonorPerfect entity type.

The submodule entity types also expose per-type view/update permissions generated by the `entity`
module's `EntityPermissionProvider` (see each submodule doc). Views over donor data are not
access-limited by this module — restrict them yourself.

## Routes (`donorperfect.routing.yml`)

| Route | Path | Handler | Permission |
|---|---|---|---|
| `donorperfect.admin` | `/admin/donorperfect` | core `SystemController::systemAdminMenuBlockPage` | `donorperfect user` |
| `donorperfect.admin.settings` | `/admin/donorperfect/settings` | `Form\SettingsForm` | `donorperfect admin` |
| `donorperfect.admin.refresh_cache` | `/admin/donorperfect/refresh-cache/{ajax}` | `DonorPerfectController::refreshCache` | `donorperfect user` |
| `donorperfect.form_element.name.search` | `POST /donorperfect/form_element/name/search` | `DonorPerfectController::searchDonors` | `donorperfect user` |

Menu links (`donorperfect.links.menu.yml`) put "DonorPerfect" under the admin menu and "Settings"
beneath it. `info.yml` `configure:` points to `donorperfect.admin.settings`.

## The settings form (`src/Form/SettingsForm.php`, `donorperfect_settings_form`)

A `ConfigFormBase` editing config object **`donorperfect.settings`**. Fieldsets:

- **DonorPerfect Cache** — a "Refresh DonorPerfect cache" link (rendered as an AJAX button) to the
  `donorperfect.admin.refresh_cache` route.
- **Drupal Entity Settings** — built by `donorperfect.entity.controller_service`
  (`ControllerService::settingsFormBuild()`), which asks each registered entity controller's
  settings form (`EntitySettingsFormBase`) for a per-entity "Entity Fields" checkboxes element.
  The chosen fields are stored under `entity.<entity_type_id>.fields` and determine which
  DonorPerfect columns become Drupal entity base fields.
- **XML API Credentials** — `key` (XML API Key), or `user` + `pw` (username/password). Saved by
  `DPUtility::apiCredentialsSave()` into `donorperfect.settings:api`. Validation
  (`apiCredentialsValidate()`) requires either a key, or a username *and* a password, and clears
  the unused pair.
- **Miscellaneous Settings** — `first_name_variations` textarea (one group per line, comma
  separated); parsed back into a nested array in config.

After submit, `ControllerService::settingsFormPostSubmit()` rebuilds each entity type's base-field
storage definitions so newly selected/removed fields take effect.

## Config objects

- **`donorperfect.settings`** — `api` (`key`/`user`/`pw`), `entity.<type>.fields`,
  `first_name_variations`. Shipped install default (`config/install/donorperfect.settings.yml`)
  contains the large default `first_name_variations` list only.
- **`donorperfect.cache`** — `dptables` (field definitions keyed by table/field), `dpcodes`
  (Code Maintenance codes), `dpmultivalues` (multi-value field map). Written by
  `DPQuery::loadDpTables()/loadDpCodes()/loadDpMultivalues()`.

**No config schema ships** (there is no `config/schema/` directory), so strict config-schema tooling
will flag these objects; the settings still save and work.

## Refreshing the cache (`DonorPerfectController::refreshCache`)

`GET /admin/donorperfect/refresh-cache/{ajax}` (perm `donorperfect user`) calls
`DPQuery::refreshCache()` — several DonorPerfect API calls that rebuild `donorperfect.cache` — then
adds a status message and redirects to the destination (AJAX `RedirectCommand` when `{ajax}` is
`ajax`, otherwise a `RedirectResponse`). Run this after credentials are saved and whenever fields or
codes change in DonorPerfect.

## Entity access (`src/Entity/AccessControlHandler.php`)

Extends the `entity` module's `EntityAccessControlHandler`. It hard-denies the `delete` operation
for all DonorPerfect entities (`AccessResult::forbidden()`); other operations defer to the parent
(entity permission provider + `donorperfect admin`).
