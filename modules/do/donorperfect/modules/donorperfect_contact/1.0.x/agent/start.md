# DonorPerfect Contact (donorperfect_contact) — agent index

Submodule of **donorperfect**. Defines the `donorperfect_contact` content entity (DonorPerfect
contact/activity record). Package `DonorPerfect`. Core `^10 || ^11`, PHP `^8.0`. GPL-2.0-or-later.
Version 1.0.x (installed 1.0.20). Depends on `donorperfect:donorperfect` only.

- **The entity, its tables/fields, controller and settings form** →
  [entity/contact.md](entity/contact.md)

## What it provides (from source)

- **Entity** `donorperfect_contact` (`src/Entity/Contact.php`, `@ContentEntityType`): base table
  `dpcontact`, `udf_table` `dpcontactudf`, id key `contact_id`, label key `contact_id`.
  `admin_permission = donorperfect admin`. Handlers: base `Storage`, `StorageSchema`,
  `AccessControlHandler`, `ViewsData`; `entity` `EntityPermissionProvider`; own `ContactViewBuilder`;
  add/edit form `ContactForm`. Routes under `/admin/donorperfect/contact`.
- **Extra field**: `Contact::baseFieldDefinitions()` adds a `donor_id` entity_reference to
  `donorperfect_donor` **only if** the `donorperfect_donor` module is enabled. Other base fields are
  generated by the base `EntityBase` from the selected `dpcontact`/`dpcontactudf` cached fields.
- **Service** `donorperfect_contact.entity_controller` → `Entity\ContactController` (extends base
  `ControllerBase`), tagged `donorperfect.entity_controller` **priority 980**;
  `ENTITY_TYPE_ID = donorperfect_contact`; `getSettingsFormClass()` → `Form\SettingsForm`.
- **Settings form** `Form\SettingsForm` extends base `EntitySettingsFormBase`
  (`ENTITY_TYPE_ID = donorperfect_contact`) — contributes the contact "Entity Fields" checkboxes to
  the base settings form.
- **View builder** `Entity\ContactViewBuilder` clears default `content` (render via Views/fields).

Records live in DonorPerfect and are read/written via the base `DPQuery` client. Delete is forbidden
by the base access handler. No routing.yml/permissions.yml/config schema/Drush of its own (entity
permissions come from `EntityPermissionProvider`).
