REST Export Nested adds a Views display, "REST export nested", that behaves like core's REST Export but automatically decodes any field whose value is a JSON string into real nested JSON in the output — ideal for embedding a sub-view's rows inside a parent feed.

---

The module provides a single Views display plugin (`rest_export_nested`, extending core's
`RestExport`) whose `render()` first renders the view through its serializer style as usual,
then walks every row and, for each string field value, tries `json_decode()` (and an
HTML-entity-decoded variant) — if it parses, the string is replaced by the decoded structure so
the emitted JSON contains genuine nested objects/arrays instead of an escaped JSON string. It
also normalises the literal string `"null"` to real `null`. This is the missing piece when you
combine it with **Views Field View**: you build a child "REST export" (or "REST export nested")
display that outputs referenced content as JSON, add it to a parent "REST export nested"
display via a Views Field View field passing a contextual argument (e.g. the host entity id),
and the parent feed then embeds each row's children as nested JSON rather than a quoted blob.
The display is configured entirely through the Views UI (it adds an `auth` option for
authentication providers, like core REST Export); there is no settings page. It requires the
core `rest` and `views` modules. Because it operates on any field that renders a bare JSON
string, it also works with JSON stored in a field or generated by other means (set the field's
output to "Raw" if needed).

---

- Emit a Views REST feed where a "children" column is real nested JSON, not an escaped string.
- Embed a sub-view's rows inside a parent entity's JSON feed via Views Field View.
- Build a decoupled endpoint returning parent items each with an array of related items.
- Return an article feed where each article includes its comments as nested JSON.
- Expose a product feed with each product's variations nested inline.
- Include a node's referenced media/paragraphs as structured JSON in one request.
- Avoid the client having to double-parse an escaped JSON string field.
- Decode a field that stores JSON (e.g. a computed/plugin field) into structured output.
- Normalise the string "null" to a real null value in the JSON response.
- Serve a menu/tree structure as nested JSON from Views.
- Provide a single aggregated JSON payload for a front-end instead of multiple calls.
- Wrap a "REST export" child display's output as nested data in a parent feed.
- Keep authentication (basic_auth, cookie, etc.) like core REST Export via the auth option.
- Return taxonomy terms with their child terms nested inside each parent term.
- Feed a JavaScript app hierarchical data with one HTTP request.
- Combine multiple related content types into one nested JSON document.
- Output an order with its line items nested as JSON objects.
- Expose an event with its sessions nested for a decoupled calendar UI.
- Turn a flat Views result containing JSON-string columns into a proper JSON tree.
- Use as a drop-in replacement for a REST Export display when fields carry JSON.
- Support HTML-entity-encoded JSON field output by decoding entities before parsing.
