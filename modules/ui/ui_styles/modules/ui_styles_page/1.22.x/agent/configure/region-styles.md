# Style a theme's regions

Enable with `drush en ui_styles_page` (needs `ui_styles`).

## Routes / access

`ui_styles_page.routing.yml`:

- `ui_styles_page.regions.overview` → `/admin/appearance/regions-styles`
  (a system admin-menu block page; this is the module's `configure` route), `administer themes`.
- `ui_styles_page.regions.theme_settings` → `/admin/appearance/regions-styles/{theme}`,
  form `RegionsThemeSettingsForm`, title from `theme_handler:getName`, `administer themes`.

A per-theme menu link is generated by the deriver
`Drupal\ui_styles_page\Plugin\Derivative\RegionStyles` (`links.menu.yml`), under the overview.

## The form

`RegionsThemeSettingsForm` (extends `ConfigFormBase`, form id
`ui_styles_page.regions.theme_settings`) lists the theme's regions
(`listAllRegions()` / `system_region_list()`), rendering a `ui_styles_styles` element per
region under the `#tree` root key `ui_styles_page_regions`, scoped to the theme
(`#drupal_theme`). If the theme has no available styles it shows a warning and no fields.

## Storage

Constant `UiStylesPageInterface::REGION_STYLES_KEY_THEME_SETTINGS` =
`third_party_settings.ui_styles_page.regions`:

```
<theme>.settings:
  third_party_settings:
    ui_styles_page:
      regions:
        header:  { selected: { background: bg-dark }, extra: 'py-3' }
        content: { selected: {...}, extra: '' }
```

Schema `theme_settings.third_party.ui_styles_page` (a `regions` sequence of
`ui_styles.selected_mapping`). `submitForm()` filters empties; if nothing remains it clears the
`regions` key (and the now-empty `third_party_settings.ui_styles_page` /
`third_party_settings`).

## Render

`PreprocessRegion::preprocess()` (a `template_preprocess_region` handler) reads the theme
setting for the current `$variables['region']`, merges `selected` + space-split `extra` onto
`$variables['attributes']` via `AttributeHelper::mergeCollections`. Note: a region whose Twig
template does not print `attributes` will not show the classes.
