Submodule of Message Digest that gives users the human-facing side of the base (API-only) module: a per-subscription and per-user "notification interval" preference that, at send time, routes their message notifications through the chosen digest notifier (daily / weekly / custom) or leaves them immediate.

---

Message Digest UI ships a `message_digest` `list_string` field on the Message Subscribe Email flaggings (`email_node` / `email_term` / `email_user`) and on the `user` entity, and adds an `options_select` widget for it to those form displays on install (see `config/optional` and `hook_install`). The option list is generated by the parent module's `message_digest_allowed_values_callback` — `'0'` for "Send immediately" plus one entry per digest notifier plugin id (e.g. `message_digest:daily`, `message_digest:weekly`). The stored value is the notifier plugin id to deliver with. It also derives an Action plugin, `message_digest_interval` (one derivative per flag × interval, deriver `DigestIntervalActionDeriver`), whose `execute()` flags the current user's entity if needed and writes the interval onto that flagging, with `access()` deferring to the flag's `actionAccess('flag', …)`; nine matching `system.action.*` entities ship in `config/optional`. At notify time it implements `hook_message_subscribe_get_subscribers_alter()`: it loads each subscriber's own relevant flagging, reads the `message_digest` value, and — for a non-`'0'` value — replaces that delivery candidate's notifiers with the chosen digest notifier; `'0'`/null keeps immediate delivery. `hook_module_implements_alter()` ensures this runs after `message_subscribe_email`. Requires `message_digest`, `message_subscribe_email`, and core `options`. It has no settings page, no permissions of its own, and no drush commands.

---

- Let each user choose daily / weekly / immediate for their email notifications.
- Store a per-subscription (per-flagging) digest frequency preference.
- Store a per-user default digest frequency via the user `message_digest` field.
- Seed a new flagging's interval from the user's global preference (default-value callback).
- Switch a user's notifications to a digest notifier automatically at send time.
- Keep immediate delivery for subscriptions the user set to "Send immediately".
- Offer per-entity bulk actions to change a subscription's digest interval.
- Apply an interval action from Views Bulk Operations over flagged content.
- Integrate digest preferences with Flag + Message Subscribe Email.
- Present available intervals (derived from the digest notifier plugins) as select options.
- Automatically expose any new custom digest interval as a new option and action.
- Respect flag access when exposing or running interval-change actions.
- Create the flagging on demand when a user sets an interval on an unflagged entity.
- Provide the human-facing side of Message Digest (the base module is API-only).
- Let node / term / user subscriptions each carry their own digest frequency.
- Override all of a delivery candidate's notifiers with the chosen digest notifier.
- Combine with message_subscribe so subscribers control their own digest cadence.
- Add a notification-interval field to the user account edit form.
- Migrate legacy action plugin ids from `.` to `:` separators on update (post_update).
- Ship optional field/action config that can be adapted to custom email flags.
