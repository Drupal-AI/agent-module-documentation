A pluggable framework for handling site memberships, built on Entity API, State Machine and Commerce.

---

Defines a revisionable `membership` content entity (`src/Entity/Membership.php`) with `MembershipType` config bundles (`src/Entity/MembershipType.php`), each bound to a **membership provider** plugin (`@MembershipProvider` annotation; manager `plugin.manager.membership_provider`). Provider plugins declare capabilities via interfaces - `SupportsCreationMembershipProviderInterface`, `SupportsCancellationMembershipProviderInterface`, `ConfigurableMembershipProviderBase` - and the bundled `ManualOnsite` provider implements simple on-site memberships. Access uses `MembershipAccessControlHandler` extending the Entity API `UncacheableEntityAccessControlHandler`: `createAccess()` first checks the type's provider actually supports creation (else `AccessResult::forbidden`) then delegates to the Entity-API permission provider (per-bundle CRUD permissions generated by the `entity` module). `MembershipEntityController::addPage()` filters add-links by create access and can redirect to a provider's off-site creation page. A `MembershipRepository` service, `state_machine`-driven status field, custom `MembershipStorage`, list builders and admin route provider round it out. Commerce is a hard dependency (memberships tie to store/order/customer flows); the module itself does not process payments - it delegates to Commerce. No routes/permissions of its own beyond the Entity-API-generated ones; `membership_type.schema.yml` provides type config schema.

---

- Model paid or manual site memberships as first-class content entities.
- Define multiple membership types, each backed by a different provider plugin.
- Add a custom membership provider (e.g. remote SaaS) by implementing the provider interfaces.
- Support on-site membership creation with the bundled `ManualOnsite` provider.
- Redirect users to an off-site provider's signup page when the provider requires it.
- Track membership status transitions via State Machine (active/expired/cancelled etc.).
- Keep a revision history of each membership.
- Gate membership creation on whether the provider supports it (not just permissions).
- Integrate memberships with Commerce orders/customers.
- Generate per-type CRUD permissions through the Entity API.
- Expose memberships to Views via `MembershipEntityViewsData`.
- Provide an admin add-page that lists only creatable membership types.
- Build subscription-style access using provider plugins plus Commerce.
- Use the `MembershipRepository` service to look up a user's memberships in code.
- Declare provider capabilities through marker interfaces for clean feature detection.
- Extend membership types with configurable provider settings.
