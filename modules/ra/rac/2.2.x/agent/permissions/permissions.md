# Permissions

RAC's permissions are **generated at runtime**, one set per user role, via `permission_callbacks`.
There is no fixed list in `rac.permissions.yml` except the callback registration.

## rac (top-level module)

`rac.permissions.yml`:

```yaml
permission_callbacks:
  - \Drupal\rac\AccessPermissions::permissions
```

`AccessPermissions::permissions()` loops ops `['view', 'update']` × every `user_role` and emits:

| Permission machine name | Title | `restrict access` |
| --- | --- | --- |
| `RAC_view_<role_id>` | "view Content for Role <label>" | TRUE |
| `RAC_update_<role_id>` | "update Content for Role <label>" | TRUE |

Both are **hidden from the standard permissions page**: `rac_form_user_admin_permissions_alter()`
unsets `RAC_view_*` and `RAC_update_*` from `user_admin_permissions`. They are granted programmatically
instead:
- `rac_install()` grants `RAC_view_<role_id>` to **every** role at install.
- `_rac_form_user_role_form_submit()` grants `RAC_view_<role_id>` to a role when that role is saved.
- `rac_user_role_delete()` revokes `RAC_update_<deleted_role_id>` from all roles when a role is deleted.

`RAC_update_<role_id>` is consumed by `_rac_get_account_roles('update', $account)`, which the
`rac_relations` provider calls to decide which roles' content a user may update.

## rac_relations (submodule)

`rac_relations.permissions.yml` defines one static permission plus a callback:

| Permission machine name | Title | `restrict access` |
| --- | --- | --- |
| `administer rac_relations` | "Manage Role Access Control Relations" | TRUE |
| `RAC update <role_id>` (space-separated) | "Update content for role <label>" | TRUE |

`administer rac_relations` gates the `rac_relations.settings` form route. The per-role
`RAC update <role_id>` permissions (note: **spaces**, not underscores) are generated by
`RoleAccessControlRelationPermissions::permissions()` and are what the relations grid form
grants/revokes.

> Naming caveat for integrators: the relations grid grants the **space-separated** `RAC update <id>`,
> while the `rac_relations` provider reads the **underscore** `RAC_update_<id>` (via
> `_rac_get_account_roles`). They are distinct permission strings.

Grant/revoke from code by role id:

```php
$role = \Drupal\user\Entity\Role::load('editor');
$role->grantPermission('RAC_update_content_role_id'); // e.g. RAC_update_member
$role->save();
```
