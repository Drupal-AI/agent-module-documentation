# FlowDrop entity types

FlowDrop's data model spans several submodules. Config entities carry the *definition* (what a
workflow is, its node types); content entities carry the *execution record* (what happened when a
workflow ran). Each entity type declares its own permissions and access-control handler.

## Config entities (definition / configuration)

| Entity type | Provided by | Purpose |
|---|---|---|
| `flowdrop_workflow` | flowdrop_workflow | The workflow graph: nodes + typed-port edges. Exportable to YAML; the unit of authorship. Access: `view/create/edit/delete/administer flowdrop_workflow` (create/edit/delete/administer are **restrict access** — authorship = broad site access). |
| `flowdrop_node_type` | flowdrop_node_type | A configured node variant available in the editor palette; binds a `FlowDropNodeProcessor` plugin to preset config. `administer flowdrop_node_type`. |
| `flowdrop_node_category` | flowdrop_node_category | Groups node types into palette sections. |
| `port_shape` (PortShape) | flowdrop_node_type | Named JSON Schemas a port may carry; decides which ports may be wired together (edge legality). `administer flowdrop_port_shape` (**restrict**). |
| `flowdrop_job_type` | flowdrop_job | Bundle for job entities. `administer flowdrop_job types` (**restrict**). |
| `flowdrop_pipeline_type` | flowdrop_pipeline | Bundle for pipeline entities. `administer flowdrop_pipeline types` (**restrict**). |
| `flowdrop_trigger_config` | flowdrop_trigger | An event→workflow binding (entity/user/form/cron/external). `administer flowdrop triggers` (**restrict**), `view flowdrop triggers`. |
| `flowdrop_trusted_publisher` | flowdrop (base) | An Ed25519 publisher key trusted to supply importable signed bundles. `administer flowdrop trusted publishers` (**restrict**). |

## Content entities (execution record / state)

| Entity type | Provided by | Purpose |
|---|---|---|
| `flowdrop_pipeline` | flowdrop_pipeline | One workflow run: overall status, input_data, grouping of its jobs. `view own/any flowdrop_pipeline`. |
| `flowdrop_job` | flowdrop_job | One node execution within a pipeline: status, input, output, timing, errors. `view/edit/delete/create ... flowdrop_job` (own/any). |
| `flowdrop_session` | flowdrop_session | An interactive/conversational workflow session (turns of messages). `view/create/edit/delete own|any flowdrop_session`, `execute session workflow`. |
| `flowdrop_session_message` | flowdrop_session | A single message in a session. `view own/any flowdrop_session_message`. |
| `flowdrop_interrupt` | flowdrop_interrupt | A pending human-in-the-loop request (confirm/choice/text/form). See its rich permission set (view/resolve/cancel own|any, plus a callback permission). Storage schema class present. |
| `memory_record` (MemoryRecord) | flowdrop_memory | Entity-backed scoped memory value (one of several swappable backends). |
| `state_checkpoint` (FlowDropStateCheckpoint) | flowdrop_stategraph | A saved StateGraph checkpoint for resumable execution. `create/view/edit/delete own|any state_checkpoint`, `manage approval gates`. |
| `flowdrop_workflow_snapshot` | flowdrop_runtime | A captured snapshot of an execution/workflow state; entity-access gated so "view own" holders see only their own. `view/delete own|any flowdrop_workflow_snapshot`, `administer flowdrop_workflow_snapshot`. |

## Notes for agents

- The **workflow** (config) vs **pipeline/job** (content) split is the key mental model: editing a
  workflow changes *what will run*; a pipeline is *a run that happened* and is immutable history.
- Most collection/CRUD routes are generated by `AdminHtmlRouteProvider` from entity link
  templates; only API and custom routes appear in each submodule's `*.routing.yml`.
- Access is enforced per entity type by dedicated `*AccessControlHandler` classes; several API
  routes add a `_custom_access` callback on top of an OR-set of `_permission`s so ownership is
  checked per entity (see api/rest-api.md).
