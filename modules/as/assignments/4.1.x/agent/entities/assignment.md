# The `assignment` content entity

Source: `src/Entity/Assignment.php`, `src/Entity/AssignmentInterface.php`,
`src/AssignmentStorage.php`, `src/AssignmentAccessControlHandler.php`,
`src/AssignmentListBuilder.php`, `src/AssignmentHtmlRouteProvider.php`,
`src/Entity/AssignmentViewsData.php`, `src/Form/Assignment*Form.php`, `assignments.module`,
`templates/*.twig`.

## Install / enable

`ddev drush en assignments -y`. No config to import, no dependencies to add beyond core
(`user`; `views` is used by the Views-data handler). After enabling, create at least one bundle
under **Structure → Assignment type** (`/admin/structure/assignment_type`) before adding
assignments (see [../config/types-and-permissions.md](../config/types-and-permissions.md)).

## Definition

`@ContentEntityType(id = "assignment")` — a fieldable content entity.

- `base_table = "assignment"`, `admin_permission = "administer assignment entities"`.
- `bundle_entity_type = "assignment_type"`, `field_ui_base_route =
  "entity.assignment_type.edit_form"` (so Field UI's Manage fields/display live on the bundle).
- entity_keys: `id`, `bundle = type`, `label = name`, `uuid`, `uid = user_id`, `langcode`,
  `status`.
- links: canonical `/admin/content/assignment/{assignment}`, add-page
  `/admin/content/assignment/add`, add-form `/admin/content/assignment/add/{assignment_type}`,
  edit `.../{assignment}/edit`, delete `.../{assignment}/delete`, collection
  `/admin/content/assignment`.

Routes are generated by `AssignmentHtmlRouteProvider` (extends core `AdminHtmlRouteProvider`, so
pages are admin-themed). There is **no `assignments.routing.yml`**. Menu/local-task/local-action
links come from `assignments.links.menu.yml`, `.links.task.yml`, `.links.action.yml`.

## Base fields (`Assignment::baseFieldDefinitions`)

| Field | Type | Notes |
|-------|------|-------|
| `user_id` | entity_reference → user | "Authored by"; revisionable+translatable; autocomplete widget. Defaults to current user in `preCreate()`. |
| `name` | string | **Label "Channel"**, `max_length = 50`, `text_processing = 0`, **required**; used as the entity label. |
| `created` | created | Creation timestamp. |
| `changed` | changed | Last-changed timestamp (via `EntityChangedTrait`). |

Getters/setters: `getName`/`setName`, `getCreatedTime`/`setCreatedTime`, owner methods from
`EntityOwnerInterface`. `getMatches()`/`alterMatches()` are stubs returning `[]`/the input.

## Access control (`AssignmentAccessControlHandler::checkAccess`)

Standard per-operation permission checks:

- `view` → `view published assignment entities`; when `!$entity->isPublished()` →
  `view unpublished assignment entities`.
- `update` → `edit assignment entities`.
- `delete` → `delete assignment entities`.
- create (`checkCreateAccess`) → `add assignment entities`.
- Unknown operations return `AccessResult::neutral()`.

**Quirk:** `Assignment::isPublished()` always returns `TRUE` and `setPublished()` is a no-op, so
the `status` key never becomes unpublished in practice — the `view unpublished` branch is
effectively unreachable through normal editing, and every record is treated as published (viewable
by holders of `view published assignment entities`).

## Storage & Views

- `AssignmentStorage` is an empty subclass of `SqlContentEntityStorage` (no custom behaviour).
- `AssignmentViewsData` extends core `EntityViewsData` and adds nothing, so assignments get
  default Views integration (base table `assignment`).
- `AssignmentListBuilder` renders the collection with `Assignment ID` + `Name` columns, the name
  linking to `entity.assignment.edit_form`.

## Forms

- `AssignmentForm` (add/edit, extends `ContentEntityForm`): injects `request_stack` +
  `entity_type.manager`. In `buildForm()` it reads `?node=<nid>`, loads that node, and sets it as
  the default of `$form['node']['widget'][0]['target_id']` (disabled). In `save()` it messages
  "Created/Saved the assignment." and **redirects to `entity.assignment.add_page` with
  `node => $form_state->getValue('node')[0]['target_id']`**.
  **Caveat:** this module defines **no `node` base field**, so on a plain install `$form['node']`
  is undefined — the node plumbing and redirect only make sense once an extension (or a manually
  added `node` reference field) provides it. Treat the node integration as extension-facing.
- `AssignmentDeleteForm` (extends `ContentEntityConfirmFormBase`): standard confirm-form delete,
  cancel → collection. Deletion is a POST confirm form (CSRF-protected by core).
- `AssignmentSettingsForm` (`FormBase`): renders only static markup and has an empty submit. Its
  route (`entity.assignment.settings`) is generated by
  `AssignmentHtmlRouteProvider::getSettingsFormRoute()` **only when the entity has no bundle entity
  type** — `assignment` *has* one (`assignment_type`), so the route is **never registered** and the
  form is dead code. `data.json` `configure` is therefore null.

## Theming (`assignments.module`)

- `hook_theme` registers `assignment` (template `assignment.html.twig`, preprocess
  `template_preprocess_assignment` in `assignment.page.inc`) and `assignment_content_add_list`.
- `hook_theme_suggestions_assignment` adds per-view-mode / per-bundle / per-id suggestions.
- `hook_preprocess_entity_add_list` rewrites each bundle's add-link to
  `entity.assignment.add_page/<bundle>?node=<nid>` so the current `?node` context is carried into
  creation.
- The default `assignment.html.twig` is a scaffold stub (prints `content.name`,
  `getName()`, `getMatches()`, and iterates the elements). All dynamic values go through Twig's
  default autoescaping — the `name`/"Channel" string is plain text (`text_processing = 0`) and is
  escaped on output.

## Operating notes

- Manage the schema (add fields, view modes) on the **bundle** via Field UI, not on the entity
  type directly.
- Everything lives under `/admin/...`; there is no front-end/public route for assignments.
