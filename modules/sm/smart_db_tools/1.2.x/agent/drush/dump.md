# Running the Smart DB Tools dump

Smart DB Tools is invoked through its own CLI bootstrap script, not Drush. It extends core's
`db-tools.php` application and is fully backward-compatible with the core `dump` command; the only
addition is per-table splitting.

## Basic split dump
```
php modules/contrib/smart_db_tools/scripts/smart-db-tools.php dump \
  --database fixture_connection \
  --subsplit-limit 5000 \
  --split-destination modules/custom/db-dump.php
```
This writes `db-dump.php` plus a `db-dump/` directory containing one `<table>.php` per table
(each `include`d from the main file). Tables exceeding `--subsplit-limit` rows are further split
into `<table>/<table>_<page>.php` sub-files.

## Options
- `--split-destination PATH` — enable per-table split output at PATH (omit for core single-file dump).
- `--subsplit-limit N` — max rows per file (default 1000; `<1` disables sub-splitting). N=1000 pairs
  well with PHP `memory_limit=256M`.
- `--schema-only PATTERN` — dump only the schema (no data) for matching tables.
- `--no-generator-comment` — drop the "generated by db-tools" comment.
- `--file-comment "TEXT"` — set a custom wrapped file comment.
- `--database`, `--insert-count` — inherited from core's dump command.

## Notes
Runs only under CLI (the bootstrap returns immediately otherwise). The generated scripts use
`$connection->insert(...)` / create-table statements identical in shape to core's output, so they
import the same way as a standard core fixture.
