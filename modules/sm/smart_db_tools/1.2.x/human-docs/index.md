# Smart DB Tools — manual setup guide

**Smart DB Tools** (`smart_db_tools`) is an enhanced version of Drupal core's
command-line `db-tools.php` application. Core's tool exports an entire database to
a single PHP fixture script; Smart DB Tools adds a `--split-destination` option
that instead writes **one PHP script per table**, wired together with `include`
statements. To keep memory use bounded, tables larger than a configurable row
threshold are split further into paged sub-files.

The problem it solves is a developer/testing one. When you keep database fixtures
in version control (for kernel and functional tests, for example), a single-file
export produces enormous, noisy diffs — change a couple of tables and the whole
dump churns. Splitting the export per table means each table's data sits in its
own file, so the diff shows only what actually changed and fixtures stay
reviewable.

This is a **command-line tool for developers**, not a web feature. Enabling the
module adds no routes, permissions, services, forms, or configuration pages — its
entire surface is the `scripts/smart-db-tools.php` script, which bootstraps Drupal
and deliberately refuses to run under anything but the CLI SAPI. There is no
web-facing attack surface: the dump reads tables using names taken from Drupal's
own schema (never from request input) and pages results with integer limits, so
there is no request-driven SQL injection vector. It has no dependencies beyond
Drupal core and runs on Drupal 10, 11, and 12.

This guide is written for a **human** running the tool from a shell. If you want
terse, token-cheap references for an AI coding agent, read the sibling
[`agent/`](../agent/start.md) docs instead.

## How to use it

Run the bundled script from your site root. A typical split dump looks like:

```bash
php modules/contrib/smart_db_tools/scripts/smart-db-tools.php dump \
  --database fixture_connection \
  --subsplit-limit 5000 \
  --split-destination modules/custom/db-dump.php
```

This writes `db-dump.php` plus a `db-dump/` directory containing one
`<table>.php` file per table (each `include`d from the main file). Tables with
more rows than `--subsplit-limit` are split further into
`<table>/<table>_<page>.php` sub-files.

Useful options:

- `--split-destination PATH` — turn on per-table split output at `PATH`. Omit it
  and you get core's normal single-file dump — the tool is fully
  backward-compatible with core's `dump` command.
- `--subsplit-limit N` — maximum rows per file (default **1000**; a value below 1
  disables sub-splitting entirely). `--subsplit-limit 1000` pairs well with a PHP
  `memory_limit` of 256M.
- `--schema-only PATTERN` — dump only the schema (no data) for matching tables.
- `--no-generator-comment` — drop the "generated by db-tools" comment.
- `--file-comment "TEXT"` — set a custom wrapped file comment.
- `--database`, `--insert-count` — inherited unchanged from core's dump command.

The generated scripts use the same insert/create-table shape as core's output, so
they import exactly like a standard core fixture.
