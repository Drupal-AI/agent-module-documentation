# Admin, permission & global Segment Sets

Smart Content has **no dedicated settings form** (`configure` is null). "Configuration" means two
things: the admin section that lists reusable global Segment Sets, and the per-placement decision
authored on a Decision Block ([../blocks/decision-block.md](../blocks/decision-block.md)).

## Permission & admin routes

Single permission `administer smart content` (`smart_content.permissions.yml`), used as the
`admin_permission` on both config entities.

| Route | Path | Purpose |
|---|---|---|
| `system.admin_structure_smart_content` | `/admin/structure/smart-content` | Admin section landing (core `systemAdminMenuBlockPage`). Requires `administer smart content`. |
| `entity.smart_content_segment_set.collection` | `/admin/structure/smart_content_segment_set` | List global Segment Sets. |
| `entity.smart_content_segment_set.add_form` | `/admin/structure/smart_content_segment_set/add` | "Add Global Segment Set". |
| `entity.smart_content_segment_set.edit_form` | `…/{id}/edit` | Edit. |
| `entity.smart_content_segment_set.delete_form` | `…/{id}/delete` | Delete. |
| `entity.smart_content_segment_set.canonical` | `…/{id}` | View. |

These entity routes are generated by `SegmentSetConfigHtmlRouteProvider` (extends core
`AdminHtmlRouteProvider`), so they all inherit the `administer smart content` admin permission — i.e.
authoring/editing segment sets is admin-only. Menu link `smart_content.overview` (+ action link
"Add Global Segment Set") wire these into the admin toolbar (`*.links.menu.yml` / `*.links.action.yml`).

## The `smart_content_segment_set` config entity

`Entity\SegmentSetConfig` stores a reusable Segment Set. Keys: `id`, `label`, `uuid`, `settings`
(exported). On construct it hydrates a `SegmentSet` from `settings` (`SegmentSet::fromArray()`); on
`save()` it writes `getSegmentSet()->toArray()` back to `settings` and clears the
segment-set-storage manager's cached definitions (the `GlobalSegmentSetDeriver` exposes one
`global_segment_set:<id>` storage plugin per entity). Forms:
`Form\SegmentSetConfigEntityForm` (add/edit), `Form\SegmentSetConfigEntityDeleteForm`; list builder
`SegmentSetConfigListBuilder`.

## Config schema

`config/schema/`:
- `smart_content.smart_content.segment_set.*` (`smart_content.schema.yml`): `id`, `label`,
  `settings.segments` → sequence of `smart_content.segment`.
- `smart_content.segment` (`smart_content.segment.yml`): `uuid`, `weight`, `label`, `default`,
  `conditions` → sequence of `smart_content.condition.plugin.[type]`.
- `smart_content.condition` + per-type variants (`smart_content.condition.schema.yml`): base keys
  `id`, `weight`, `negate`, `type`; the `plugin:group` variant adds `op` + nested `conditions`; each
  `type:<id>` variant defines its `condition_type_settings` (e.g. `op`/`value`/`key`).

## Create a global Segment Set in PHP

```php
use Drupal\smart_content\Entity\SegmentSetConfig;
use Drupal\smart_content\Segment;
use Drupal\smart_content\SegmentSet;

// Build a segment whose single 'group' condition wraps a browser/textfield condition, etc.
$condition = \Drupal::service('plugin.manager.smart_content.condition')
  ->createInstance('group');          // then append child conditions to the group
$segment = new Segment(NULL, [$condition->getConfiguration()], 0, 'Mobile users');

$set = new SegmentSet([$segment]);

$entity = SegmentSetConfig::create([
  'id' => 'mobile_users',
  'label' => 'Mobile users',
  'settings' => $set->toArray(),
]);
$entity->save();   // now selectable as a global segment set on any Decision Block
```

Because conditions are plugin configuration, the reliable way to author them is through the Decision
Block UI or by copying a known-good `settings` array; the snippet shows the entity/value-object
plumbing (`Segment`/`SegmentSet::toArray()`).
