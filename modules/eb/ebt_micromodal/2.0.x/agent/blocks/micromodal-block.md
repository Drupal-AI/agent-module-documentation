# EBT Micromodal block type

Everything the module ships to produce a button-opens-modal block. Grounded in the on-disk source of
`ebt_micromodal` 2.0.0.

## Install / enable

- `drush en ebt_micromodal -y`. `ebt_micromodal.info.yml` declares `dependencies: [ebt_core:ebt_core]`,
  so `ebt_core` is required (which in turn brings the `ebt_settings` field type/storage, media/design
  infrastructure — see the EBT Core README: Media Image type expected).
- `composer.json` requires `drupal/ebt_core:^2.0` and `levmyshkin/micromodal:^1.0`. The latter is the
  Micromodal.js front-end library; `ebt_micromodal.libraries.yml` references it at
  **`/libraries/micromodal/dist/micromodal.min.js`**, so the library must be present in the web root's
  `libraries/` directory (Composer + a merge/installer-paths setup, or manual download). Missing library
  = the button renders but no modal opens.
- No install-time settings form; `configure` is null.

## What install creates (config/install/)

- `block_content.type.ebt_micromodal` — the bundle (label "EBT Micromodal").
- `field.storage.block_content.field_ebt_micromodal_title` — `text_long`, cardinality 1, translatable.
- `field.field.block_content.ebt_micromodal.field_ebt_micromodal_title` — label "Micromodal Title".
- `field.field.block_content.ebt_micromodal.body` — reuses core `block_content` `body`
  storage (`text_with_summary`), summary disabled.
- `field.field.block_content.ebt_micromodal.field_ebt_settings` — attaches the shared `ebt_settings`
  field (module dep `ebt_core`); its `default_value` seeds the standard EBT design options
  (margin/border/padding box, border color/style/radius, background color/media/image style,
  edge_to_edge, container_width).
- `core.entity_form_display.…default` — organises fields with **field_group** into a Tabs group
  (`Content` tab = title + body; `Settings` tab = `field_ebt_settings`). `field_ebt_settings` uses
  widget **`ebt_settings_micromodal`**. (Requires `field_group`; it is a form-display third-party
  setting, not an info.yml dependency.)
- `core.entity_view_display.…default` — body (weight 1), title (weight 0), `field_ebt_settings`
  rendered with `ebt_settings_default` formatter (weight 2), all labels hidden.

## The settings widget

`src/Plugin/Field/FieldWidget/EbtSettingsMicromodalWidget.php`, id **`ebt_settings_micromodal`**,
`field_types = { ebt_settings }`, extends `ebt_core\...\EbtSettingsDefaultWidget`. `formElement()`
calls the parent (design options) then adds under `ebt_settings`:

| Key | Type | Default | Notes |
|-----|------|---------|-------|
| `pass_options_to_javascript` | hidden | TRUE | tells EBT Core to expose settings via `drupalSettings` |
| `button_text` | textfield | `Open` | trigger-button label |
| `close_button_text` | textfield | `Close` | **required**; footer close-button label |
| `disable_scroll` | checkbox | NULL | locks page scroll while modal open |
| `display_close_icon` | checkbox | TRUE | show the header "X" button |

`massageFormValues()` just ensures each delta has an `ebt_settings` key. All four are stored inside the
`field_ebt_settings` value; there is no separate config object and no config schema in this module
(schema for `ebt_settings` is defined by `ebt_core`).

## Rendering (templates + JS)

Two overrides, near-identical: `templates/block--block-content--ebt-micromodal.html.twig` (standalone
custom blocks) and `templates/block--inline-block--ebt-micromodal.html.twig` (Layout Builder inline
blocks; adds the `ebt-micromodal-block` class the JS selects on). Both:

- `{{ attach_library('ebt_micromodal/ebt_micromodal') }}`.
- Print block label as `<h2>`, then `content|without('field_ebt_settings','body','field_ebt_micromodal_title')`.
- Render a trigger `<a data-micromodal-trigger="modal-micromodal-block-revision-id-{revision_id}" href="javascript:;">`
  whose text is `content.field_ebt_settings.0['#ebt_settings']['button_text']`.
- Render `<div class="modal micromodal-slide" id="modal-micromodal-block-revision-id-{revision_id}">`
  containing the header title (`content.field_ebt_micromodal_title`), the body (`content.body`), and a
  footer close button labelled `close_button_text`. The header "X" (`button.modal__close`) prints only
  when `display_close_icon == 1` or the setting is undefined.
- End with `{{ styles|raw }}` — the per-block CSS string generated by `ebt_core` (GenerateCSS), which
  `ebt_core` escapes before output.

`js/ebt_micromodal.js` — `Drupal.behaviors.ebtMicromodal.attach()` uses `once('ebt-micromodal-block-once',
'.ebt-micromodal-block', context)` and calls `MicroModal.init({ disableScroll: drupalSettings.ebtMicromodal[id].options.disable_scroll })`
for each block. Micromodal's own `data-micromodal-trigger` / `data-micromodal-close` attributes handle
open/close; the JS only wires the disable-scroll option.

The modal id and trigger target derive from `configuration.block_revision_id` (an integer), so each
placed block gets a unique, stable modal id.

## Uninstall / update

- `ebt_micromodal.install` defines `hook_update_9001()`: loads all `block_content` of type
  `ebt_micromodal` and sets `field_ebt_settings[0]['ebt_settings']['display_close_icon'] = TRUE`, then
  saves — a one-time back-fill so pre-existing blocks keep showing the "X".
- No `hook_uninstall`; removing the module leaves the block type/fields per core's config-dependency
  handling.

## Notes

- Standalone: per the README FAQ, EBT block types can be installed individually; you do not need the
  other EBT modules.
- The modal body/title are ordinary format-filtered text fields; the button/close labels are plain
  textfields printed through Twig's default auto-escaping.
- If `Field Layout` is enabled it may force Layout Builder onto the bundle's display — disable it at
  `/admin/structure/block/block-content/manage/ebt_micromodal/display/default` (README troubleshooting).
