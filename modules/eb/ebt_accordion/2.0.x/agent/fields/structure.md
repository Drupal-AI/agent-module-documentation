# Content model, displays and templates

All of this ships as `config/install/*` (default config installed with the module) plus four Twig
templates. There is no config schema in this module — the `ebt_settings` field type/schema is owned
by `ebt_core`.

## Entities and bundles

- **Block type** `block_content.type.ebt_accordion` — label "EBT Accordion/FAQ", revisions on.
  Add form: `block/add/ebt_accordion`.
- **Paragraph type** `paragraphs.paragraphs_type.ebt_accordion` — label "EBT Accordion section /
  FAQ section". One instance = one collapsible section.

## Fields

| Entity/bundle | Field | Type | Required | Notes |
|---|---|---|---|---|
| `block_content.ebt_accordion` | `field_ebt_accordion` | `entity_reference_revisions` | no | Targets paragraph bundle `ebt_accordion`; the repeatable list of sections. |
| `block_content.ebt_accordion` | `field_ebt_settings` | `ebt_settings` | no | EBT settings blob (accordion behaviour + design); widget `ebt_settings_accordion`. |
| `block_content.ebt_accordion` | `body` | core text | no | Standard block body (optional intro). |
| `paragraph.ebt_accordion` | `field_ebt_accordion_title` | `text_long` | **yes** | "Title / Question" — formatted text (so it can carry icons/markup). |
| `paragraph.ebt_accordion` | `field_ebt_accordion_text` | `text_long` | **yes** | "Text / Answer" — formatted text. |

`field_ebt_accordion_title`/`_text` are made required by update hook `ebt_accordion_update_9102`
(and are required in fresh installs). `field_storage.*` configs define storage for
`field_ebt_accordion`, `field_ebt_accordion_title`, `field_ebt_accordion_text`.

## Displays (default config)

- **Form display** `core.entity_form_display.block_content.ebt_accordion.default`: `field_group`
  tabs — **Content** (`field_ebt_accordion`, `entity_reference_paragraphs` widget, edit_mode `open`,
  add_mode `dropdown`) and **Settings** (`field_ebt_settings` → widget **`ebt_settings_accordion`**);
  `body` and `info` also present.
- **View display** `core.entity_view_display.block_content.ebt_accordion.default`:
  `field_ebt_accordion` via `entity_reference_revisions_entity_view` (default view mode),
  `field_ebt_settings` via formatter **`ebt_settings_default`** (emits the generated CSS), `body`
  via `text_default`.
- Paragraph form/view displays (`*.paragraph.ebt_accordion.default`) expose the title and text
  fields.

## Templates

- `block--block-content--ebt-accordion.html.twig` / `block--inline-block--ebt-accordion.html.twig`:
  build the `ebt-block`, `ebt-accordion`, `ebt-accordion-<styles>` and `plugin-id-…` /
  `block-revision-id-…` classes (the classes the JS keys on), conditionally `attach_library` the
  preset CSS, always `attach_library('ebt_accordion/jquery_ui_accordion')`, render
  `content|without('field_ebt_settings')`, then print `{{ styles|raw }}`. The `|raw` output is the CSS
  string generated by `ebt_core.generate_css` from the design options (margins/paddings are
  numeric-validated, colours hex-validated in the widget) — it is not user free-text.
- `field--block-content--field-ebt-accordion--ebt-accordion.html.twig`: wraps the paragraph list in
  `div.ebt-accordion-wrapper` — this is the element the JS calls `.accordion()` on.
- `paragraph--ebt-accordion--default.html.twig`: renders each section as
  `<h3 class="ebt-accordion-title">{{ field_ebt_accordion_title }}</h3>` + `.ebt-accordion-content`
  (jQuery UI treats the `<h3>` as the header and the following div as its panel).

## Lifecycle

- `ebt_accordion_uninstall()` (`.install`) deliberately **does not delete** the block type on
  uninstall; it logs a notice telling the admin to remove it manually from the custom block library.
- Update hooks: `9101` relabels the paragraph type; `9102` sets title/text fields required.
