# Settings widget, styles, libraries, templates

## Widget plugin `ebt_settings_stats`

`src/Plugin/Field/FieldWidget/EbtSettingsStatsWidget.php` —
`@FieldWidget(id="ebt_settings_stats", field_types={"ebt_settings"})`, extends
`Drupal\ebt_core\Plugin\Field\FieldWidget\EbtSettingsDefaultWidget`. It is the form widget for the
block's `field_ebt_settings` (wired in the block form display).

- **`formElement()`** calls `parent::formElement()` (which builds all the EBT Core design options),
  then appends one element: `$element['ebt_settings']['styles']`, a `#type => 'radios'` with three
  fixed options — `stats_with_vertical_dividers`, `stats_in_squares`, `stats_in_column` — default
  `stats_with_vertical_dividers`. The value is thus **constrained to those three keys**, not free
  text.
- It builds a `#description` with three `<a>` links to the shipped help PNGs, using
  `extension.path.resolver` to resolve `/modules/.../ebt_stats/images/help/`. The href values are
  static module-relative paths passed through `$this->t()` placeholders.
- **`massageFormValues()`** ensures each value has an `ebt_settings` key before save.

There is **no config schema in this module** — the `ebt_settings` field type and its schema are
defined by `ebt_core`. `provides_config_schema` is false.

## Libraries (`ebt_stats.libraries.yml`)

Three CSS-only libraries (component CSS in `css/`): `stats_with_vertical_dividers`,
`stats_in_squares`, `stats_in_column`. No JavaScript is shipped by this module.

## Templates (`templates/`)

- `block--block-content--ebt-stats.html.twig` (reusable block) and
  `block--inline-block--ebt-stats.html.twig` (Layout Builder inline block): identical structure.
  They read the selected style from
  `content.field_ebt_settings['#object'].field_ebt_settings.ebt_settings.styles`, add a
  `ebt-stats-<style>` wrapper class, and `attach_library()` the matching CSS (falling back to
  `stats_with_vertical_dividers`). Body renders `{{ content.body }}`, items render
  `{{ content.field_ebt_stats }}`.
- The trailing `{{ styles|raw }}` prints the per-block design CSS generated by **ebt_core**'s
  `GenerateCSS` (the `styles` variable is produced and escaped upstream by ebt_core, not by this
  module).
- `field--block-content--field-ebt-stats--ebt-stats.html.twig`: a standard field wrapper for
  `field_ebt_stats` that adds `ebt-stats-wrapper` and emits each `{{ item.content }}` (rendered
  paragraph) — no raw output of stat values.

## How rendering flows

Editor picks a style in the Settings tab → stored in `field_ebt_settings` → template adds the class
and attaches the corresponding CSS library → each `ebt_stats_item` paragraph (number, text, link,
image) is rendered by its normal field formatters. Presentation is swapped purely by the Styles
radio and CSS; the underlying data is untouched.
