# Block Permissions — agent index

Adds **dynamic** permissions that refine core's `administer blocks`: one per enabled theme
and one per block-plugin provider. No config, no config schema, no settings form
(`configure: null`), no Drush, no plugin types.

- **The two permission families, exact names, how to grant/read them** →
  [permissions/permissions.md](permissions/permissions.md)
- **Which core routes/forms it overrides and how access is resolved** →
  [extend/access-overrides.md](extend/access-overrides.md)

Key facts:
- Permission names, generated by
  `Drupal\block_permissions\BlockPermissionsPermissions::permissions()` via
  `permission_callbacks` in `block_permissions.permissions.yml`:
  - `administer block settings for theme <theme>` — one per installed, non-hidden theme.
  - `administer blocks provided by <provider>` — one per distinct block-plugin `provider`.
- To reach `/admin/structure/block` a user needs core's `administer blocks` **and**
  `administer block settings for theme <default theme>` (`system.theme:default`).
- The add-block form requires **both** the provider permission and the theme permission.
- Nothing is stored: the module owns no config objects.
