Linked Data Lookup Field lets editors autocomplete against external linked-data sources — SPARQL endpoints, the Library of Congress authorities, or a generic URL-argument JSON API — and store the chosen label + URI on content, rather than only referencing local entities.
---
Administrators define `linked_data_endpoint` config entities (collection at Structure) choosing an endpoint-type plugin: `SparqlQuery`, `LoCAuthority`, or `URLArgument`, each configured with a `base_url`, label/URL keys and (for URL argument) a JSON result path. A field type/widget/formatter and an `EntityReferenceSelection` plugin present an autocomplete widget; as the editor types, the `AutocompleteController` loads the endpoint entity, instantiates its plugin and calls `getSuggestions()` / `postProcessResponse()`, returning `label` and a `label - [[value]]` string so the URI is captured. Requests to the external endpoints go through Guzzle (`httpClient`) with default TLS verification.

The autocomplete route `/linked-data-lookup/{linked_data_endpoint}` requires the `authenticated` role, so it is not exposed to anonymous users; the target endpoints are admin-configured (not attacker-supplied), which contains SSRF exposure — the authenticated user controls only the query string, not the destination host. Managing endpoint config rides on the config-entity admin routes generated by the module's route provider.
