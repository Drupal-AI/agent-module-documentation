Vipps MobilePay Login is a Social Auth network plugin that adds "Log in with Vipps" to Drupal, authenticating users through the Vipps MobilePay OpenID Connect / OAuth2 provider.
---
The module registers a Social Auth `@Network` plugin (`vipps_mobilepay_login`, short name `vipps`) backed by the `league/oauth2-client` Vipps provider and a `VippsAuthManager` extending Social Auth's `OAuth2Manager`. Redirect, callback and settings-form routing are delegated to Social Auth's shared routes (`social_auth.network.redirect` / `social_auth.network.callback`); a custom param-converter maps the `vipps` network slug to this plugin. `getAuthorizationUrl()` requests the `openid address email name phoneNumber` scopes (plus any extra configured scopes), `authenticate()` exchanges the returned `code` for an access token, and `getUserInfo()` builds a `SocialAuthUser` from the resource owner (id, name, email, phone, address). A login-form alter optionally renders a Vipps login button.

Credentials are not entered directly here: the settings form (`/admin/config/social-api/social-auth/vipps`, permission `administer social api authentication`) selects a **Vipps MobilePay Connection** profile (from the `vipps_mobilepay` module) that supplies client id, client secret, merchant serial number and subscription key, plus toggles for partner mode, test mode and showing the login button. Because the OAuth state, callback CSRF check, token-exchange HTTP transport (TLS) and token handling are all provided by Social Auth core and the League OAuth2 client (state generated by `getState()` and verified by Social Auth; token exchange over the provider's HTTPS endpoints via Guzzle defaults), the module adds no bespoke callback or transport of its own — no refresh token is placed in a URL and no TLS verification is disabled in this code.

Typical setup: install `social_auth` and `vipps_mobilepay`, create a Vipps MobilePay connection profile with your merchant credentials, then on this module's settings form pick that profile, set partner/test mode, and enable the login button.

---

- Add a 'Log in with Vipps' button to the user login form
- Authenticate Drupal users via Vipps MobilePay OpenID Connect
- Register Vipps as a Social Auth network provider
- Map Vipps profile data (name, email, phone, address) to a Drupal user
- Request openid/address/email/name/phoneNumber scopes at login
- Select a Vipps MobilePay connection profile holding client credentials
- Enable partner mode for API calls on behalf of a merchant
- Toggle test mode for sandbox authentication
- Configure the integration at /admin/config/social-api/social-auth/vipps
- Register the authorized redirect URL in the Vipps developer portal
- Add extra OAuth scopes beyond the defaults
- Rely on Social Auth core for state/CSRF verification on the callback
- Exchange the authorization code for a token over the provider's HTTPS endpoint
- Show or hide the Vipps login button via a setting
- Provision or link Drupal accounts from Vipps identities via Social Auth
- Keep client id/secret in the vipps_mobilepay connection entity, not hardcoded
