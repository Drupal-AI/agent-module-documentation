# Vitals — configuration & endpoint

## The endpoint
- Route `vitals.content`, path `/vitals/{token}`, `_permission: access content`.
- Controller `\Drupal\vitals\Controller\VitalsController::output($token)`:
  1. Flood check `vitals_check_attempt`, 10/hour per client IP. If exceeded → unauthorized response (and a `warning` log with the IP).
  2. `hash_equals(state.get('vitals.token'), $token)` — mismatch logs a warning, registers a flood event, and returns the unauthorized response.
  3. On success, clears the flood event and returns `JsonResponse` of `Vitals::getStatus()`.
- Payload = `{ <check_id>: <data>, ... }` for each enabled check.
- Unauthorized response is a real `NotFoundHttpException` (404) or `AccessDeniedHttpException` (403) per config.

## Token (stored in state, not config)
- Key: `state` `vitals.token`. Generated by `Vitals::generateToken()` = `bin2hex(random_bytes(64))` (128 hex chars).
- Set on `hook_install`; deleted on uninstall. Regenerate from the form ("Generate New Token") — this **invalidates all existing clients**.
- Read it programmatically: `\Drupal::state()->get('vitals.token')`. Build the URL: `Url::fromRoute('vitals.content', ['token' => $token])`.

## Settings form
- Route `vitals_settings`, path `/admin/config/services/vitals`, `_permission: administer vitals`.
- Form `\Drupal\vitals\Form\VitalsAdminForm` (extends `ConfigFormBase`, edits `vitals.settings`):
  - **Generate New Token** — submit handler `::generateNewToken` writes a fresh `state` token.
  - **Copy Current Token** — JS-only (library `vitals/vitals_admin`) copies the hidden token field.
  - **Unauthorized Action** (`vitals_unauthorized_action`) — select `403 - Forbidden` or `404 - Not Found`.
  - **Enabled Vitals Checks** (`vitals_enabled_plugins`) — checkboxes over all `vitals_check` plugin definitions.
  - A link renders the live endpoint URL with the current token.

## Config object `vitals.settings`
```yaml
vitals_unauthorized_action: '404'   # or '403'
vitals_enabled_plugins:             # id => id means enabled (checkboxes format)
  cms_version: cms_version
  php_version: php_version
  themes: themes
  updates: updates
```
Schema: `config/schema/vitals.schema.yml` (`vitals.settings` → `vitals_unauthorized_action` text, `vitals_enabled_plugins` sequence of strings).

Set via Drush:
```
drush config:set vitals.settings vitals_unauthorized_action 403 -y
```
`getEnabledChecks()` treats a plugin as enabled only when its map value equals its key (unchecked boxes store `0`).

## Built-in checks and their output
- `cms_version` → `\Drupal::VERSION` (string).
- `php_version` → `MAJOR.MINOR.RELEASE`.
- `themes` → `{ default_theme, admin_theme }` from `system.theme`.
- `updates` → `{ pending_updates: {name: recommended}, security_updates: {name: recommended} }`, derived from `update_calculate_project_data(update_get_available(TRUE))`; security bucket = statuses `NOT_SECURE`, `REVOKED`, `NOT_SUPPORTED`; `pending_updates` also includes `NOT_CURRENT`.
