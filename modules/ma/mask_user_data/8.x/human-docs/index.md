# Mask User Data — manual setup guide

**Mask User Data** (`mask_user_data`) is a utility for **masking (obfuscating)
the user data already stored in your database** — names, email addresses, phone
numbers and any other account field or property. It replaces the real values with
realistic‑looking but entirely fake data generated by the PHP **Faker** library,
so a copy of your database can be shared, developed against, or demonstrated
without exposing anyone's real personal information. This is a common step when
making a sanitised development or staging copy of a production site, and it is a
useful tool when thinking about GDPR obligations.

You control what gets masked with a **map**: each user field or property is paired
with a Faker function — for example the `mail` property maps to Faker's `email`,
`field_phone` maps to `phoneNumber`, and so on. The map can be defined in
`settings.php` or through the module's admin UI. Once the map is in place you run
the masking with the Drush command `drush mud`, on cron, or from the UI.

> **This module rewrites real user data in place. Never run it against a
> production site.** Masking is destructive and irreversible — the original values
> are overwritten. Because the effect is so severe, the module deliberately ships
> with a second "enable" safety flag that you must switch on before it will do
> anything, so it cannot run by accident. Only ever point it at a non‑production
> copy of your database. (Note: the project itself is marked deprecated, with the
> GDPR module suggested as an alternative — weigh that before adopting it for new
> work.)

This guide is written for a **human** clicking through the admin UI. If you want
terse, token‑cheap references for an AI coding agent, read the sibling
[`agent/`](../agent/start.md) docs instead.

## Where it lives in the admin menu

After installation the module provides an admin settings page where you arm the
safety flag and define the masking map. The same settings can also be provided
directly in `settings.php`. See [Configuration](configuration/index.md) for both
routes.
