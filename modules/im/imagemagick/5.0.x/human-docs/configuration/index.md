# Configuration — selecting and setting up the toolkit

Once the module is enabled (see [Installation](../installation/index.md)), you
configure everything from the core **Image toolkit** page. Selecting the
ImageMagick toolkit is what reveals its settings; until you do, only the GD2
settings are shown.

## Open the Image toolkit page

Go to **Configuration → Media → Image toolkit**
(`/admin/config/media/image-toolkit`).

![The Image toolkit page with GD2 selected; choose "ImageMagick image toolkit" to switch](../images/toolkit.png)

In the screenshot above, **GD2 image manipulation toolkit** is the selected
radio and only its **JPEG quality** field is showing. That is the state of this
particular server, where no ImageMagick binary is installed. On a server where
ImageMagick (or GraphicsMagick) is available, you switch the toolkit as follows.

## Step-by-step

1. Under **Select an image processing toolkit**, click the **ImageMagick image
   toolkit** radio button. The page updates and an **ImageMagick image toolkit
   settings** section appears in place of the GD2 settings. (Because this
   screen's fields depend on which radio is chosen, the ImageMagick-specific
   fields described below only become visible *after* you select this option —
   they are not shown in the screenshot, which has GD2 selected.)

2. **Choose the package.** Pick which command-line suite is installed on your
   server:
   - **ImageMagick** — the default; uses the `convert` and `identify` commands.
     When ImageMagick is chosen you can also indicate the version, **v6** or
     **v7**, so the module emits the right command syntax.
   - **GraphicsMagick** — uses the single `gm` command instead. Choose this only
     if GraphicsMagick, rather than ImageMagick, is what is installed.

3. **Set the path to the binaries.** In the **path to the binaries** field, enter
   the directory that contains the executables — for example `/usr/bin/`. Two
   rules matter here:
   - Include the **trailing slash** (`/usr/bin/`, or a Windows path such as
     `C:\Program Files\ImageMagick...\`).
   - Leave the field **empty** if the binaries are already on the server's
     `$PATH`, in which case Drupal finds them by name.

4. **Choose which image formats are enabled.** The **image formats** section
   lists formats (PNG, JPEG, GIF, WEBP, AVIF, and optional ones such as TIFF,
   PDF, HEIC, PSD, BMP, SVG, ICO). Ticking a format lets Drupal read and write
   it and maps it to a MIME type. PNG, JPEG, WEBP and AVIF are enabled by
   default; TIFF, PDF and the rest are off. Only enable a format if the binary
   you installed actually supports it — the MIME mapping is validated against the
   Sophron module.

5. Optionally set the **quality** (output quality for JPEG/WEBP, default `75`)
   and, under advanced options, things like colorspace, image density, an ICC
   profile, or coalescing animated GIF frames. The defaults are sensible; you can
   leave them as-is to start.

6. Click **Save configuration**. ImageMagick is now your active image toolkit and
   all subsequent image-style derivatives are generated by the command-line
   binaries.

## Verify the binaries are found

When you select ImageMagick and save, the toolkit form runs a **path check**: it
tries to locate and run the binaries and reports back the detected package and
version. If the path is wrong or the binary is missing, this check tells you so —
this is the fastest way to confirm your server setup is correct. You can also
check the site's status report (**Reports → Status report**), where the module
adds a runtime requirements check that warns, for example, if rotate effects
cannot be supported by the detected binary.

If you need to troubleshoot exactly what Drupal is running, the advanced settings
include a **debug** option that logs the literal `convert`/`identify` command
lines that get executed.
