Image Style Generate ships one Migrate source plugin (`image_style_generate`) that produces image style config entities from a rules-and-patterns definition, so a whole matrix of styles is generated by running a migration instead of clicked into a form one at a time.

---

Image styles multiply. A design system with several aspect ratios, a dozen base sizes and a few pixel-density scales implies hundreds of styles, each identical to its neighbours except for two numbers, each otherwise created through the same multi-step admin form — slow, and inconsistent in ways nobody notices until a page looks wrong. This module reframes style creation as a migration: you set `plugin: image_style_generate` as the source, describe the axes (`style_groups` × `base_sizes` × `size_scales`), attach `effects`, and give an `id_pattern` and `label_pattern`; the plugin iterates the cartesian product, computes each style's width and height from `base_size × size_scale/100 × size_multiplier` (honouring an optional `aspect_ratio` and `base_size_dimension`), substitutes `{{variable}}` tokens into the names and effect data, and emits one row per style keyed by its generated machine name — so identical machine names naturally collapse to a single style. The destination is core's `entity:image_style`, so the output is ordinary image style config: it exports, deploys and gets overridden like anything else, and the whole set is `migrate:rollback`-able. The module itself has no UI, no routes, no settings and no permissions of its own — everything lives in a `migrate_plus` migration YAML that a developer authors and a migrate-privileged user runs via Drush or the Migrate Tools UI. Nothing is fetched, no derivative images are pre-rendered (derivatives are still generated on demand by core the usual way); the plugin only writes configuration. Requires core `image` + `migrate`; `migrate_plus` (to store the migration as config) and `migrate_tools` (Drush/UI to run it) are the recommended companions. Two example submodules — basic (`image_style_generate_example`, three migrations) and advanced (`image_style_generate_example_advanced`, one migration producing 336 focal-point styles) — are the practical templates to copy. Version **1.2.0**, core `^8.8 || ^9 || ^10 || ^11`.

---

- Generate a full matrix of image styles from one YAML definition.
- Replicate core's Thumbnail/Medium/Large plus 1.5x/2x/3x density variants.
- Build a responsive image style set per breakpoint.
- Create one style group per aspect ratio (16:9, 4:3, 1:1, 3:4).
- Keep the image style estate in version control as a migration.
- Roll back every generated style with `drush migrate:rollback`.
- Reproduce the identical style set across dev/stage/prod.
- Regenerate styles after a design-system change by editing numbers and re-running.
- Standardise crop settings (anchor, crop type) across hundreds of styles.
- Apply a Focal Point scale-and-crop effect uniformly.
- Vary image quality per size scale (higher compression for larger densities).
- Define base sizes as multiples of a `size_multiplier` for tidy definitions.
- Enforce a consistent machine-name and label naming convention via patterns.
- Remove or override a specific base size / scale / effect for one style group.
- Generate square, landscape and portrait families in a single run.
- Learn the pattern of using Migrate to generate *configuration* rather than content.
- Bulk-create styles for a large media library without clicking.
- Seed a new site's image styles as installable default config.
- Avoid drift between near-identical hand-built styles.
- Compute heights automatically from a declared aspect ratio.
