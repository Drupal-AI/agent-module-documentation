# Formatter, entity and render

Image Hotspots has no widget and no dedicated config form. You turn an existing **image** field into a
hotspot image purely by choosing its **formatter** on the entity's *Manage display* page; the hotspot
records themselves are separate content entities created later, from the rendered page.

## Field formatter `image_with_hotspots`

- Class: `Drupal\image_hotspots\Plugin\Field\FieldFormatter\ImageHotspotsFormatter`
  (`src/Plugin/Field/FieldFormatter/ImageHotspotsFormatter.php`).
- Extends core `Drupal\image\Plugin\Field\FieldFormatter\ImageFormatter`, so it keeps every core image
  formatter setting (`image_style`, `image_link`, responsive, etc.) and adds one:

| Setting | Values | Default (code) | Meaning |
|---|---|---|---|
| `image_hotspots_style` | `tooltip`, `modal` | `'tootip'` (misspelled in `defaultSettings()`) | `tooltip` = show label text on hover; `modal` = open a Drupal dialog on click. |

`viewElements()` (`ImageHotspotsFormatter.php:75`) builds each image, then:

1. Resolves `image_style` (or `'none'`), `field_name`, and the file id, and loads hotspots with
   `ImageHotspot::loadByTarget(['field_name'=>…, 'image_style'=>…, 'fid'=>…])`.
2. If the view langcode differs from the site default language, swaps in each hotspot's translation
   where one exists.
3. If the current user has `edit image hotspots`, attaches the edit UI: `image_hotspots/translate`
   when viewing a non-default language, otherwise `image_hotspots/edit`.
4. Serialises the hotspots (title, description, link, target, x/y/x2/y2) into
   `#attached['drupalSettings']['image_hotspots'][field_name][fid][image_style][hotspots_style][langcode]['hotspots']`.
5. Adds cache tag `hotspots:{field_name}:{fid}:{image_style}`, attaches `image_hotspots/view` +
   `core/drupal.dialog.ajax`, and switches the element `#theme` to `image_formatter_with_hotspots`.

Set the formatter from code:

```php
\Drupal::service('entity_display.repository')
  ->getViewDisplay('node', 'article', 'default')
  ->setComponent('field_image', [
    'type' => 'image_with_hotspots',
    'settings' => [
      'image_style' => 'large',            // hotspots are bound to THIS style
      'image_hotspots_style' => 'tooltip', // or 'modal'
    ],
  ])->save();
```

Because hotspots are stored against `(field_name, fid, image_style)`, changing the field's image style
hides hotspots drawn under the previous style (they are not migrated).

## Theme / template

- Theme hook `image_formatter_with_hotspots` (declared in `image_hotspots.module` `hook_theme`),
  template `templates/image-formatter-with-hotspots.html.twig`, preprocess
  `template_preprocess_image_formatter_with_hotspots()` (which calls core
  `template_preprocess_image_formatter`).
- The template renders the `<img>` inside `.image-hotspots-wrapper` with `data-field-name`,
  `data-image-style`, `data-fid`, `data-hotspots-style`, `data-langcode` attributes that the JS reads,
  a `.labels` container, and — only when `info.editable` — the "Add hotspot" button and the inline
  edit `<form>` (title/description/link/target inputs).

## The `image_hotspot` content entity

Defined in `src/Entity/ImageHotspot.php` (annotation `@ContentEntityType`):

- id `image_hotspot`; base_table `image_hotspot`; data_table `image_hotspot_field_data`;
  `translatable = TRUE`, `content_translation_ui_skip = TRUE`.
- Entity keys: `id` → `hid`, `label` → `title`, `uuid`, `langcode`.

Base fields (`baseFieldDefinitions()`):

| Field | Type | Notes |
|---|---|---|
| `hid` | integer | id, read-only, unsigned |
| `uuid` | uuid | read-only |
| `field_name` | entity_reference → `field_config` | which image field |
| `fid` | entity_reference → `file` | the image file |
| `image_style` | entity_reference → `image_style` | style the hotspot was drawn on |
| `uid` | entity_reference → `user` | creator (set to current user on create) |
| `title` | string | translatable; entity label |
| `target` | string | link `target` attribute (`_self` / `_blank`) |
| `description` | string_long | translatable |
| `link` | string_long | translatable; URL for the label/box link |
| `langcode` | language | |
| `x`, `y`, `x2`, `y2` | float | region corners (unsigned) |

Helpers on the entity/interface: `getTarget()` returns the `(field_name, fid, image_style, langcode)`
array; `getTitle/setTitle`, `getDescription/setDescription`, `getLink/setLink`,
`getTargetLink/setTargetLink`, `getCoordinates/setCoordinates`, and the static
`ImageHotspot::loadByTarget($values)` (a `loadByProperties` wrapper the formatter uses).

There is **no** `.install` file — the entity's schema is generated by the entity/field API, so
`drush entity:updates` / a normal module install creates the `image_hotspot` tables.
