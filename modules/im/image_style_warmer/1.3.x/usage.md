Image Style Warmer pre-generates configured image style derivatives so the resized/cropped images already exist on disk when a page first requests them, instead of being created on the first visitor's request.

---

The module hooks `hook_ENTITY_insert`/`hook_ENTITY_update` on `file` (and `crop`) entities and hands each permanent image file to its `image_style_warmer.warmer` service. Two lists of image styles are configured on one settings form (`admin/config/development/performance/image-style-warmer`, config object `image_style_warmer.settings`): **Initial image styles** (`initial_image_styles`) are generated synchronously at the end of the request via the service's `destruct()` (it implements `DestructableInterface`, tagged `needs_destruction`), while **Queue image styles** (`queue_image_styles`) are pushed onto the `image_style_warmer_pregenerator` queue and generated later by its cron QueueWorker. Generation is idempotent — `doWarmUp()` skips a derivative whose file already exists — and only runs for permanent files that pass image-extension validation. The module also ships VBO/action plugins (`image_style_warmer_warmup_file`, `image_style_warmer_warmup_media`) so editors can warm existing files or media from a Views bulk-operations list, and a Drush command (`image-style-warmer:warm-up`, alias `isw:wu`) that batch-warms every existing file using the Initial image styles config. There is no per-field configuration; the two style lists apply site-wide to every uploaded image file.

---

- Pre-render thumbnail and teaser image styles the moment an image is uploaded so the first page view is not slowed by on-the-fly derivative creation.
- Warm heavy, expensive image styles (large hero crops, WebP conversions) in the background via cron instead of blocking any visitor request.
- Split fast/light styles into "initial" (generated on save) and slow/large styles into "queue" (generated by cron).
- Batch-generate derivatives for a whole existing media library after adding a new image style, using `drush isw:wu`.
- Avoid the "first visitor pays" latency spike for newly added responsive image style sets.
- Warm image styles for files attached to freshly imported/migrated content by re-saving the files.
- Use a Views Bulk Operations list of files with the "Warmup image styles of files" action to selectively pre-generate derivatives.
- Warm all image fields on selected media entities with the "Warmup image styles of media entities" action.
- Regenerate missing derivatives after clearing the `styles/` directory, without waiting for visitor traffic.
- Ensure social-share/Open Graph image styles exist before a page is crawled.
- Keep CDN origins warm by pre-creating derivatives so the CDN never misses on first fetch.
- Reduce load spikes on image-heavy launches (galleries, catalogs) by pre-building styles ahead of go-live.
- Pre-generate crop-based derivatives automatically when an `image_widget_crop`/Crop entity is saved (the module also listens on `crop` insert/update).
- Configure which styles warm on upload purely through exported config (`initial_image_styles`, `queue_image_styles`) for repeatable deployments.
- Throttle background generation by relying on the QueueWorker's per-cron time limit (`cron = {"time" = 60}`).
- Pre-warm print/PDF or email-sized image styles that are rarely requested but must render instantly when needed.
- Guarantee derivatives exist for images served to a decoupled/JSON:API frontend that cannot trigger Drupal's lazy derivative route.
- Trigger warming programmatically by calling `\Drupal::service('image_style_warmer.warmer')->warmUp($file)` from custom code.
- Force immediate generation of a specific style set with `->doWarmUp($file, ['thumbnail','large'])`.
- Queue a custom style list for a file from code with `->addQueue($file, [...])`.
- Keep the derivative directory populated so backup/deploy snapshots capture the generated images.
- Pre-generate styles for user-uploaded avatars so profile pages never render a blank/placeholder image.
- Warm image styles used inside emails (which cannot run the dynamic image-derivative route) so remote clients get real images.
