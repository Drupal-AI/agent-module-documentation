# Configuration

Setup is short: enter your Rokka credentials on the settings form, then sync your
existing image styles to Rokka so they keep working. After that, image handling
runs through Rokka automatically.

## Open the settings form

1. Log in as an administrator (a user with permission to administer the site's
   configuration and the Rokka permissions the module provides).
2. Open the Rokka settings form under **Configuration** (the
   `rokka.admin_settings` route).

## Enter your Rokka credentials

The form asks for your Rokka **organization** and **API key** (and related
connection details from your Rokka account). These authenticate every request the
module makes to Rokka, so treat them as secrets:

- Never hard-code or commit the API key.
- In DDEV, store the value in an environment variable and load it into the
  container rather than pasting it somewhere that gets committed:

  ```bash
  ddev dotenv set .ddev/.env --rokka-api-key=<value>
  ddev restart
  ```

  Keep `.ddev/.env` out of version control, and confirm the variable is present
  without printing it:

  ```bash
  ddev exec 'test -n "$ROKKA_API_KEY"'   # exit status 0 = it is set
  ```

  You can then reference that environment variable from your settings rather than
  storing the raw key in exported configuration.

Save the form once the credentials are in place.

## Sync your existing image styles

If your site already has images and image styles, run the Drush command that maps
each Drupal image style to a Rokka "stack" so your current styles keep rendering
through Rokka:

```bash
drush rokka:migrate-imagestyles
```

## How image handling changes

Once configured, new image uploads are stored in Rokka rather than on your local
file system, and image derivatives (resize, crop, optimize, plus Rokka's extra
effects) are generated by Rokka and served from its CDN. Standard Drupal image
styles continue to work — they are simply produced by Rokka now.

Because images are served from Rokka's public CDN, avoid routing
**access-restricted** images through it: a CDN URL is reachable by anyone who
obtains it. Keep private or licensed imagery on a storage mechanism that enforces
access control.
