Façade is a generic framework for managing multi-tenant scenarios — provisioning and managing separate Drupal sites/environments — from one control site. It provides a `Tenant` content entity and a `Tenant type` config entity, plus a launch-tenant plugin manager so implementing modules can react to tenant lifecycle operations (create, edit, delete) by driving an external cloud orchestrator.

---

The reference implementation manages an OpenStack-based Cloud Orchestrator distribution on Amazon EC2/CloudFormation, but Façade itself is provider-agnostic: you define a Tenant type and a `FacadeLaunchTenantPlugin` that performs the actual deployment work. Access is permission-driven — `add tenant`, `view/edit/delete tenant entities`, `administer tenant entities` (the last flagged `restrict access: true`), plus per-bundle permissions generated by `Access\TenantPermissions::generatePermissions`. The only route is the admin settings form (`/admin/config/services/facade`, `administer site configuration`). A submodule, `facade_remote_worker`, adds a REST resource (`entity.cloud_config`), a Drush `EntityCommands` command, a `field_bearer_token` user field and a global bearer-token authentication provider so remote workers can authenticate back to the control site and fetch their configuration.

Typical setup: install Façade (and the `cloud` module for the reference provider), define a Tenant type, wire a launch plugin, configure the admin settings, and — if using remote workers — enable `facade_remote_worker` and issue each worker user a bearer token.
---
- Model each managed site/environment as a `Tenant` entity
- Define `Tenant type` bundles with their own settings
- React to tenant create/edit/delete via a launch-tenant plugin
- Provision an OpenStack Cloud Orchestrator per tenant (reference impl)
- Drive Amazon EC2 / CloudFormation deployments from tenant operations
- Grant granular tenant permissions (add/view/edit/delete/administer)
- Generate per-bundle tenant permissions automatically
- Configure the framework at /admin/config/services/facade
- List and manage tenants through entity list builders
- Delete a tenant and trigger teardown of its remote resources
- Expose tenant/cloud config to remote workers over REST (submodule)
- Authenticate remote workers with a bearer token (submodule)
- Store a per-user bearer token in the `field_bearer_token` field
- Run Drush entity commands for remote-worker automation
- Build a custom cloud provider by implementing a launch plugin
- Centralize control of many Drupal sites from one dashboard site
- Separate tenant configuration from deployment logic via plugins
- Integrate with the contrib `cloud` module for AWS operations
