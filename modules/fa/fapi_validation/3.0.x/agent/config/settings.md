# Config, routes, and permissions

## Install / enable

`composer require drupal/fapi_validation` then `drush en fapi_validation -y`. No module or third-party
dependencies. Once enabled, `#validators` / `#filters` are available on every input form element site-wide.

## Config object + schema

- Config: `fapi_validation.settings` (`config/install/fapi_validation.settings.yml`), a single key `bypass: false`.
- Schema: `config/schema/fapi_validation.schema.yml` — `type: config_object` with `bypass: boolean`.

## Settings form

- Route `fapi_validation.settings` → `/admin/config/system/fapi`, form
  `\Drupal\fapi_validation\Form\FapiValidationForm` (extends `ConfigFormBase`), title *Form API Validation settings*.
- Permission: `manage fapi validation settings`.
- One checkbox `bypass` ("Bypass validations") saved to `fapi_validation.settings:bypass`.
- Menu link under `system.admin_config_system`; local tasks defined in `fapi_validation.links.task.yml`.

## Bypass model (intended admin/trusted capability)

`FapiValidationValidatorsManager::validate()` runs all declared rules for everyone **unless** the site `bypass`
config flag is TRUE and the current user holds the relevant bypass permission. Default config `bypass: false`, so
out of the box validation applies to all users. The bypass path exists so trusted roles can be exempted
deliberately (e.g. admin/staging workflows).

- Static permission `bypass fapi validations` — exempts a holder from validation when `bypass` config is on.
- Dynamic per-validator permissions `bypass <validator_id> fapi validation` are generated by
  `FapiValidationPermissions::permissions()` (registered via `permission_callbacks` in
  `fapi_validation.permissions.yml`), one per registered validator plugin id.

## Read-only plugin-listing routes

`FapiValidationController` renders two admin tables (`#theme => 'table'`) of plugin id / label / description /
provider:

- `fapi_validation.validations` → `/admin/config/system/fapi/validations`, permission `view fapi validation plugins`.
- `fapi_validation.filters` → `/admin/config/system/fapi/filters`, permission `view fapi filter plugins`.

Both are informational and change no state; the listed values come from plugin attributes/annotations.

## Permissions summary (`fapi_validation.permissions.yml`)

| permission | grants |
|-----------|--------|
| `manage fapi validation settings` | access the settings form. |
| `bypass fapi validations` | skip validation when the bypass flag is enabled. |
| `view fapi validation plugins` | view the validators listing. |
| `view fapi filter plugins` | view the filters listing. |
| `bypass <id> fapi validation` (dynamic) | per-validator bypass, one per registered validator. |
