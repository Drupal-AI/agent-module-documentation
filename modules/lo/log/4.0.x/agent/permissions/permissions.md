# Permissions

Access is split between four module-declared permissions and a set of **per-bundle
entity permissions generated by the Entity API** (`entity` module). The Log entity uses
`permission_granularity: 'bundle'` with handlers
`UncacheableEntityPermissionProvider` and `UncacheableEntityAccessControlHandler`, and its
`admin_permission` is `administer log`, `collection_permission` is `access log collection`.

## Declared in `log.permissions.yml`

| Permission | Title | Notes |
|-----------|-------|-------|
| `access log collection` | View log collection | Grants the entity collection listing. Also the entity's `collection_permission`. |
| `administer log types` | Administer log types | Manage `log_type` bundles + their fields. `restrict access: true`. Also the `log_type` admin permission. |
| `view all log revisions` | View all log revisions | Required for `view revision` / `view all revisions` operations. `restrict access: true`. |
| `revert all log revisions` | Revert all log revisions | Required for the `revert` operation. `restrict access: true`. |

Revision permissions are enforced by `Drupal\log\Hook\AccessHooks::entityAccess()`
(`hook_entity_access`): it returns *allowed* for `view revision`/`view all revisions` only
with `view all log revisions`, and for `revert` only with `revert all log revisions`;
otherwise neutral (falls back to core/entity access).

## Generated per bundle (Entity API)

Because granularity is `bundle`, `UncacheableEntityPermissionProvider` generates, for each
`log_type` bundle `<b>`:

- `administer log` — bundle-independent super permission (the entity `admin_permission`).
- `create <b> log`
- `view any <b> log` / `view own <b> log`
- `update any <b> log` / `update own <b> log`
- `delete any <b> log` / `delete own <b> log`

"own" permissions are evaluated against the log owner (`uid` base field via
`EntityOwnerTrait`). These gate the canonical/add/edit/delete routes and the bulk actions.
`administer log` bypasses the per-bundle checks.

## Route access summary

| Route / surface | Requirement |
|-----------------|-------------|
| canonical / add / edit / delete / revision routes | Entity access (create/view/update/delete + revision perms above), via `AdminHtmlRouteProvider` + `RevisionHtmlRouteProvider`. |
| `log.autocomplete.name` (`/log/{log_bundle}/autocomplete`) | `_entity_create_access: 'log:{log_bundle}'`; results are further filtered per view permission (see [api/entity.md](../api/entity.md)). |
| `log.log_clone_action_form` (`/admin/content/log/clone`) | `_entity_create_any_access: 'log'`; each log re-checked for `view`+`create` at submit. |
| `log.log_schedule_action_form` (`/admin/content/log/reschedule`) | `_user_is_logged_in: 'TRUE'`; operates only on the user's own tempstore selection, each log re-checked for `update` + timestamp/status field edit at submit. |
| `log_admin` Views page (`admin/content/log`) | `perm: 'administer log'` (optional view; overrides the entity collection route at the same path). |
