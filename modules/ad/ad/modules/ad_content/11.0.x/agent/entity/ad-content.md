# ad_content — entity, bundles, bucket & rendering

## The `ad_content` entity

`src/Entity/AdContent.php` — `#[ContentEntityType(id: 'ad_content', …)]`, extends
`EditorialContentEntityBase`, uses `EntityOwnerTrait`. Revisionable (`show_revision_ui: TRUE`),
translatable, `permission_granularity: bundle`, `admin_permission: administer ads`,
`bundle_entity_type: ad_content_type`. Tables `ad_content` / `ad_content_field_data` (+ revision
tables). Implements `AdContentInterface` (which declares `AdInterface`), so an ad **is** an
`AdInterface`: `getAdIdentifier()` returns the **UUID**, `getBucketId()` returns
`AdContentInterface::BUCKET_ID` (`'ad_content'`), `getTargetUrl()` builds a `Url` from the
`target_url` link field with `rel=nofollow`.

**Base fields** (`baseFieldDefinitions`): `title` (required, unique-title constraint), `uid`
(owner), `placement` (`list_string`, required, allowed values from `ad_get_placements_list()`),
`target_url` (`link`, required), `status` (published), `created`, `changed`. Bundle fields:
`image_ad` → `field_ad_image` (image), `text_ad` → `field_ad_text` (`text_with_summary`). All field
config lives in `config/install/`.

**Entity routes** (from the attribute + `AdminHtmlRouteProvider`): collection `/admin/content/ad`,
add-page `/admin/content/ad/add`, add-form `/admin/content/ad/add/{ad_content_type}`, canonical
`/admin/content/ad/{ad_content}`, edit/delete, and the revision routes. Canonical view route
`entity.ad_content.canonical` is also defined in `ad_content.routing.yml` with permission
`administer ads` (view mode `ad_content.admin`).

## Bundles — `ad_content_type`

`src/Entity/AdContentType.php` — `ConfigEntityBundleBase` (`config_prefix: ad_content_type`,
`admin_permission: administer ad types`), managed at `/admin/structure/ad-content`. Shipped:
`image_ad` ("Image advertisement"), `text_ad` ("Text advertisement"). Field UI base route
`entity.ad_content_type.edit_form`.

## Permissions & access

`ad_content.permissions.yml`: static `create ads`, `edit ads`, `delete ads`,
`view/revert/delete ad revisions`, `administer ad types` (all `restrict access: true`), plus
per-bundle permissions generated by `AdContentPermissions::contentAdTypePermissions()` (e.g.
`create image_ad ads`). `AdContentAccessControlHandler` grants everything to `administer ads`, then
checks the type-specific OR generic permission per operation; create access checks
`administer ads` / `create ads` / `create {bundle} ads`.

## Bucket plugin `AdContentBucket`

`src/Plugin/Ad/Bucket/AdContentBucket.php` (id `ad_content`). Key methods:

- `buildPlaceholder($placement)` — returns an `<ad-content>` html_tag element carrying
  `bucket`/`placement` attributes + `data-nosnippet`, attaching library
  `ad_content/ad_content.render_ads`. This is what the block renders.
- `getAdContent($placement, $random=TRUE)` — entity query with **`accessCheck(TRUE)`**,
  `condition('placement', …)`, `condition('status', 1)`, tag `order_random` (→ `orderRandom()` via
  `ad_content_query_order_random_alter`), `range(0,1)`.
- `buildAd($placement)` — renders the chosen ad in the **`impression`** view mode, calls
  `getTracker()->trackImpression($ad, currentUser, ad_context)`, stamps `#ad_content_uuid`,
  `#ad_impression_id`, and a `#post_render` (`postAdRender`) that replaces
  `TrackerInterface::PLACEHOLDER_IMPRESSION` in the markup with the real event id.
- `getAd($uuid)` — loads by UUID via `entity.repository`. `isEmpty()` / `getPlacementCount()` —
  access-checked count queries.

## Impression render controller

`ImpressionController::renderAds` (route `ad_content.render_ad` → `/ad/content/render`, permission
`access content`). Reads the `ads` query param (JSON), **rejects non-arrays**, caps at
`ALLOWED_ADS_AMOUNT = 50` (DoS guard), and for each entry validates that `bucket`, `placement`, and
the html id are non-empty strings before calling `bucketFactory->get($bucket)?->buildAd($placement)`.
Each ad is rendered with `renderer->renderInIsolation()` and keyed by
`Html::cleanCssIdentifier($html_id)`; the response is JSON of `{element, ad_content_uuid, bucket_id,
placement_id}`. The JS then injects `element` into the placeholder and, if `track_clicks` is on,
wires an onclick GET to the click route.

## Image formatters

- `AdContentImageFormatterBase` (`src/Field/`) — renders the image with `#theme => image_formatter`
  linked to the ad's `getTargetUrl()` (`target=_blank`, `rel=nofollow`).
- `ad_content_image` (`AdContentImageFormatter`) — plain linked image.
- `ad_content_image_click_track` (`TrackAdContentImageFormatter`) — links to route `ad_track.track`
  with `parent_id=PLACEHOLDER_IMPRESSION` so the click is tied to the impression; forces
  `#cache max-age=0` so the placeholder replacement isn't cached.

## Advertisement indicator

`hook_entity_extra_field_info` adds a display-only `ad_content_advertisement_indicator` component
per bundle; `hook_ENTITY_TYPE_view` renders it (theme `ad_content_advertisement_indicator`,
template `templates/ad-content-advertisement-indicator.html.twig`) using the translated
`ad.settings` `advertisement_indicator` string when the component is enabled.
