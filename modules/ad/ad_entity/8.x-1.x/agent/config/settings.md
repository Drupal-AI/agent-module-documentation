# Global settings, config objects & personalization

## Install & enable

```bash
composer require drupal/ad_entity      # pulls drupal/entity ~1.0
drush en ad_entity -y
# then enable at least one provider submodule, e.g.:
drush en ad_entity_dfp -y
```

Grant view access per role: **"View Advertising entities"** and **"View Display configs for
Advertisement"** (both generated by the entity `permission_provider`). All create/edit/delete and
the global settings form require **`administer ad_entity`**.

## The `ad_entity.settings` config object

Global settings form `GlobalSettingsForm` at **`/admin/structure/ad_entity/global-settings`**
(route `ad_entity.settings`, permission `administer ad_entity`, extends `ConfigFormBase`, edits
`ad_entity.settings`). Install defaults in `config/install/ad_entity.settings.yml`; schema in
`config/schema/ad_entity.schema.yml`.

| Key | Type | Meaning |
|---|---|---|
| `enable_responsive_behavior` | bool | Re-initialize ads on breakpoint change (needs `theme_breakpoints_js`). |
| `process_targeting_output` | string\|null | Filter-format id used by `TargetingCollection::filter()`; `null` = strip all tags. |
| `personalization.enabled` | bool | Whether personalized ads are on. |
| `personalization.consent_awareness.method` | string | `opt_in` / `opt_out` / `disabled` / `unbiased` / `oil` / `eu_cookie_compliance`. |
| `personalization.consent_awareness.cookie.{name,operator,value}` | — | Cookie to check for consent (module does **not** set the cookie). |
| `behavior_on_context_reset.include_entity_info` | bool | Add `entitytype`/`entitylabel`/`entityuuid` targeting for the route entity. |
| `behavior_on_context_reset.collect_default_data` | bool | Collect context from the entity's default-view-mode context fields. |
| `site_wide_context` | sequence | Site-wide AdContext data (`plugin_id`, `settings`, `apply_on`). |
| `tweaks.force_backend_appliance` | bool | Force server-side context appliance (drops `context.js`). |
| `tweaks.include_preload_tags` | bool | Emit `<link rel=preload>` for provider libraries. |
| `tweaks.use_inline_js` | bool | Inline the queue-push `<script>` in each ad container. |

Provider submodules extend this object via `hook_config_schema_info_alter()` (e.g. DFP adds a
`dfp` mapping, AdTech adds `adtech_factory`, AdTech v2 adds `adtech_v2_factory`) and add their own
tab through `AdType::globalSettingsForm()`.

## JS settings tag (how the frontend gets config)

`hook_page_attachments()` → `_ad_entity_attach_js_settings_head()` always injects one
`<script id="ad-entity-settings" type="application/json">` into `<head>` (weight −80) with the
result of `_ad_entity_get_js_settings()` (cached under cid `ad_entity.js_settings`, tag
`config:ad_entity.settings`). It carries `responsive`, `inline`, `p13n`, and the resolved
`consent` block. `drupalSettings` is deliberately **not** used here so the whole settings library
isn't forced into `<head>`. Alterable via `hook_ad_entity_js_settings_alter()`.

## Consent methods (resolved in `_ad_entity_get_js_settings()`)

- `oil` → checks existence of the `oil_data` cookie.
- `eu_cookie_compliance` → adapts method + `cookie_name` from `eu_cookie_compliance.settings`.
- otherwise → uses the configured method + cookie name/operator/value (value is `json_decode`d).
- `disabled` / `unbiased` need no cookie logic, and `hook_library_info_alter()` drops
  `js/consent.js` when personalization is off or the method is `disabled`/`unbiased`.

## Config entity schemas

`ad_entity.ad_entity.*` (id, label, `type_plugin_id`, `view_plugin_id`,
`disable_initialization`) and `ad_entity.display.*` (id, label, `theme_canonical`, `variants` —
a themes→ads→breakpoint-JSON sequence — and `fallback`). Field/widget/formatter schemas for the
context field are also declared here (`field.formatter.settings.ad_entity_context`,
`field.widget.settings.ad_entity_context`).
