# Xray Audit permissions & route access

Defined in `xray_audit.permissions.yml`. Both are marked `restrict access: true` (they grant
access to potentially sensitive site-structure/data reports).

| Permission | Gates |
|---|---|
| `xray_audit access` | Viewing all report pages: `xray_audit.home`, `xray_audit.group`, the dynamic per-operation task routes, batch CSV, and the ZIP download. |
| `xray_audit administer configuration` | The config/dev pages: `xray_audit.development` and the settings form `xray_audit.settings`. |

## Route → requirement map (`xray_audit.routing.yml`)

| Route | Path | Requirement |
|---|---|---|
| `xray_audit.home` | `/admin/reports/xray-audit` | `xray_audit access` |
| `xray_audit.group` | `/admin/reports/xray-audit/{group_id}` | `xray_audit access` |
| `xray_audit.batch_process` | `/admin/reports/xray-audit/batch/{task_plugin}/{batch_process}` | `xray_audit access` |
| `xray_audit.download_all_csv_batch` | `/admin/reports/xray-audit/download-all-csv-batch` | `xray_audit access` |
| `xray_audit.download_generated_zip_file` | `/admin/reports/xray-audit/download-zip` | `xray_audit access` |
| `xray_audit.settings` | `/admin/config/development/xray_audit/settings` | `xray_audit administer configuration` |
| `xray_audit.development` | `/admin/config/development/xray_audit` | `xray_audit administer configuration` |
| `xray_audit.display_mode_example` | `/xray-audit/{entity_type}/{entity_id}/{view_mode}/example` | `access content` |
| `xray_audit.example_popup` | `/xray-audit/{entity_type}/{entity_bundle}/{view_mode}/popup` | `access content` |

The two display-mode example routes back the sample renderings shown on the content-display
reports (the popup picks a random example entity of the chosen bundle/view-mode and the example
route renders it inside an iframe).

## Dynamic operation access

Per-operation routes generated by `Routing/RouteSubscriber` can additionally use the
`_xray_audit_operation_access` access check (`Access/OperationAccessCheck`), which allows an
operation only when its task plugin's module `dependencies` are met
(`$task_plugin->isOperationAvailable($operation)`). This is a *capability* gate (is the report
applicable), layered on top of the `xray_audit access` permission — not a per-user restriction.
