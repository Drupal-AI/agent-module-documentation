Acquia Analytics Redirects re-attaches marketing/analytics query parameters that Acquia Cloud's Varnish strips for cache performance, putting them back onto the destination URL of a Drupal redirect. It is a single response event subscriber with no configuration.

---

On Acquia Cloud the default Varnish VCL strips common analytics query parameters (utm_*, gclid, etc.) to improve cache hit rates, then passes the stripped query to the backend in an `X-Acquia-Stripped-Query` request header. This module's `AnalyticsRedirectsEventSubscriber` listens on `KernelEvents::RESPONSE` (priority -1024); when the response is a 301 or 302 redirect and that header is present, it parses the redirect's target URL, merges the header's query string into the target's own query (the target's own parameters win on key collision, and any `#fragment` is preserved), adds `X-Acquia-Stripped-Query` to the response `Vary` header (so Varnish caches per query variation), and re-issues the redirect as a `TrustedRedirectResponse` carrying the original headers. This ensures that when Drupal issues a redirect whose destination is expected to keep analytics parameters, those parameters survive Varnish's stripping. The module has no admin UI, no permissions, no config, and no services beyond the one subscriber; it is intended specifically for sites fronted by Acquia Cloud Varnish. On any other host the `X-Acquia-Stripped-Query` header is normally absent, so the module simply does nothing. Note also that core's Internal Page Cache module must be disabled/uninstalled for the module to take effect.

- Preserve utm_source / utm_medium / utm_campaign parameters through a Drupal redirect on Acquia Cloud.
- Keep Google Ads `gclid` (and similar click IDs) on the destination of a 301/302 redirect.
- Stop Varnish query-stripping from breaking analytics attribution on redirected landing pages.
- Maintain high Varnish cache hit rates while still delivering analytics params to the final URL.
- Restore stripped query strings on path redirects (e.g. old URL → new URL) without custom code.
- Ensure marketing campaign tracking survives canonical/redirect chains on Acquia.
- Vary the Varnish cache correctly per stripped-query value so different campaigns cache separately.
- Support redirect modules / route responses that expect query params on their target.
- Deploy a zero-config fix for the known Acquia Varnish + analytics-redirect interaction.
- Keep affiliate or referral parameters intact across a redirect on Acquia-hosted sites.
- Preserve tracking parameters on login/anonymous redirects that would otherwise lose them.
- Avoid losing query data on 302 responses generated by contrib or custom controllers.
- Reapply parameters transparently for every 301/302 response site-wide.
- Complement Acquia's documented query-string stripping VCL behavior on the Drupal side.
- Retain search or filter query params that analytics relies on after a redirect.
- Provide analytics continuity for paid-traffic landing pages behind Varnish.
- Merge stripped analytics params without overriding query values the destination URL already sets.
- Keep a URL fragment (anchor) on the redirect target while re-attaching stripped query params.
