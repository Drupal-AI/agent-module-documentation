Experimental Content Hub health-check submodule. It provides a Drush command that finds
configuration entities with a `NULL` UUID on a publisher site and assigns them freshly generated
UUIDs so they can be syndicated reliably.

---

Acquia Content Hub tracks and syndicates entities by UUID. Configuration entities that were
somehow created without a UUID (a `NULL` value) cannot be exported/tracked correctly, which
breaks syndication from a publisher. This submodule audits for that known incompatibility and
ships one Drush command, `acquia:contenthub-fix-config-entities-with-null-uuids`
(alias `ach-fix-null-uuids`), implemented by `AcquiaContentHubConfigNullUuidsFix`. The command
walks every config entity type, and for any entity whose `uuid()` is empty it writes a newly
generated UUID into that config object and saves it, reporting each fix. It refuses to run unless
`acquia_contenthub_publisher` is enabled. The module is marked experimental ("Use with caution")
and adds no UI, permissions, config, or plugins.

---

- Repair configuration entities that have `NULL` UUIDs before syndicating.
- Diagnose why certain config entities fail to export from a publisher.
- Backfill stable UUIDs for legacy or imported configuration.
- Run a one-off audit of config-entity UUID integrity on a publisher.
- Fix Content Hub tracking issues caused by missing config UUIDs.
- Prepare a publisher site for clean configuration syndication.
- Guard the repair so it only runs on publisher sites.
- Print each entity type, id, and new UUID that was fixed.
- Confirm all config entities have proper UUIDs.
- Recover from partial or broken config imports that dropped UUIDs.
- Include the fix in a pre-syndication maintenance routine.
- Troubleshoot Content Hub export failures tied to configuration.
- Assign UUIDs generated by Drupal's core UUID service.
- Keep publisher configuration compatible with Content Hub's UUID-keyed model.
- Use alongside the base module's publisher audit commands.
