# RDF SKOS — manual setup guide

**RDF SKOS** (`rdf_skos`) exposes **SKOS** concept schemes and concepts as Drupal
entities. SKOS is the W3C standard that libraries, governments, and EU
institutions use to publish controlled vocabularies and thesauri — EuroVoc,
subject headings, standardised classification schemes — each with concepts,
broader/narrower relationships, and multilingual labels. Instead of copying such
a vocabulary into a Drupal taxonomy (where it drifts out of date and loses its
published identifiers), RDF SKOS reads it **live from a SPARQL triplestore**,
defining `skos_concept_scheme` and `skos_concept` entity types whose storage is
the SPARQL Entity Storage backend. A `rdf_skos_language_mapping` submodule aligns
SKOS language tags with Drupal's language codes so multilingual concept labels
resolve correctly.

The payoff is that your content stays classified against the *publisher's* own
concept URIs and remains in step with the source vocabulary — which is exactly
what you need for EuroVoc, official subject headings, and government
classification schemes. It comes from the OpenEuropa (EU institutional Drupal)
ecosystem.

> **This module needs a SPARQL endpoint, and Drupal will not bootstrap without
> one.** A `sparql_default` database connection must exist in `settings.php`,
> pointing at a triplestore (typically Virtuoso). If you enable the module without
> one, every Drush command and page fails with *"The specified database
> connection is not defined: sparql_default"* until a connection is added. Set up
> the triplestore infrastructure **before** enabling the module — it is not a
> configure-later dependency.

This guide is written for a **human** clicking through the admin UI. If you want
terse, token‑cheap references for an AI coding agent, read the sibling
[`agent/`](../agent/start.md) docs instead.

## Where it lives in the admin menu

RDF SKOS defines administrative routes for its entity types (generated by its
concept-scheme route provider). Administration is gated by the standard entity
permissions, with **Administer SKOS concept scheme entities** marked as
access-restricted.

## How to use it

1. Configure a `sparql_default` connection in `settings.php` and make sure your
   triplestore is reachable (see [Installation](installation/index.md)).
2. Enable **RDF SKOS** and, if you need multilingual labels to resolve, the
   **`rdf_skos_language_mapping`** submodule.
3. Point the module at the **graph IRIs** where your SKOS data lives, so the
   concept schemes and concepts load as entities. (All graphs are passed to the
   loading methods, which requires each SKOS entity to have a unique IRI across
   the graphs.)
4. Reference the loaded SKOS concepts from your content, keeping your
   classification aligned with the published vocabulary.
