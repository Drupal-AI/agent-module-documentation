RDF Meta Entity extends the Meta Entity module so metadata about an entity can be stored in `rdf_meta_entity` entities that live in a SPARQL/triplestore backend.
---
Meta Entity lets a site attach side-car metadata entities to any entity (view counts, ratings, computed values) without altering the host entity. RDF Meta Entity provides a SPARQL-backed variant: an `rdf_meta_entity` content entity type plus an `rdf_meta_entity_type` bundle config entity, whose storage is the `sparql_entity_storage` backend, and a `meta_entity.repository` service tagged for the `rdf_meta_entity` meta-entity type. This is aimed at RDF-published / semantic-web Drupal sites (the SPARQL entity storage ecosystem) that need to keep metadata as triples.

The module exposes a single administrative route — `/admin/structure/rdf-meta-entity` — a menu block page gated by the `administer rdf meta entity` permission (marked `restrict access: true`), plus per-bundle permissions generated by `RdfMetaEntityPermissionProvider` (extending Meta Entity's provider). There is no anonymous or mutating public endpoint; entity CRUD goes through the standard entity system and its access handlers. Setup requires the `meta_entity` and `sparql_entity_storage` contrib modules and a configured SPARQL endpoint; then define an `rdf_meta_entity` type mapping fields to the SPARQL backend (see the test module's `visit_count` example).
---
- Store per-entity metadata as RDF triples in a SPARQL backend.
- Attach side-car meta-entities to host entities without altering them.
- Define `rdf_meta_entity` bundles mapped to SPARQL storage.
- Track values such as visit counts in a triplestore (see test fixture).
- Administer meta-entity types at `/admin/structure/rdf-meta-entity`.
- Gate administration with the `administer rdf meta entity` permission.
- Generate per-bundle permissions via the permission provider.
- Integrate metadata with an existing SPARQL-published Drupal site.
- Use the `meta_entity.repository` service for the rdf_meta_entity type.
- Theme meta-entity output via the `rdf_meta_entity` template.
- Map meta-entity fields to a SPARQL mapping config.
- Extend Meta Entity's storage model to the semantic-web stack.
- Keep host-entity schemas clean by externalizing metadata.
- Model computed/derived metadata as first-class SPARQL entities.
- Reuse Meta Entity's UI patterns over a triplestore backend.
