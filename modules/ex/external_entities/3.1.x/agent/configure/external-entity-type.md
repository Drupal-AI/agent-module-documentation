# Configure: the `external_entity_type` config entity

An external entity type is a `ConfigEntityType` (`id = external_entity_type`, class
`Drupal\external_entities\Entity\ExternalEntityType`, config prefix
`external_entities.external_entity_type.`). Saving one **derives a content entity type** whose id
equals the config id (see `external_entities_entity_type_build()` in the `.module`), so records
appear as a real Drupal entity type with Field UI, view/form displays, references, and routes at
`/{base_path}` (default base path = the id with `_`→`-`).

## Admin routes (`external_entities.routing.yml`)

| Route | Path | Permission |
|---|---|---|
| `entity.external_entity_type.collection` | `/admin/structure/external-entity-types` | `administer external entity types` |
| `entity.external_entity_type.add_form` | `/admin/structure/external-entity-types/add` | `administer external entity types` |
| `entity.external_entity_type.edit_form` | `/admin/structure/external-entity-types/{external_entity_type}` | `administer external entity types` |
| `entity.external_entity_type.delete_form` | `/admin/structure/external-entity-types/{external_entity_type}/delete` | `administer external entity types` |
| `system.external` | `/admin/config/external` | `administer site configuration` |

Per-type content routes (collection/canonical/add/edit/delete under `/{base_path}`) are generated by
`Routing\ExternalEntityTypeRoutes::routes` (registered via `route_callbacks`). Form/list handlers:
`Form\ExternalEntityTypeForm`, `ExternalEntityTypeDeleteForm`, `ExternalEntityTypeListBuilder`.

## Config keys (`config_export` / `config/schema/external_entities.schema.yml`)

| Key | Type | Meaning |
|---|---|---|
| `id`, `label`, `label_plural` | string | Machine name and human labels |
| `base_path` | string, nullable | URL base for the derived entity type (defaults to `id`) |
| `description` | text | Admin description |
| `content_class` | string | Entity class, default `Drupal\external_entities\Entity\ExternalEntity` |
| `read_only` | bool | If true, no create/edit/delete; all fields non-editable |
| `debug_level` | int (≥0) | 0 off; 1 logs queries; ≥2 also logs values/responses |
| `field_mappers` | sequence keyed by Drupal field name | Per-field `{id: <field_mapper>, config: {...}}` |
| `field_save_order` | sequence, nullable | Ordered savable field names (null = all mapped fields) |
| `field_mapping_notes` | text | Admin notes |
| `data_aggregator` | mapping | `{id: single|group|horizontal|vertical, config: {storage_clients: {...}}}` |
| `data_aggregator_notes` | text | Admin notes |
| `language_settings` | mapping | Per-langcode overrides of `field_mappers` / `data_aggregator` |
| `persistent_cache_max_age` | int | Max age (seconds) entities may be cached; `0` = disabled |
| `annotation_entity_type_id` / `annotation_bundle_id` / `annotation_field_name` | string | Local content entity that "annotates" each external entity via an entity-reference field |
| `annotation_inherited_fields` | sequence | Annotation fields inherited/displayed on the external entity |
| `locks` | mapping | Restricts management (lock_edit, lock_delete, lock_base_path, lock_fields, lock_display, lock_annotations, lock_translations, lock_field_mappers, lock_data_aggregator); each holds free-text tags, empty array = no tags |

The plugin configs (aggregator + storage clients + field/property mappers + data processors) are all
nested inside `data_aggregator` and `field_mappers`. `ExternalEntityType` keeps a "static" copy in
config and a "dynamic" copy in live `DefaultLazyPluginCollection`s and re-syncs them in `::get()`/`::set()`.

## The mapping pipeline

1. **Data aggregator** (`data_aggregator.id`) owns one or more **storage clients** keyed under
   `data_aggregator.config.storage_clients` (`single` = one client; `group`/`horizontal`/`vertical`
   combine several — see the module README's "Multiple storage client aggregation").
2. Each **field mapper** (`field_mappers.<field>.id`, e.g. `generic`, `text`, `file`) turns raw source
   data into a Drupal field. `id` and `title` fields are required (see `getRequiredFields()`).
3. A field mapper holds **property mappers** per field property (`constant`, `direct`, `simple`,
   `jsonpath`, `pattern`, `conditional`, `multi`), each optionally chaining **data processors**
   (`default`, `boolean`, `datetime`, `numeric`, …) to cast/transform values.

Editability is derived: a field is editable only if its field mapper `couldReverseFieldMapping()`
and the type is not `read_only` (`getEditableFields()`); saved fields come from `getSavableFields()`.

## Create via YAML (module `config/install` or `config/optional`)

```yaml
# external_entities.external_entity_type.my_type.yml
id: my_type
label: 'My type'
label_plural: 'My types'
read_only: true
content_class: Drupal\external_entities\Entity\ExternalEntity
data_aggregator:
  id: single
  config:
    storage_clients:
      sc1:
        id: rest
        config:
          endpoint: 'https://api.example.org/items'
          response_format: json
field_mappers:
  id:
    id: generic
    config:
      property_mappings:
        value: { id: simple, config: { mapping: id, required_field: true, main_property: true } }
```

See `modules/external_entities_drupalorg/config/optional/` and
`modules/xntt_example_d7import/config/install/` for full worked examples.

## Create / edit via PHP

```php
$type = \Drupal::entityTypeManager()->getStorage('external_entity_type')->create([
  'id' => 'my_type', 'label' => 'My type', 'read_only' => TRUE,
]);
$type->setDataAggregatorId('single')
  ->setDataAggregatorConfig(['storage_clients' => ['sc1' => ['id' => 'rest', 'config' => [...]]]]);
$type->setFieldMapperId('id', 'generic')->setFieldMapperConfig('id', [...]);
$type->save(); // postSave() clears entity-type/router/field caches and creates the DB schema
```

`postSave()` rebuilds the router and entity-type definitions; `delete()`/`postDelete()` clean up
reference fields and the derived entity type. There is no `drush` command; use the UI or config.
