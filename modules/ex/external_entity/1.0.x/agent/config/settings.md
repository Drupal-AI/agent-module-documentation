# Entities, configuration & admin routes

Source: `src/Entity/*.php`, `external_entity.permissions.yml`, `external_entity.links.*.yml`,
`config/schema/external_entity.schema.yml`.

## Install / enable
`drush en external_entity -y`. No modules outside core are required. There is **no site-wide
settings form** and no `configure` route; all configuration is done through the config entities below.
Setup order: (1) create a Connection, (2) create an External Entity Type that uses that connection and
selects a resource, (3) add Resource Displays (and optional Resource Alterations), (4) use the data via
Views or an entity reference field.

## Content entity
`external_entity` (`src/Entity/ExternalEntity.php`, base `ExternalEntityBase`) — the fetched item.
`bundle_entity_type = external_entity_type`; entity keys `id`/`uuid`/`label`. Handlers: storage
`ExternalEntityStorage`, view_builder `ExternalEntityViewBuilder`, access `ExternalEntityAccessHandler`,
views_data `ExternalEntityViewsData`. Items are fetched from the remote source on demand and are not
persisted to a local entity table (see `api/integration.md`). Instances carry `type`, `uuid`, `label`,
`path`, `resource`, `variation`, and a `fields` array of remote properties.

## Configuration entities (all `ConfigEntityType`)
| Entity type id | config_prefix | admin_permission | key config_export |
|---|---|---|---|
| `external_entity_type` | `type` | `administer external entity type` | `type`, `name`, `storage` |
| `external_entity_connection` | `connection` | `administer external entity connection` | `id`, `label`, `connection_type`, `connection_settings`, `authentication_type`, `authentication_settings` |
| `external_entity_resource_display` | `resource_display` | `administer external entity resource displays` | `id`, `render`, `resource`, `variation`, `external_entity_type_id` |
| `external_entity_resource_alter` | `resource_alteration` | `administer external entity resource alterations` | `id`, `resource`, `property`, `variation`, `alterations`, `external_entity_type_id` |

- **Connection** (`ExternalEntityConnection`) — names a `connection_type` plugin + its
  `connection_settings`, and an optional `authentication_type` plugin + its `authentication_settings`.
  `connectionTypeInstance()` / `createAuthenticationTypeInstance()` build the plugins with the stored
  settings and inject the connection (via `ExternalEntityConnectionAwareInterface::setConnection()`).
- **External Entity Type** (`ExternalEntityType`) — a bundle of `external_entity`. `storage.connection`
  points at a Connection id. `getResourceDefinitions()` lazily calls the connection type's
  `fetchResourceDefinitions()`; `getResourceProperties()`, `getResourceOptions()`,
  `getResourceVariations()`, `getResourceDisplay()` derive UI options and the render display from those
  definitions. `getResourceAlterations()` loads matching `external_entity_resource_alter` entities.
- **Resource Display** (`ExternalEntityResourceDisplay`) — binds a `resource` + `variation` to a
  `render` mapping (`render.type` = a render type plugin id, `render.settings` = its config). Display id
  convention is `{type}.{resource}.{variation}`.
- **Resource Alteration** (`ExternalEntityResourceAlter`) — an ordered list of string `alterations` for
  one `property` of a resource/variation, scoped to an `external_entity_type_id`.

## Config schema (typed, dynamic)
`config/schema/external_entity.schema.yml` keys each config entity and uses **dynamic type resolution**:
- `connection_settings` → `external_entity.[%parent.connection_type].connection_type`; the shipped
  `external_entity_server` type stores `server_domain` (uri) + `resources` (sequence of strings).
- `authentication_settings` → `external_entity.[%parent.authentication_type].authentication_type`; the
  shipped `basic_authentication` type stores `username` + `password` strings.
- `render.settings` → `external_entity.[%parent.type].render_type`; the shipped `internal_entity` type
  stores `entity_type`, `bundle`, `display`, and a `property_mapping` sequence (`field` per property).

## Permissions (`external_entity.permissions.yml`)
- `administer external entity type`
- `administer external entity connection`
- `administer external entity resource displays`
- `administer external entity resource alterations`
- `access all external entity type resources` — gates the resource-list collection route generated by
  `Entity/Routing/ExternalEntityResourceAlterRouteProvider` (`ExternalEntityTypeResourceList::build`)
  and is checked in `EntityExternalTypeListBuilder`.

## Admin routes (generated by DefaultHtmlRouteProvider + link yml)
- Types: `/admin/structure/external-entity/type` (collection), `/…/type/add`,
  `/…/manage/{external_entity_type}` (edit), `/…/manage/{…}/delete`. Menu link under
  `system.admin_structure`; local tasks add "Manage Resources" and "Manage Displays" tabs.
- Connections: `/admin/config/services/external-entity/connection` (+ `/add`,
  `/{external_entity_connection}` edit, `/delete`). Menu link under `system.admin_config_services`.
- Resource displays: `/admin/structure/external-entity/manage/{type}/displays` (+ add/edit/delete).
- Resource alterations: `/admin/structure/external-entity/manage/{type}/resources` (+ add/edit/delete).

Forms: `ExternalEntityConnectionForm`, `ExternalEntityTypeDefaultForm`,
`ExternalEntityResourceDisplayForm`, `ExternalEntityResourceAlterForm`, shared delete form
`ExternalEntityDefaultDeleteForm`; several use `AjaxFormTrait` for dependent-select rebuilds.
