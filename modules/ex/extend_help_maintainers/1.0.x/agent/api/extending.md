# Declaring maintainers & adding a custom fetcher

## Declaring maintainers in a module's `.info.yml`
Read by `InfoMaintainersFetcher` (priority 100). Preferred location is the namespaced `extra` key so the data is unambiguous:

```yaml
extra:
  extend_help_maintainers:
    maintainers:
      - name: Jane Doe
        drupal_org: janedoe        # optional; builds profile link + avatar lookup
        avatar: https://.../pic.jpg # optional; skips the drupal.org avatar scrape
```

- Only entries with a non-empty `name` are used.
- If `avatar` is omitted but `drupal_org` is set, the fetcher scrapes the avatar from the drupal.org profile page.
- A top-level `maintainers:` list is used as a fallback when the `extra` key is absent.
- The `profile` link (`https://www.drupal.org/u/<drupal_org>`) is generated by `MaintainersHelpBuilder`; you do not set it in `.info.yml`.

## The `Maintainer` DTO (`src/DTO/Maintainer.php`)
Immutable value object: `__construct(string $name, ?string $drupalOrg = NULL, ?string $avatar = NULL)` (trims name/username, coerces empty avatar to NULL). Accessors `getName()`, `getDrupalOrg()`, `getAvatar()`, `getIdentifier()` (lowercased `drupalOrg ?? name`, the merge key), `toArray()` (`name`, `drupal_org`, `avatar`).

## Adding a custom fetcher
1. Place a class in `src/Plugin/MaintainersFetcher/` of your module.
2. Implement `MaintainersFetcherInterface::fetchMaintainers(string $module_name): array` returning `Maintainer[]`.
3. Annotate it:

```php
/**
 * @MaintainersFetcher(
 *   id = "my_source",
 *   label = @Translation("My Source"),
 *   description = @Translation("Reads maintainers from an internal directory."),
 *   priority = 50
 * )
 */
class MySourceFetcher extends PluginBase implements ContainerFactoryPluginInterface, MaintainersFetcherInterface { ... }
```

- Use `ContainerFactoryPluginInterface::create()` for dependency injection (the shipped plugins inject `http_client`, `extension.list.module`, `cache.default`, `logger.channel.extend_help_maintainers`).
- `priority` sets both run order and merge precedence; admins can override it per plugin on the settings form (see config/settings.md). Higher wins.
- After clearing caches the plugin appears as a checkbox on `/admin/config/system/extend-help-maintainers`; it only runs once selected (added to `selected_plugins`).
- Throwing from `fetchMaintainers()` is safe — `MaintainersService` catches, logs, and skips the plugin.
- Return maintainers with a stable `drupal_org` (or `name`) so `MaintainersMerger` deduplicates correctly against the other sources.

## Altering discovered plugins
Implement `hook_extend_help_maintainers_fetcher_info_alter(&$definitions)` to change labels/priorities or remove a fetcher definition (the manager's `alterInfo` hook).
