No Referrer adds `rel="noreferrer"`, `rel="noopener"` and `referrerpolicy="no-referrer"` to external links and resources — both to links generated by code (menus, link fields) and, via a text-format filter, to links and embedded resources in user-generated content — to stop referrer leakage and `window.opener` tab-nabbing.

---

The module protects privacy and security around outbound links. `rel="noreferrer"` stops the browser sending the referring URL (and blocks `window.opener` access); `rel="noopener"` blocks only the `window.opener` access; `referrerpolicy="no-referrer"` stops referrer leakage from embedded `img`/`iframe`/`script`/`link` resources. Three independent toggles in `noreferrer.settings` (`noreferrer`, `noopener`, `referrerpolicy`, all default TRUE) control which attributes are applied. For links built by Drupal it implements `hook_link_alter` (`Drupal\noreferrer\Hook\LinkAlter`): `noopener` is added to any link with a `target`, and `noreferrer` to any external link whose host is not allowlisted. For user-generated content it ships a text-format **filter** (`noreferrer`, `TYPE_TRANSFORM_IRREVERSIBLE`) that must be enabled per text format; it rewrites `a`/`area`/`form` `rel` and adds `referrerpolicy` to external resources. An **allowed-domains** list (`allowed_domains`) exempts trusted hosts (matched by host or subdomain via `Allowlist\Validator::isAllowed()`). A site can optionally **publish** its allowlist as a secret-URL JSON file (`Allowlist\Publisher`) and/or **subscribe** to another site's list, refreshed on cron (`Allowlist\Subscriber`). Settings live at `/admin/config/content/noreferrer` (permission *administer site configuration*).

---

- Add `rel="noreferrer"` to every external link on the site so outbound clicks don't leak the referring URL.
- Add `rel="noopener"` to links that open in a new tab (`target="_blank"`) to prevent reverse tab-nabbing.
- Add `referrerpolicy="no-referrer"` to externally-hosted images and iframes embedded in body content.
- Protect user-generated content (comments, body fields) by enabling the No Referrer filter on a text format.
- Keep only the security protection (`noopener`) while turning off the privacy one (`noreferrer`) via config toggles.
- Exempt trusted partner domains from `noreferrer` by adding them to the allowed-domains list.
- Allowlist a whole domain and all its subdomains (e.g. `example.com` also matches `www.example.com`).
- Strip referrer data from `script` and `link` (stylesheet) resources in rich-text content.
- Apply the attributes to menu links and link-field links generated by code, not just body HTML.
- Publish your site's allowed-domains list as a JSON file for partner sites to consume.
- Subscribe to a central allowed-domains list that refreshes automatically on each cron run.
- Harden a multisite/network by sharing one canonical allowlist across sites via publish/subscribe.
- Meet a privacy/compliance requirement to not leak internal URLs to third parties.
- Ensure `noreferrer` is only added to genuinely external links (internal links are left untouched).
- Call `Validator::isAllowed($url)` from custom code to check whether a host is exempt.
- Programmatically refresh a subscribed allowlist by calling `Subscriber::subscribe($url)`.
- Prevent the linked page from reading `window.opener` on links with a target attribute.
- Add the No Referrer filter alongside existing HTML filters (it also fixes faulty/chopped-off HTML).
- Configure attributes globally once and have them applied consistently across all rendered links.
- Avoid double-adding rel values — existing `rel` tokens are merged, not overwritten.
- Turn off `referrerpolicy` on resources while keeping `noreferrer` on anchor links.
- Roll out link privacy hardening site-wide without editing themes or templates.
