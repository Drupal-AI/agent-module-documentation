Node Authorize Link generates per-node secret links (containing an `?authkey=` token) that let an unauthenticated visitor view, view a revision of, edit, or delete a specific node without logging in — like a shareable, scoped "magic link" for individual nodes.

---

Enabled per content type (on the node-type edit form under "Node authorize link"), the module gives each node a random 256-bit key (`hash('sha256', random_bytes(64))`) stored in its own `node_authlink_nodes` table. Which operations a valid key authorizes — `view`, `view revision`, `update`, `delete` — is configured per content type ("Grants to give"). When a request carries `?authkey=<key>` matching the node's stored key, `node_authlink_check_authlink()` records the allowed operations in the visitor's session and grants them; access is enforced by overriding the node access control handler (`hook_entity_type_alter` → `NodeAuthlinkNodeAccessControlHandler`), decorating the entity-access check for revisions (`NodeRevisionAccessCheck`), and `hook_node_access()`. An admin UI at `/node/{node}/authlink` (permission-gated) lets privileged users create/delete a node's key and copy the view/revision/edit/delete links; a bundled view (`node_authlinks`) lists all keys with delete links. Tokens are exposed for use in emails/fields (`[node:authlink:view-url]`, `:edit-url`, `:delete-url`, `:authkey`). Keys are permanent by default but can be auto-regenerated by cron after a configurable age ("Regenerate authkeys after"), and are deleted with the node. Permissions: `configure node_authlink module`, plus `create and delete node authlinks` and per-bundle `create and delete node <type> authlinks` (both `restrict access: TRUE`).

---

- Send a client a link to review a specific unpublished node without giving them an account.
- Let an external editor update one node via a scoped edit link, no login required.
- Share a one-off "delete this node" link with a trusted party.
- Give reviewers access to a particular node revision through a link.
- Embed a node's view/edit/delete URL into a notification email via tokens.
- Provide "preview" links for draft content to stakeholders.
- Grant temporary anonymous access to a single node while keeping the rest of the site private.
- Enable authlinks only for the content types that need them (per-bundle configuration).
- Choose exactly which operations a link authorizes (view / view revision / update / delete).
- Rotate all keys of a content type periodically via the cron "regenerate after" setting.
- Bulk-generate keys for every existing node of a content type ("Generate authkeys" batch button).
- Bulk-delete all keys of a content type ("Delete all authkeys" batch button).
- Manage a single node's key from the node's "Authlink" tab and copy the ready-made links.
- List and audit all issued authlinks (and delete them) through the `node_authlinks` view.
- Include an authkey in a custom field or block using the `[node:authlink:*]` tokens.
- Let anonymous reviewers browse older revisions of a node via revision authlinks.
- Provide download/print-friendly access to gated documents stored as nodes.
- Integrate with Group: authlink access is layered in front of Group content access.
- Delegate one-node edit rights to a contractor without touching Drupal roles/permissions.
- Automatically drop a node's key when the node is deleted (handled by the module).
- Restrict who may mint/revoke links using the per-content-type permissions.
- Build an email workflow where each recipient gets a personalized, node-scoped access link.
