# Routes, permissions, settings, and config (notification_system_database)

## Permissions (`notification_system_database.permissions.yml`)
- `administer notification` — title "Administer notification settings", **`restrict access: true`**.
  This is the entity `admin_permission`; it gates the settings form and (via the core entity access
  handler) create/update/delete of `notification` entities.
- `access notification overview` — declared, for an overview page.

## Routes
- `entity.notification.settings` — `/admin/structure/notification` — form
  `NotificationSettingsForm`, permission `administer notification`. This is the `configure` route.
- Entity CRUD (generated by `AdminHtmlRouteProvider`):
  `/admin/content/notification` (collection), `/admin/content/notification/add`,
  `/notification/{notification}` (canonical), `/admin/content/notification/{notification}/edit`,
  `/admin/content/notification/{notification}/delete`.
- Menu/task/action links in `.links.menu.yml` / `.links.task.yml` / `.links.action.yml` place the
  collection under **Content** and the settings under **Structure**.

## Settings form (`src/Form/NotificationSettingsForm.php`)
Writes config object `notification_system_database.settings`:
- `read_purge_days` (int, default 0) — "Delete read notifications after (days)"; 0 = never. Drives
  the cron purge (see api doc). Schema: `config/schema/notification_system_database.settings.schema.yml`.

## Entity forms / list
- `NotificationForm` (`ContentEntityForm`) — add/edit; on save logs + redirects to the canonical.
- `NotificationListBuilder` — columns id / title (link) / audience (user count) / created, plus a
  "Total notifications" summary; operations carry a `destination`.

## Optional REST resource
`config/optional/rest.resource.entity.notification.yml` declares a REST resource for the
`notification` entity — `GET`/`POST`/`PATCH`/`DELETE`, formats json/xml, **cookie** auth. Being in
`config/optional`, it installs only when the `rest` module is enabled, and is **off by default**.
When enabled, access is governed by core REST method permissions **and** the entity access handler
(create/update/delete require `administer notification`); entity *view* access follows the core
content-entity default. Treat enabling it as a deliberate, permission-reviewed step.

## Install / schema
- `hook_schema` creates `notification_system_database_read`.
- Update hooks 8001–9001 add the `expires`/`forced` base fields, create the read table, and add its
  `uid__entity_id` index.
