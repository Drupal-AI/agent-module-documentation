Show Node Aliases lists every URL alias (path) assigned to a node directly on that node's edit form, and — for users who can administer URL aliases — gives inline Edit and Delete links for each one.

---

The module is a single form alteration with no config, no settings page, and no permissions of its own (it reuses core's `administer url aliases`). It implements `hook_field_widget_single_element_WIDGET_TYPE_form_alter()` for the core `path` widget, so on any node edit form that shows the URL alias (Path) field it queries the `path_alias` table for every alias whose `path` is `/node/<nid>` and renders them in an "Existing Aliases" details element. The table shows each alias and its language; when the current user has the `administer url aliases` permission it adds an Operations column with Edit and Delete links that deep-link to core's alias edit/delete routes (`/admin/config/search/path/edit|delete/<id>`) with a destination back to the node edit page. Core's own Path field only ever shows one alias per node, so this module is what surfaces the *additional* aliases a node can accumulate (e.g. from Pathauto, translations, or manual entries). It reads aliases straight from the database and does not create or modify them itself — creation/editing/deletion all happen through core's path UI.

---

- See at a glance every URL alias pointing at a node while editing it.
- Spot duplicate or stale aliases a node has collected over time.
- Give editors inline Edit links to fix a wrong alias without leaving the node form.
- Give editors inline Delete links to remove an obsolete alias from the node form.
- Review per-language aliases on a multilingual node in one place.
- Audit aliases generated by Pathauto alongside manually added ones.
- Confirm which alias a redirect or menu link should target.
- Clean up leftover aliases after changing a node's title/Pathauto pattern.
- Verify a node has the expected canonical path before publishing.
- Let content admins manage a node's paths without visiting the global URL aliases admin list.
- Restrict alias editing/deleting to users with `administer url aliases` while still showing the list to others.
- Show the alias list only when a node actually has aliases (empty nodes render nothing).
- Surface aliases created by translation workflows for review.
- Quickly delete a bad alias that is shadowing another page.
- Cross-check alias language codes against the node's translations.
- Troubleshoot "why does this node answer on two URLs" from the edit screen.
- Provide a lightweight aliases overview without installing a heavier path-management module.
- Deep-link into core's alias edit form with a return destination to the node.
- Deep-link into core's alias delete confirmation with a return destination to the node.
- Give reviewers read-only visibility of a node's aliases (no admin permission needed to see them).
- Keep alias housekeeping close to the content it affects.
- Help SEO teams verify the exact paths a node exposes.
