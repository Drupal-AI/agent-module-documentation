# Theme Permission — agent index

Turns core's single `administer themes` permission into **per-theme** permissions so a role can
manage only specific themes on the Appearance page. No config form of its own — `configure` is core's
`system.themes_page` (`/admin/appearance`); you assign the generated permissions at
`/admin/people/permissions`.

- **The dynamic per-theme permissions and the routes they gate** →
  [permissions/permissions.md](permissions/permissions.md)

Key facts:
- Generated permissions (one pair per **installed** theme) + one global:
  `administer themes <theme>`, `uninstall themes <theme>`, and `Edit Administration theme`.
- Generated by `ThemePerm::dynamicPermissions()` (permission_callbacks), so the exact machine names
  depend on which themes are installed (e.g. `administer themes olivero`, `administer themes claro`).
- A `RouteSubscriber` swaps the Appearance page controller to `AccessController::themesPage()` (lists
  only manageable themes) and adds `_custom_access` (`AccessController::access`) to the theme
  install / uninstall / set-default / settings and per-theme block routes, keyed on the `theme` query arg.
- No config schema, no services beyond the route subscriber, no Drush.
