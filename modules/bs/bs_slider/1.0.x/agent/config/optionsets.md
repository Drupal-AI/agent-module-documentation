# BS Slider optionsets (the `bs_slider` config entity)

## Install & enable

```bash
composer require drupal/bs_slider
drush en bs_slider -y
# plus at least one library submodule, e.g.
drush en bs_slider_bootstrap -y   # requires drupal/bs_lib
```

The parent module has **no module dependencies** (only core). It is useless alone — a library
submodule supplies the `BsSlider` plugins you select in an optionset.

## The config entity

`BsSliderConfiguration` (`src/Entity/BsSliderConfiguration.php`), a `ConfigEntityBase`:

- `id = "bs_slider"`, `config_prefix = "configuration"` → config objects are named
  `bs_slider.configuration.{id}` (e.g. `bs_slider.configuration.default`).
- `config_export`: `id`, `label`, `status`, `plugin_id`, `options`.
- `admin_permission = "administer bs_slider"`.
- Accessors (interface `BsSliderConfigurationInterface`): `getPluginId()/setPluginId()`,
  `getOptions()/setOptions()`, `getOption($k)/setOption($k,$v)`.

### Config schema (`config/schema/bs_slider.schema.yml`)

```yaml
bs_slider.configuration.*:
  type: config_entity
  mapping:
    id: {type: string}
    label: {type: label}
    uuid: {type: string}
    plugin_id: {type: string}
    options:
      type: bs_slider.options.[%parent.plugin_id]   # dynamic per-plugin schema
bs_slider.options.*:
  type: mapping
```

`options` uses the dynamic type `bs_slider.options.{plugin_id}`; each library submodule ships its
own `bs_slider.options.{plugin_id}` schema (e.g. `bs_slider.options.bootstrap_carousel`).

## Routes, admin UI, permission

Routes are generated by `BsSliderHtmlRouteProvider` (extends core `AdminHtmlRouteProvider`), all
gated by `administer bs_slider`:

| Route | Path | Purpose |
|---|---|---|
| `entity.bs_slider.collection` | `/admin/configuration/media/bs_slider` | list (menu: *Config → Media*) |
| `entity.bs_slider.add_form` | `…/bs_slider/add` | create |
| `entity.bs_slider.edit_form` | `…/bs_slider/{bs_slider}/edit` | edit |
| `entity.bs_slider.duplicate_form` | `…/bs_slider/{bs_slider}/duplicate` | duplicate (added in the route provider) |
| `entity.bs_slider.delete_form` | `…/bs_slider/{bs_slider}/delete` | delete (confirm form) |

> Note the collection/menu path lives under `/admin/configuration/media/...` (not the usual
> `/admin/config/...`); that is what the entity link templates and menu link declare.

- **List builder** `BsSliderConfigurationListBuilder` — columns Label / Machine name / Plugin ID,
  adds a *Duplicate* operation.
- **Add/Edit/Duplicate form** `BsSliderConfigurationForm` (`EntityForm`): a `label`, a
  `machine_name`, a `plugin_id` `select` built from `BsSliderManager::getDefinitions()`, and an
  AJAX-refreshed `options` fieldset delegated to the plugin's `buildConfigurationForm()`. If no
  plugins are installed it shows a message and stops. Duplicate operation calls
  `createDuplicate()` and prefixes the label with "Duplicate of".
- **Delete form** `BsSliderConfigurationDeleteForm` (`EntityConfirmFormBase`) — standard
  CSRF-protected confirm form.

## Manager service `bs_slider_configuration.manager`

`BsSliderConfigurationManager` (`src/BsSliderConfigurationManager.php`, implements
`BsSliderConfigurationManagerInterface`). Constructor args: `entity_type.manager`,
`module_handler`, `renderer`, `config.factory`, `cache.default`, `current_user`. Key methods:

- `entityLoad($id)` / `entityLoadMultiple($ids=NULL)` / `entityLoadByProperties($values)` — load
  optionset entities via storage `bs_slider`.
- `getAllOptionSet()` → `['id' => 'label', …]` (for select widgets);
  `getAllOptionSetByProperties(['plugin_id' => 'swiper'])` filters by plugin.
- `getOptionSet($name)` → that optionset's `options` array.
- `getPlugin($id)` → instantiates the optionset's `BsSlider` plugin via
  `plugin.manager.bs_slider->createInstance($plugin_id, $options)`; returns NULL if missing.
- `getOptionSetDescription()` → help text linking to the collection page (link shown only if the
  current user may access it).

## Theming

`bs_slider_theme()` defines the `bs_slider` render element; `template_preprocess_bs_slider()`
loads the optionset, sets `plugin_id`, `bs_slider_id`, `bs_slider`, then calls the plugin's
`preprocess($variables)`. `hook_theme_suggestions_bs_slider()` adds, in order:
`bs_slider__{plugin_id}`, `bs_slider__{config_id}`, `bs_slider__{plugin_id}__{config_id}` — so a
theme can override markup per plugin, per optionset, or both. Base template
`templates/bs-slider.html.twig` wraps each item in `<div class="bs-slider__item">`; the first item
gets `active`. All item output is a render array (auto-escaped); classes go through `clean_class`.

## Programmatic use

```php
$manager = \Drupal::service('bs_slider_configuration.manager');
$optionset = $manager->entityLoad('homepage_carousel');   // BsSliderConfiguration|null
$plugin = $manager->getPlugin('homepage_carousel');       // BsSliderInterface|null
// In a formatter/behavior: $plugin->view($build, $optionset, $options);
```
