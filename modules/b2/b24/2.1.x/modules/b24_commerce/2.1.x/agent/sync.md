# b24_commerce — order sync, catalog export & mapping

## Order → lead/deal sync (`B24CommerceSubscriber`)

Constructor sets `crmMode = RestManager::getCrmMode()` and
`operatedB24EntityType = crmMode == CRM_MODE_CLASSIC ? 'lead' : 'deal'`.

- `onOrderInsert` — `getValues()` builds fields from `b24_commerce.mapping.<order_type>` (returns
  `[]` if no mapping for the entity, aborting the push); `alter('b24_commerce_data', …, {op:insert})`;
  `addLead()` or `addDeal()`; on success stores a `b24_reference` with `getHash($fields)`; then
  `updateProducts()`.
- `onOrderUpdate` → `updateOrder()` — loads the reference; rebuilds fields; **only pushes when
  `getHash($fields) !== reference['hash']`**; Classic → `updateLead()`, Simple → looks up the
  deal's contact (`crm.contact.list` filter `DEAL_ID`) and `updateContact()`; updates the stored
  hash; refreshes product rows.
- `onOrderAssign` — sets the order email to the current user's email, then `updateOrder()`.
- `onOrderDelete` — deletes the `b24_reference` (does not delete the remote record).

`getValues()` token-replaces each mapped value (`nl2br` + `token->replace(..., ['clear'=>TRUE])`),
substitutes `- Not set -` for empty required fields, and wraps `crm_multifield` values as
`[['VALUE'=>…, 'VALUE_TYPE'=>'HOME']]` (carrying the existing item ID on update).

`getProductRows()` maps order line items to `[PRODUCT_ID, PRICE, QUANTITY]` by resolving each
purchased entity to its Bitrix24 product via `getList('product', filter XML_ID)`. `updateProducts()`
calls `setLeadProducts`/`setDealProducts`.

## Catalog export (`CatalogManager`)

- `processItem($id, $entity_type_id, $update=FALSE)` — for a `commerce_product` recurses into its
  variations; for a variation builds `NAME` (label + ` (sku)`), `XML_ID`, `PRICE`, `CURRENCY_ID`,
  and `SECTION_ID` (resolved from the configured `section_fields` mapping → `getSections()`); then
  `updateEntity`/`addEntity` (`product`) depending on existing `XML_ID`.
- `entityMapping`: `taxonomy_term → productsection`, `commerce_product_variation → product`.
- `getExistingProducts()` / `getSections()` list current Bitrix24 catalog items by `XML_ID`.
- `getExportableVocabularies()` reads `section_fields` field configs' target bundles.

Entity hooks in `b24_commerce.module` drive live sync: variation insert/update →
`processItem(...)`; variation delete → `RestManager::deleteProduct(external)`; taxonomy term
insert/update/delete → catalog section sync; order-item insert/update/delete → `updateProducts`.

## Field mapping form (`MappingForm`)

- One page per Commerce order type. Routes generated by `Routing/B24CommerceRoutes::routes()`
  (first bundle at `/admin/config/b24/commerce/mapping`, others at `…/mapping/<bundle>`); local
  tasks from `Plugin/Derivative/DynamicMappingTasks`.
- Builds Lead and Deal vertical tabs via `FormHelper::getMappingFields()` (Bitrix24 field →
  Drupal token/value). Missing `commerce_order_type` throws `NotFoundHttpException`.
- `submitForm` writes each tab to `b24_commerce.mapping.<order_type>` and stores the Bitrix24 field
  definitions in `b24_commerce.field_types`.

## Batch product export (`ProductExportBatchForm`)

- Route `b24_commerce.product_export_batch_form` (`/admin/config/b24/commerce/export_products`).
- Select `exportable_stores` (checkboxes) and per-product-type `section_fields` (entity-reference→
  taxonomy fields); **Save** persists to `b24_commerce.settings`, **Export** builds a Batch that
  runs `CatalogManager::processItem()` over sections then products (50/op), skipping items already
  present in Bitrix24 (queried by `XML_ID`).

## Routes / permission

`b24_commerce.settings_form` (menu block), `b24_commerce.mapping[.*]`,
`b24_commerce.product_export_batch_form` — all require **`administer b24 configuration`**.
