# Permissions

Declared statically in `editorial_access_manager.permissions.yml`; per-entity-type variants are
generated by `Drupal\editorial_access_manager\EditorialAccessManagerPermissions::permissions()` (wired via
`permission_callbacks:`). Dynamic permissions exist only for entity types enabled in
`editorial_access_manager.settings` (`<type>` = e.g. `node`, `taxonomy_term`, `media`).

| Permission | Source | Grants |
|------------|--------|--------|
| `assign entity edition` | static | Assign the *edition* of any supported entity to assignable users. |
| `assign entity translation` | static | Assign the *translation* of any supported entity to assignable users. |
| `edit assigned entity` | static | Edit / translate content that has been assigned to the user (any supported type). |
| `reassign assigned entities` | static | Use `/admin/content/reassign` to move all assignments from one user to another. |
| `assign <type> edition` | dynamic | Assign edition, scoped to one entity type. |
| `assign <type> translation` | dynamic | Assign translation, scoped to one entity type. |
| `edit assigned <type>` | dynamic | Edit / translate assigned content, scoped to one entity type. |

## How each permission gates a surface

- **Manage-editorial-access tab + assignment form** (`_editorial_access_manager_assign_access`,
  `AssignmentPagesAccessChecker`): requires `assign entity edition`/`assign <type> edition` for the
  original (untranslated) language, or `assign entity translation`/`assign <type> translation` for other
  languages. The entity type must be enabled and the bundle must have `enabled = TRUE`. These are the
  permissions that decide **who may assign editors** — grant them only to trusted roles.
- **"Assigned content" page** `/admin/content/assigned` (`_editorial_access_manager_assigned_content_access`,
  `AssignedContentAccessChecker`): requires `edit assigned entity` or any `edit assigned <type>`.
- **Editing/translating assigned entities**: the `edit assigned entity` / `edit assigned <type>`
  permissions are what `hook_entity_access`, `hook_node_grants`, and the translation handler consult to
  widen access to assigned content. A user holding one of these does **not** need core content
  create/edit/translate permissions.
- **Settings form**: gated by core `administer site configuration`.

`AssignableUserSelection` (the assignment autocomplete) only offers users whose roles carry
`edit assigned entity` / `edit assigned <type>`, so only such users can be picked as assignees.
