# SPARQL Entity Storage — manual setup guide

**SPARQL Entity Storage** (`sparql_entity_storage`) lets Drupal store entities in a
**SPARQL triple-store** (such as Virtuoso, Blazegraph, or another RDF database)
instead of in the usual SQL database. It provides an alternative entity storage
backend and an entity-query implementation that translate Drupal's normal entity
CRUD and entity queries into SPARQL 1.1 statements sent to a triple-store over HTTP.

This is **infrastructure**, not a feature you switch on and see. Enabling the module
alone adds nothing user-facing — it exists so that *other* modules can define entity
types backed by RDF. The best-known consumer is the **RDF Entity** (`rdf_entity`)
module. If you are not building an RDF / linked-data / semantic-web application, this
module is probably not what you are looking for.

When you do use it, entity data is mapped to RDF: entity fields map to RDF
predicates and datatypes, entity IDs become IRIs (generated by a pluggable
generator), and entities can live in one or more named **graphs** — which lets you
keep, say, draft and published versions of the same entity in separate graphs. It
also ships serialization support so SPARQL entities can be output as RDF/XML,
Turtle, N-Triples, N3, or JSON-LD.

Setup is more technical than most modules: you point Drupal at your SPARQL endpoint
in `settings.php`, then manage graphs and field mappings. You will need a running,
external SPARQL endpoint to connect to.

This guide is written for a **human** setting up the backend. If you want terse,
token-cheap references for an AI coding agent, read the sibling
[`agent/`](../agent/start.md) docs instead.

## Where it lives in the admin menu

The SPARQL graphs are managed at **Configuration → SPARQL → Graphs**
(`/admin/config/sparql/graph`), under the **Administer site configuration**
permission. The endpoint connection itself is not an admin form — it is declared in
`settings.php`.

## How to use it

By itself the module gives you no content type to create. The workflow is: connect
Drupal to your triple-store (in `settings.php`), install a module that defines
SPARQL-backed entity types (or define your own), then map that entity type's fields
to RDF predicates and choose which graphs it uses. From then on the standard entity
API — save, load, delete, and `getQuery()` entity queries — works against the
triple-store. See [Configuration](configuration/index.md) for the details.
