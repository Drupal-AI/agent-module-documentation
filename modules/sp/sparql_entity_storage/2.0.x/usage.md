SPARQL Entity Storage provides an entity storage backend and entity-query implementation that persists Drupal entities in a SPARQL triple-store (e.g. Virtuoso) instead of SQL. It is infrastructure: enabling it alone adds no user-facing feature — it is a prerequisite for modules that define entity types backed by RDF.

---

The module supplies an alternative `EntityStorage` (`SparqlEntityStorage`) and entity-query backend
(`Entity\Query\Sparql\Query` + `SparqlCondition`) that translate Drupal entity CRUD and entity queries into
SPARQL 1.1 read/update statements sent to a triple-store over the Graph Store HTTP Protocol. Connection details
are configured as a `sparql_default` database connection in `settings.php` (host, port, endpoint path, https),
using a bundled classmap driver (`src/Driver/Database/sparql/Connection.php`) that wraps EasyRDF. Field values
map to RDF predicates via per-field third-party settings (`SparqlMapping` config entity, `sparql_mapping.*`),
and a `SparqlEntityStorageFieldHandler` converts between Drupal field columns and typed RDF literals/URIs
(inbound/outbound value event subscribers handle datetime and translatable-literal conversion). Entities can
live in multiple named **graphs** (`sparql_graph` config entities, managed at `/admin/config/sparql/graph`),
enabling draft/published/sync style versioning; a graph handler resolves which graph to read/write and supports
graph-candidate fallback on load. Entity ids are IRIs, generated by a pluggable `sparql_entity_id` generator
plugin type (default plugin provided). It also ships serialization support (RDF/XML, Turtle, N-Triples, JSON-LD,
N3 encoders + a normalizer) so SPARQL entities can be output as RDF. All query values are escaped through a
central `SparqlArg` layer that serializes literals/URIs with EasyRDF's N-Triples serializer. Requires an external
SPARQL endpoint; the well-known consumer is the RDF Entity module.

---

- Store a custom entity type in a SPARQL triple-store (Virtuoso, Blazegraph, etc.) instead of SQL.
- Back an RDF-based content model with proper Drupal entity CRUD and entity queries.
- Provide the storage layer required by the RDF Entity (`rdf_entity`) module.
- Query triple-store-backed entities with the standard `getQuery()` entity-query API (conditions, sort, range).
- Map entity fields to specific RDF predicates and datatypes via per-field mappings.
- Keep draft and published versions of an entity in separate named graphs.
- Load an entity from a specific graph, or fall back through a candidate list of graphs.
- Save an entity into a different graph (e.g. move draft → default).
- Manage SPARQL graphs (add/edit/enable/disable/weight) from the admin UI at `/admin/config/sparql/graph`.
- Prioritize which graph is the "topmost" (default read/write) via graph weight.
- Use IRIs as entity identifiers, generated by a pluggable id-generator plugin.
- Implement a custom entity-id generation strategy via the `sparql_entity_id` plugin type.
- Serialize SPARQL entities to RDF/XML, Turtle, N-Triples, N3, or JSON-LD.
- Expose triple-store entities through Drupal's serialization/normalizer pipeline.
- Store translatable literal fields with language tags in RDF.
- Convert Drupal datetime values to/from RDF datatypes automatically via event subscribers.
- Connect Drupal to a remote public SPARQL endpoint for read/query workloads.
- Alter default field mappings for SPARQL-stored entities via `hook_sparql_apply_default_fields_alter()`.
- Build linked-data / semantic-web applications on top of Drupal's entity system.
- Prototype an RDF entity model using the bundled `sparql_test` example entity in the test module.
