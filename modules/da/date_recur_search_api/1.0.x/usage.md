Recurring Dates Field Search API indexes each occurrence of a recurring date (date_recur) field as a separate Search API item.

---

The module adds a per-field Search API content-entity datasource ("Date occurrences") for every `date_recur`
field in the site. Instead of indexing an entity once, the datasource expands the field's recurrence rule into
concrete occurrences up to a configurable point in the future (a PHP `DateInterval` "pre-create" period,
default `P2Y` / two years) and creates one search item per occurrence, per translation. Each item ID encodes the
entity ID, langcode, field delta, and the occurrence's start/end dates. When an item is loaded, the datasource
sets that occurrence's date on a hidden computed date-range field (named `<field>_occurrence`) on a cloned entity
copy, so you filter, sort, and display results by the single occurrence rather than by the whole recurring field.
The datasource extends Search API's core `ContentEntity` datasource, so entity rendering and access checking are
inherited. An event subscriber listens to date_recur's save/delete events and keeps the Search API tracker in sync
as occurrences change. Requires Recurring Dates Field, Search API, and Computed Field; Search API Common Fields is
recommended to share fields across datasources.

---

- Index event-style content where one node recurs on many dates (weekly classes, monthly meetups).
- Show each occurrence of a recurring event as its own distinct search result.
- Sort search results by the specific occurrence date rather than by the field's first value.
- Filter/facet search results to a date range and match individual occurrences inside it.
- Generate occurrences up to two years ahead by default via the `pre_create` = `P2Y` setting.
- Change how far ahead occurrences are generated by entering any valid PHP `DateInterval` (e.g. `P1Y`, `P6M`).
- Add the "Date occurrences" datasource to a Search API index for a chosen entity type and field.
- Restrict indexing to selected bundles using the datasource's bundle include/exclude configuration.
- Restrict indexing to selected languages using the datasource's language include/exclude configuration.
- Mix per-field date-occurrence datasources with Search API's built-in Content datasource on the same index.
- Index each translation of a recurring event as separate per-occurrence items.
- Keep the search index automatically updated when a recurring-date field is saved (tracker insert/update/delete).
- Remove all tracked occurrence items for an entity when it is deleted.
- Add the computed `<field>_occurrence` date-range field to the index for sorting and display.
- Render the underlying entity in search results with the correct per-occurrence date via a view mode.
- Cache each per-occurrence entity render separately so different occurrences do not collide in render cache.
- Reuse Search API's entity access checking for date-occurrence results.
- Build a "what's on next" listing view backed by Search API over recurring events.
- Support most Search API backends, since the datasource extends the core content-entity datasource.
- Pair with Search API Common Fields to combine occurrence datasources with ordinary content datasources.
