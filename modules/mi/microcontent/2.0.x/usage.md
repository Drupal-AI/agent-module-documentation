Micro-content provides a lightweight, fieldable, reusable content entity (`microcontent`) with configurable bundles (`microcontent_type`), supporting fields, revisions, moderation and translation — for managing small reusable snippets separately from nodes.

---

The module defines a `microcontent` content entity (an `EditorialContentEntityBase` with an owner, publish status, revisions and translation) and a `microcontent_type` config bundle entity, both administered through the standard entity UI. Types are managed at `/admin/structure/microcontent-types` (fields via Field UI, since the type is the `field_ui_base_route`), and items are created/listed at `/admin/content/microcontent`. Each type has a name, description, an optional `type_class` "background class" (rendered on the entity template `microcontent.html.twig`) and a `new_revision` default. Access is enforced by a custom `MicroContentAccessHandler`: the `administer microcontent` permission grants full access, otherwise view requires published status or `view unpublished microcontent`, and create/update/delete are governed by dynamic **per-bundle** permissions (`create/update own/update any/delete own/delete any <type> microcontent`) generated by `MicroContentPermissions`. Revision operations map to `view/revert/delete any microcontent revisions` permissions, and an overview permission gates the admin listing. The module ships optional config for an Entity Browser (`microcontent_browser`) and admin/browser Views, an entity-browser form mode and a preview view mode, JSON:API filter access wiring, and a `BackFillQuery` plugin that integrates with the `backfill_formatter` module to show fallback values. It has no global settings form (`configure` is null); configuration is the type entities and their fields.

---

- Store reusable content snippets (promos, callouts, disclaimers) as first-class entities instead of nodes or blocks.
- Define multiple micro-content types, each with its own fields, via Field UI.
- Attach any Drupal fields (text, media, links, references) to a micro-content type.
- Reference micro-content from nodes or other entities with an entity-reference field.
- Keep revisions of a snippet and revert to an earlier version.
- Enable per-type "create new revision by default" behaviour.
- Translate micro-content into multiple languages (entity is translatable).
- Put micro-content under content moderation / editorial workflow.
- Publish and unpublish individual micro-content items.
- Grant editors rights to edit only their own micro-content of a given type.
- Grant a role edit/delete-any rights on a specific micro-content type only.
- Let a role view unpublished micro-content for review.
- Restrict the admin micro-content overview to specific roles.
- Pick micro-content through an Entity Browser (`microcontent_browser`) when building content.
- Render a micro-content item in a chosen view mode (e.g. `preview`).
- Apply a background/utility CSS class per type via the type's `type_class` setting.
- Expose micro-content over JSON:API with published/unpublished filter access respected.
- Show a fallback value for empty micro-content references using the `backfill_formatter` integration.
- Assign ownership/authorship of each micro-content item.
- Track revision author and log messages for editorial history.
- Build a library of approved, centrally-managed marketing snippets reused across pages.
- Separate small structured content from the node system to keep content types lean.
- List and manage all micro-content from the admin content area.
