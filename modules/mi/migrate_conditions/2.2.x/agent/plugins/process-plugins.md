# Migrate Conditions — process plugins

All extend `ProcessPluginWithConditionBase`, so each takes a **`condition`** key:
- a plugin id string — `condition: empty` (only for conditions needing no config), or
- a map — `condition: { plugin: equals, value: bird }`.

The condition is evaluated against the process plugin's incoming value (its `source`), unless
the condition sets its own `source`. See
[condition-plugins.md](condition-plugins.md).

## `evaluate_condition`
Returns the boolean result of the condition. `handle_multiples = TRUE`.
```yaml
is_null_flag:
  plugin: evaluate_condition
  source: source_value
  condition: is_null
```

## `skip_on_condition`
Skip when the condition is met. Keys: `method` (`row` = skip the whole row, `process` = stop
this property), optional `message` and `message_context` (properties for `sprintf`; logged
only for `method: row`). `handle_multiples = TRUE`.
```yaml
skip_old:
  plugin: skip_on_condition
  source: created_on
  method: row
  condition: { plugin: older_than, format: 'j M Y', value: '-1 month' }
  message: 'Created %s, too old.'
  message_context: [created_on]
```

## `stop_on_condition`
If the condition is met, **stop the pipeline** but keep the current value unchanged. Key:
`method`. `handle_multiples = TRUE`. Good as a guard before an expensive step.
```yaml
field_number:
  - { plugin: stop_on_condition, condition: 'not:empty', source: my_number }
  - { plugin: callback, callable: rand, unpack_source: true, source: [] }
```

## `if_condition`
Branch. Pick **one** of `do_get` / `do_process` / `do_default_value` for the true branch and
**one** of `else_get` / `else_process` / `else_default_value` for the false branch. `*_get`
takes a source/`@destination` property; `*_process` runs a sub-pipeline; `*_default_value` is
a literal. Unset true branch defaults to the source; unset else defaults to NULL.
```yaml
animal_color:
  plugin: if_condition
  source: animal_family
  condition: equals(bird)
  do_get: feather_color
  else_get: fur_color
```

## `first_meeting_condition`
Return the first value (of a multi-value `source`) meeting the condition; else
`default_value` (a literal). Recreates `null_coalesce` with `condition: not:is_null`.
```yaml
null_coalesce:
  plugin: first_meeting_condition
  condition: 'not:is_null'
  source: [field_one, field_two, field_three]
  default_value: 'fallback'
```

## `filter_on_condition`
`array_filter` over an array source — keep elements meeting the condition. Key:
`preserve_keys` (default FALSE → re-index). Throws if the value is not an array.
`handle_multiples = TRUE`.
```yaml
upcoming_dates:
  plugin: filter_on_condition
  source: field_timestamps
  condition: { plugin: 'not:older_than', format: 'U', value: 'now' }
```

## `switch_on_condition`
Ordered `cases`; the first case whose `condition` is met wins (implicit break). Each case
gives exactly one of `default_value` (literal), `get` (property), or `process` (sub-pipeline).
Use `condition: default` as the final catch-all.
```yaml
comparison:
  plugin: switch_on_condition
  source: my_source
  cases:
    - { condition: { plugin: less_than, value: 5 }, default_value: 'less than 5' }
    - { condition: equals(5), default_value: 'equal to 5' }
    - { condition: default, default_value: 'greater than 5' }
```

## `:foreach` variants
Any process plugin above (they all declare `handle_multiples`) gets an auto-generated
`<id>:foreach` variant that turns off multiple-handling so the condition is evaluated
**per element** of an array. E.g. `evaluate_condition:foreach` with `condition: greater_than(3)`
on `[4, 2]` yields `[TRUE, FALSE]` (whereas plain `evaluate_condition` treats the whole array
as the source). Generated by `hook_migrate_process_info_alter`.
