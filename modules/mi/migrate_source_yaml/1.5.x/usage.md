Migrate Source YAML adds a single Migrate API source plugin (`yaml`) that reads rows of data from a YAML file, so you can use a `.yml` file as the source of a Drupal migration.

---

The module provides one class, `\Drupal\migrate_source_yaml\Plugin\migrate\source\Yaml`
(`@MigrateSource(id = "yaml")`), extending core's `SourcePluginBase`. In its constructor it
requires two source settings — `file` (path to the YAML file) and `ids` (the unique key field
definition) — throwing a `MigrateException` if either is missing, then parses the whole file with
Symfony's `Yaml::parse(file_get_contents($file))` into an array of rows. `initializeIterator()`
returns an `\ArrayIterator` over those rows, so the **top level of the YAML file must be a
sequence/list, each item a mapping of field name → value**. `getIds()` returns the configured
`ids`, `fields()` returns the optional `fields` setting (field name → description, purely
documentational for the migrate UI), and `__toString()` returns the file path. There is no admin
UI, config, permission, Drush command, or schema — you use it by setting `source.plugin: yaml`
in a migration definition (typically a `migrate_plus.migration.*` config entity or a module's
`migrations/*.yml`). Parsing happens once, in memory, at construct time, and a parse failure is
logged and yields an empty row set. It pairs with the usual migrate process plugins and any
destination (nodes, terms, users, config, etc.).

---

- Import content into Drupal from a hand-written or exported YAML data file.
- Seed a site with demo/fixture content defined in a `.yml` file.
- Migrate a small dataset without standing up a database or CSV source.
- Use YAML (readable, comment-friendly) as the source format for a migration.
- Import taxonomy terms from a structured YAML list.
- Create users in bulk from a YAML file of accounts.
- Populate a custom content type from a YAML export of another system.
- Drive a `migrate_plus` migration config entity with a YAML source instead of JSON/CSV/XML.
- Provide default/example content for a distribution or install profile via YAML.
- Keep migration source data under version control as readable YAML.
- Define the unique key(s) of each source row with the `ids` setting for tracking/rollback.
- Document source fields via the optional `fields` setting so they show in the migrate UI.
- Combine YAML source rows with process plugins (e.g. `get`, `default_value`, `migration_lookup`).
- Run repeatable imports via `drush migrate:import` using a YAML-backed migration.
- Roll back a YAML-sourced migration with `drush migrate:rollback` (ids enable tracking).
- Migrate menu links, blocks, or config-like data authored as YAML.
- Prototype a migration quickly by editing a YAML file rather than a database.
- Import nested/complex records (each YAML row can contain arrays for sub-process handling).
- Load reference data (countries, categories, settings rows) from a YAML file.
- Convert an existing YAML content dump into real Drupal entities.
- Use a YAML file generated by another script/pipeline as a migration feed.
- Test process-plugin pipelines against a controlled YAML row set.
