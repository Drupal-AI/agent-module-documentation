Language Switcher Enhanced supplies a drop-in replacement for core's language switcher block that adds control over label display, HTML structure (list or dropdown), soft-hiding languages behind a permission, and what happens when the current entity has no translation in a language.

---

The module ships one block plugin, `language_switcher_enhanced_block` ("Enhanced language switcher"), that extends core's `LanguageBlock` and is derived per language-negotiation type just like the core block. Placing it gives four settings on the block form. **Display** chooses the link label: the translated language name (default), the language ID (`en`, `nl`), or the native name (`English`, `Nederlands`). **Structure** chooses the markup: a single flat list, a Bootstrap dropdown with the active language on top and repeated in the menu (default), or a dropdown with the active language on top but omitted from the menu. A `use_bootstrap` checkbox (on by default) attaches a bundled slice of Bootstrap CSS/JS so the dropdown works without theme styling; turn it off to style it yourself. **Hidden languages** is a checkbox list of languages to remove from the switcher for users who lack the `see hidden languages switcher` permission — this is a soft, presentation-only hide (it does not block access to those translations, as the form text states). **Not translated** decides link behaviour when, on an entity canonical route (`entity.*.canonical`) whose entity is a content entity, a language has no translation: follow the Drupal default (leave the link as core built it), point the link to that language's front page ("redirect to homepage" — a plain link change, not an HTTP redirect), or disable the link (render it as `<nolink>`). This translation check only runs on content-entity canonical pages; on all other routes the links behave like core's. To steer admins toward the enhanced block, a `VIEW` kernel event subscriber strips the core `language_block:*` entries out of the Block layout and Context block-reaction "place block" listings. Links are still generated by core's `LanguageManager::getLanguageSwitchLinks()` for the current route (or `<front>` on the front page), so each link keeps the visitor on the equivalent path; the module only rewrites labels, structure, visibility, and the untranslated-target URL. No config route: everything is per-block, stored in block settings and covered by config schema.

---

- Replace the core language switcher with a version that has display and structure options.
- Show language links as a Bootstrap dropdown instead of a flat list.
- Show the active language as a dropdown toggle with the other languages in the menu.
- Label language links by their native name (Nederlands, Deutsch) instead of the translated name.
- Label language links by short language ID (en / nl / fr).
- Disable the switcher link for a language the current page is not translated into.
- Send visitors to a language's front page when the current page has no translation there.
- Keep core's default link behaviour but gain the display/structure options.
- Soft-hide a not-yet-finished language from ordinary visitors.
- Let editors/translators preview a hidden language via a permission.
- Avoid dead or wrong-language links from the switcher on a partially translated site.
- Style the switcher entirely from the theme by disabling the bundled Bootstrap.
- Place a separate enhanced switcher per language negotiation type (interface, content, URL).
- Hide the core language block from the block placement UI to prevent confusion.
- Present a language switcher on content pages that reflects which translations actually exist.
- Give a phased translation programme a switcher that degrades gracefully.
- Repeat or omit the active language in the dropdown menu as the design requires.
- Keep visitors on the current page when switching language rather than the front page.
- Provide a language switcher whose markup matches a Bootstrap-based theme out of the box.
- Configure switcher behaviour entirely through block settings, no code required.
