# Taxonomy Permissions — agent index

Adds a **per-vocabulary** `view terms in <vocabulary_id>` permission that core Taxonomy is missing,
and enforces it by replacing the taxonomy_term access handler. No config, no settings form
(`configure: null`), no Drush, no config schema. Depends on core **taxonomy**. Core requirement
`^9 || ^10 || ^11`.

- **The exact permission it defines and how each entity/field operation is gated** →
  [permissions/permissions.md](permissions/permissions.md)

Key facts:
- Dynamic permission per vocabulary: `view terms in <vocabulary_id>` (title "View terms in <label>"),
  provider `taxonomy_permissions`, generated by `TaxonomyPermissions::permissions`
  (`taxonomy_permissions.permissions.yml` `permission_callbacks`). The list tracks your vocabularies.
- Enforcement: `hook_entity_type_alter()` sets the taxonomy_term access class to
  `TaxonomyPermissionsControlHandler` (extends core `TermAccessControlHandler`). Its `checkAccess`
  gates only the `view` operation (needs `view terms in <bundle>` **and** the term published;
  `administer taxonomy` always passes); create/update/delete fall through to core.
- Field access: `hook_entity_field_access()` allows editing an entity_reference field targeting
  taxonomy_term when the user can view at least one target vocabulary (view-handler fields need
  `access taxonomy overview`).
- Default-open: `hook_install`, `hook_entity_insert` grant the view permission to Anonymous +
  Authenticated as vocabularies exist/are created (`hook_entity_delete` revokes). Tighten manually
  on the Permissions page to see any effect.
