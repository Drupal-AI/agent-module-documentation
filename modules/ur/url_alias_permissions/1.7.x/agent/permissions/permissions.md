# Permissions — URL Alias Permissions

Permissions are **dynamic**, generated by `UrlAliasPermPermissions::urlAliasPermissions()`
(wired via `permission_callbacks` in `url_alias_permissions.permissions.yml`). There are no
static permission entries.

## Generated permission names
The callback iterates every entity type that has a `path` field
(`getFieldMapByFieldType('path')`) and, based on the entity type's permission granularity:

- **bundle** granularity → one permission per bundle:
  `edit <bundle_id> <entity_type_id> url alias`
  - e.g. nodes: `edit page node url alias`, `edit article node url alias`.
- **entity_type** granularity → one permission for the type:
  `edit <entity_type_id> url alias`.

Titles read "Create and edit %bundle_label @entity_label URL alias" (or without the bundle).

## How access is decided
`url_alias_permissions_entity_field_access($operation, $field_definition, $account, $items)` in
`.module`:

1. Returns `AccessResult::neutral()` unless `$operation === 'edit'` **and** the field type is
   `path`.
2. Computes the permission name for the entity's type/bundle (same scheme as above); if the
   granularity is neither `bundle` nor `entity_type`, returns `neutral`.
3. Returns:
   ```php
   AccessResult::allowedIfHasPermissions($account, [
     $permission,                 // the specific per-type/bundle permission
     'create url aliases',        // core
     'administer url aliases',    // core
   ], 'OR')->cachePerPermissions();
   ```

Semantics:
- **Grant-only.** On a match it returns *allowed*; when the user lacks all three it returns
  *neutral*, never *forbidden*. So it never overrides another module that forbids the field; it
  only opens the path field to the roles you grant.
- The two core permissions still work as global overrides — a user with `create url aliases` or
  `administer url aliases` keeps alias access everywhere, exactly as in core.
- Because it is grant-only and layered on core field access, denying a role the specific
  permission simply falls back to core's default path-field access (hidden unless the user has a
  core alias permission). It does not, by itself, add a new bypass.

## Assigning
No config UI. Grant the generated permissions on `/admin/people/permissions` (People →
Permissions), grouped under the module. Clear caches after adding a new bundle so its permission
appears.
