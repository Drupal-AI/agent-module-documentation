Workflow Operations is an **obsolete, hidden** submodule of Workflow. The lesser-used transition permissions it once added (edit a transition's comment, revert a transition) are now part of the main Workflow module, so it is an empty placeholder you do not need to enable.

---

Originally this submodule provided the "edit own/any comment" and "revert own/any transition"
permissions and their operations. Those are now generated by the main module's
`WorkflowPermissions` for every workflow type (`edit own/any <wid> workflow_transition`,
`revert own/any <wid> workflow_transition`) and the revert form/route lives in the parent. The
submodule now ships **only an `info.yml`** (`hidden: TRUE`, depends on `workflow`): no code,
routes, permissions, config or schema of its own. Enabling it does nothing; it is kept only so
sites that previously enabled it can upgrade cleanly. For the actual permissions and the revert
flow, see the parent module's
[permissions doc](../../../2.2.x/agent/permissions/permissions.md).

---

- Recognize that "edit comment" and "revert transition" permissions come from the main `workflow` module now.
- Leave Workflow Operations disabled on new sites.
- Understand why it appears as `hidden` on the Extend page.
- Safely uninstall it on upgraded sites where it was once enabled.
- Grant `edit any <wid> workflow_transition` / `revert any <wid> workflow_transition` from the parent's permissions instead.
- Avoid enabling it expecting new functionality — it is a no-op placeholder.
