# Critical CSS — manual setup guide

**Critical CSS** (`critical_css`) speeds up how quickly your pages *appear* to
load. It inlines a small, page-specific "critical" stylesheet directly into the
HTML `<head>` and loads the rest of your site's CSS asynchronously — so the
browser can paint the visible, above-the-fold part of the page without waiting on
render-blocking stylesheets.

The important thing to understand up front is that this module does **not**
generate the critical CSS for you. You produce those files ahead of time with a
tool like Addy Osmani's *critical* or Filament Group's *criticalCSS*, then drop
them into a directory inside your active theme. On every request the module picks
the most specific matching file from that directory — it will try a per-entity
file, then per-path files, then a per-bundle file (for example `article.css`),
and finally a catch-all `default-critical.css`. Whatever it finds first gets
inlined in a `<style>` tag, and every other stylesheet is rewritten to load
without blocking the first paint.

The module is deliberately conservative about where it runs. It stays **off on
admin routes** (so it never clashes with the admin theme), off for AJAX requests,
and off for logged-in users unless you explicitly opt in — because critical CSS
is generated by emulating an anonymous visitor, and an authenticated user's page
may look different.

Out of the box the module ships no default settings, so it does nothing until you
enable it and point it at a directory. Once configured, the settings travel with
your configuration so you can deploy them across environments.

This guide is written for a **human** clicking through the admin UI. If you want
terse, token-cheap references for an AI coding agent, read the sibling
[`agent/`](../agent/start.md) docs instead.

## Where it lives in the admin menu

The settings form is at **Configuration → Development → Performance → Critical
CSS** (`/admin/config/development/performance/critical-css`). It uses core's
**Administer site configuration** permission.

## How to use it

1. Generate your critical CSS files with a tool of your choice and place them in a
   directory inside your active theme (for example `themes/mytheme/css/critical`).
2. Enable the module and open the settings form.
3. Turn it on, set the directory path (relative to the active theme), and save.
4. Reload an anonymous page and confirm the critical CSS is inlined in the
   `<head>` and other stylesheets load asynchronously.

See [Configuration](configuration/index.md) for the file-naming rules that decide
which file gets inlined on which page.
