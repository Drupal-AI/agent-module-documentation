# Configure Search Overrides

## Admin routes

| Route | Path | Access | Purpose |
|---|---|---|---|
| `entity.search_override.collection` | `/admin/config/search/search_override` | `view slider…` → `administer search overrides` | List overrides |
| `entity.search_override.add_form` | `/admin/config/search/search_override/add` | entity create access | Add an override |
| `entity.search_override.edit_form` / `.delete_form` | …/`{id}`(`/delete`) | entity access | Edit / delete |
| `search_override.settings` | `/admin/config/search/search_override/settings` (`configure`) | `configure search overrides` (`restrict access: true`) | Global settings |
| `search_overrides.override.remove[.ajax]` | …/`{override}/remove/{field}/{entity}`(`/ajax`) | `administer search overrides` | Remove one elevated/excluded entity |
| `search_overrides.autocomplete` | `/search_overrides/autocomplete/{index_id}/{count}` | `administer search overrides` | JSON index search for the UI |

Entity CRUD/collection routes are generated by `SearchOverrideHtmlRouteProvider`; add/edit/delete
forms live in `src/Form/`.

## Settings config (`search_overrides.settings`)

Set on the settings form (`SearchOverrideSettingsForm`, form id `searchoverride_settings`). Keys are
saved by stripping the `search_override_` form-element prefix:

| Config key | Form field | Meaning |
|---|---|---|
| `path` | Search Path | Site-relative path of the search results page (e.g. `/search`) used only for the preview link. |
| `parameter` | URL Parameter | The exposed Fulltext filter's "Filter identifier" (query param carrying keywords), e.g. `query`. |
| `match_entire_string` | Only match entire search strings | If checked, an override applies only when it equals the user's whole search string. |
| `content_match` | Content to select from | `node` (pick from nodes) or `index` (pick from a Solr index). |
| `search_index` | Solr index to select from | Which Search API index to pull content from when `content_match` = `index`. |

Note: `path`/`parameter` only drive the preview/testing link — they do **not** restrict which forms
or indexes overrides apply to. The module ships **no config schema** for these settings.

## Permissions (`search_overrides.permissions.yml`)

| Permission | `restrict access` | Gates |
|---|---|---|
| `add search overrides` | no | Create override entities |
| `edit search overrides` | no | Edit overrides |
| `delete search overrides` | no | Delete overrides |
| `administer search overrides` | no | Full CRUD + remove/autocomplete routes |
| `configure search overrides` | **yes** | The global settings form |

## Drush

Set a setting directly:

```bash
ddev drush config:set search_overrides.settings match_entire_string 1 -y
ddev drush config:set search_overrides.settings content_match index -y
```

Create an override programmatically:

```php
\Drupal::entityTypeManager()->getStorage('search_override')->create([
  'query' => 'drupal',
  'elnid' => [12, 34],   // node ids to elevate
  'exnid' => [56],       // node ids to exclude
])->save();
```
